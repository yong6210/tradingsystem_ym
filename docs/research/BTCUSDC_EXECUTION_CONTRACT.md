# BTCUSDC 입력 계약과 결측 처리 — 2026-09-17

## 구현한 범위

`app/research/execution/binance_contract.py`는 네트워크 없는 입력 검사다. 거래소 주문 전송·잔고 승인·계정 검사를 수행하지 않는다.

- Decimal 수량과 가격으로 LOT_SIZE·MARKET_LOT_SIZE·PRICE_FILTER·PERCENT_PRICE·MIN_NOTIONAL 검사. float 수량을 거부하며 임의 반올림/증액하지 않는다.
- 시장가에는 markPrice를 최소 명목 검사 기준으로 사용한다. 시장가 실제 가격 제한/호가·가용 잔고/주문수/증거금은 별도 검사이며 여기서 승인하지 않는다.
- 단방향 모드의 reduce-only에 한해 최소 명목 예외를 적용한다. 포지션 반대 방향·실제 잔량 이내인지 확인하며 최소 수량/step은 적용한다. 이미 존재하는 청산 주문과의 충돌 검사는 아직 별도 통합 대상이다.
- 전체 REST 조회 응답의 종목·client ID·방향·수량·종류·reduce-only·positionSide를 대조한다. 부분 체결·전량 체결과 누계/평균 가격 일관성을 검사하고 EXPIRED_IN_MATCH를 만료로 정규화한다.
- ACK·테스트 주문 성공·정보 누락은 체결 근거가 아니다. 거래소 updateTime을 원장의 증가 시퀀스로 사용하지 않는다. 같은 밀리초에도 서로 다른 체결 상태가 올 수 있다.

계정/종목 이름 공간, 순서 역전 재조정, 단일 writer의 영속 버전 생성, 신선도·시간 동기화, 현재 위험 예산과 시장가 비용 재승인, 보호 주문 상태, 경보·미해결 잔량 조치는 아직 실거래 어댑터에 연결하지 않았다. 기존 모의 디스패처를 실제 API로 바꾸지 않았다.

## 결측 정책과 자료 로더

`app/research/data/btcusdc.py`는 등록된 원본/보충 자료의 해시를 다시 확인하고 원본과 보충을 결합한다. 누락한 마크·지수는 NaN으로 남긴다. 중복/연속성/가격 형상도 검사한다.

`require_complete_window`는 거래·마크·지수 중 하나라도 요청 범위에서 불완전하면 실행을 거부한다. 미래 결측을 알고 미리 청산하거나, 결측 봉을 삭제하거나, 직전 가격으로 숨기지 않는다. 이 계약은 완전한 구간의 연구 적격성 검사이지, 실운용 데이터 단절 대응 구현이 아니다.

E005는 가격 성과를 보기 전에 미해결2024-08-12 결측 이후의 완전한 월 단위2년(2024-09~2026-08)을 선택했다. 전체 데이터1,397,489분 중 해당 평가 구간의1,051,200분은 거래/마크/지수 모두 완전하다. 평가 이전 분봉은 지표 준비에 사용한다. 마크·지수는 E005의 적격성 검사에만 쓰며 낙폭/청산 계산을 대신하지 않는다.

## 검증

새 단위 검사23개: 주문 입력11, 로더3, 전략/펀딩9. 앞선 보충 자료4개 및 기존 회귀 검사를 포함해 관련102개 통과. E00512회 실행과16,832개 이벤트/2,949주기는 별도 Decimal 원장으로 재계산했다. 펀딩 부호·원본 사건 대조와 소스 해시도 검사했다. 새 엔진의 펀딩 없는 사례는 보존된 E004 엔진과 동일함을 확인했다.

E005 엔진은 과거 결과에 묶인 E004 소스를 수정하지 않기 위한 명시적 버전 분기다. 원장·수량 위험 계산·지표 계산은 재사용하며, 이후 공통 엔진 정리는 보존 결과의 재현 검사와 함께 수행한다.
