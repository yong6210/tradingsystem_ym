# 손절 취소·체결 경합과 비상 청산 전환 v1

2026-09-17. **활성 손절을 정리한 뒤 확인된 잔여 수량만 비상 청산하는 오프라인 전환을 연결했다.** 기존 공통 예약기·보호 감독기·주문 디스패처는 보존했다. 실제 거래소 어댑터, 체결 지연/손실 한도 보장, 실거래 승인을 뜻하지 않는다.

## 해결한 문제

취소 요청의 성공 응답과 원 손절 주문의 최종 상태는 다르다. 취소 요청 중 손절이 일부 또는 전부 체결될 수 있다. 요청이 거절되거나 응답이 유실됐더라도 이후 원 주문 조회에서 종료가 확인될 수 있다. 반대로 취소 접수 응답을 받았더라도 실제 주문 상태와 포지션을 확인하기 전에는 청산 수량을 다시 사용할 수 없다.

새 [전환 모듈](../../app/research/execution/stop_exit_handoff.py)은 취소 요청 결과와 원 주문 증거를 별도 데이터로 다룬다. `CancelAck`에는 체결 수량이 없다. 수량 해제는 [공통 계좌 예약기](ACCOUNT_EXIT_ARBITRATION_V1.md)가 받아들인 전체 주문/포지션 관측으로만 결정한다.

예: 보호 손절 `.003 BTC` → 취소 도중 `.001 BTC` 체결 후 나머지 취소 → 원 주문 누계 `.001`과 현재 포지션 `.002` 대조 → 옛 `.003` 청산 의도 폐기 → `.002` 시장가 의도만 전송. 손절에서 `.003` 전량 체결되면 시장가 청산은 0건이다.

## 상태와 불변 조건

| 상태 | 확인된 사실 | 허용되는 후속 행동 |
|---|---|---|
| NOT_REQUIRED | 아직 위험 중단/손절 도달에 따른 전환 요구 없음 | 보호 주문 유지. 이 상태는 신규 진입 승인 신호가 아님 |
| CANCEL_AND_RECONCILE | 활성 손절 또는 진입 잔량이 남음 | 대상별 취소 의도 하나, 요청 조회와 원 주문/포지션 대조 |
| RECONCILE_ACCOUNT | 주문 상태 불명, 공통 예약 미반영, 다른 경로의 기존 취소 있음 | 기존 요청·원 주문 조회. 새 시장가 반복 전송 금지 |
| RECONCILE_EXISTING_EXIT | 이미 보낸 시장가 청산에 잔량이 남음 | 그 주문을 대조. 종료된 부분 체결의 새 계좌 관측 전에는 다음 청산 금지 |
| EXIT_READY | 손절·진입 잔량이 모두 종료, 계좌 대조 통과, 잔여 포지션 존재 | 현재 잔량 재계획, 필터/공통 수량 예약 재검사 후 비상 청산 |
| FLAT_HALTED | 포지션 0, 알려진 주문 종료, 공통 예약 대조 완료 | 신규 진입 중단 유지. 이전 READY 청산도 폐기 |
| ACCOUNT_BLOCKED | 계좌/보호 관측 불일치, 잘못된 범위·시각 또는 조정 실패 | 중단과 로컬 경보 유지. 자동 수량 추정/중단 초기화 없음 |

1. 계좌 관측과 보호 관측의 버전·시각·포지션·진입 ID·활성 손절 ID/잔량/방향·기존 시장가 청산 잔량을 대조한다. 숨겨진 손절이나 빠진 진입 주문을 정상 입력으로 취급하지 않는다.
2. 원 손절의 누적 체결을 보호 원장에도 반영한다. 계좌 주문 버전과 로컬 receipt 버전은 동일 조정기가 제공하는 공통 순서라는 입력 계약이다. 임의로 거래소 timestamp를 순서로 대체하지 않는다.
3. 취소 의도를 영속화하고 `READY → SENDING` 커밋 뒤에만 transport를 호출한다. 응답 유실/강제 종료 뒤에는 같은 요청 ID를 조회한다. 조회 없음은 재송신 허가가 아니다.
4. 취소 요청은 대상별 한 번만 자동 송신한다. 거절·조회 실패가 반복돼도 무한 취소 루프를 만들지 않는다. 더 늦은 원 주문 종료 증거가 들어오면 요청 응답의 유실/거절과 별개로 진행할 수 있다.
5. 감독기가 아직 보내지 않은 취소 의도는 전환 모듈이 맡고 기존 READY 취소를 폐기한다. 이미 다른 경로에서 송신한 취소는 추가 생성하지 않고 해당 경로의 대조 대상으로 표시한다.
6. 전환 중 신규 체결된 진입 수량도 계좌의 포지션 보존 검사에 포함하고, 남은 진입 주문을 취소 대상으로 잡는다. 전환의 계좌/주기/고정 손절가 바꾸기, 시각 역행, 포지션 방향 반전은 중단 사유다.

일반 지정가 전환의 3초를 기다리는 경로가 아니다. 확인된 최종 주문/잔량이 있으면 바로 비상 청산 단계로 간다. 다만 확인할 수 없는 주문을 무시하고 시장가를 추가 송신하는 기능도 아니다.

## 보호 공백과 경보

신선한 ACTIVE 보호 수량이 실제 포지션보다 작아진 **관측 시점**을 저장한다. 공백 시작은 재시작해도 유지하며, 시각 역행으로 타이머를 초기화하지 못한다. 공백 관측 즉시 로컬 경보를 만들고 1초가 지나면 공백 시간 초과를 추가한다. 취소 대상이 전환 시작 후 1초 이상 남아 있어도 별도 대조 지연 경보를 만든다.

1초는 기존 연구의 운영 가정이며 검증된 최적값/거래소 SLA가 아니다. 기록된 시간은 실제 거래소에서 보호가 사라진 정확한 시점이나 손실 상한도 아니다. 경보는 SQLite의 `PENDING_LOCAL`이며 외부 전달은 미연결이다. 중복 경보는 같은 사유로 묶고 최초 시각을 보존한다.

## 남은 위험

- **보호 공백과 청산 지연:** 손절을 취소한 뒤 시장가를 보내기까지 공백이 생길 수 있다. 연결 장애 때 중복 방지와 즉시 청산 성공을 동시에 보장하지 않는다. 이번 작업은 공백을 감추지 않고 기록/중단하는 범위다.
- **실제 조건부 주문 의미:** 현재 STOP 하나의 누계로 정규화한 입력을 사용한다. 실제 어댑터의 조건부 주문/실행 주문 ID 대응, 취소/체결 이벤트 순서, trigger/working type 확인은 미구현이다. 특히 공통 AccountOrder에는 trigger 필드가 없어 보호 관측 공급자의 검증에 의존한다.
- **실제 계좌 조정 생산기:** 완전한 주문 목록·포지션을 테스트가 제공한다. 비동기 REST/스트림의 시각 차이와 누락을 해결하는 수집/조정기는 여전히 필요하다.
- **단일 writer와 다중 DB 경계:** 계좌 예약기와 보호 원장이 하나의 트랜잭션인 것은 아니다. 확인 불가 상태는 보존해 멈추며, 운영 리더 잠금·조정 중단 복구·실패 경보의 전달 성공은 별도 과제다. 기존 취소 경로를 전환 모듈과 동시에 독립 실행하는 구성은 지원하지 않는다.
- **공통 진입 위험 예산:** 청산 전환 모듈은 신규 진입을 승인하지 않는다. 계좌 공통 진입/증거금 예약, 계정 조건, 확증 전진 평가도 미완료다.

다음 자료 작업은 **원시 호가 L2 재생과 공백/재연결 적격성 검사**다. 이후 관측 정책을 고정하고 전진 모의에 필요한 자료와 미확인 비용을 구분한다. 운영 쪽은 실제 계좌 증거 조정 계약·경보 전달/복구를 순서대로 연결해야 한다. 기존 전략·비용 가정·백테스트 성과·채택 판단은 이번 작업에서 변경하지 않았다.
