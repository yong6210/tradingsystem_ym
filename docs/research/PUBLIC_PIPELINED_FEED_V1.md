# 구간 압축·증분 감사 수집기의 짧은 공개 연결 확인

2026-09-18. **새 v6 경로의 실제 공개 수집·재연결·종료와 저장 자료 재생은 통과했다. 데이터 품질 적격성은 미충족이다.**

[오프라인 통합 단계](PIPELINED_FEED_COLLECTOR_V1.md)의 수집기 코드를 변경하지 않고 Binance BTCUSDC 공개 WebSocket/REST로 12초 시험을 1회 실행했다. snapshot 초기화 뒤 3초에 의도적 단절을 일으켜 1회 재연결했다. 실제 주문·private 요청은 0이다.

근거: [검증 기록](../../reports/validation/public_pipelined_feed_20260918/verification.json), [사전 고정 계획](../../reports/validation/public_pipelined_feed_20260918/qualification_plan.json), [공개 실행 결과](../../reports/validation/public_pipelined_feed_20260918/public_12s/harness_result.json), [독립 재생 대조](../../reports/validation/public_pipelined_feed_20260918/public_12s/capture_verification.json), [새 관측 이력](../../reports/validation/public_pipelined_feed_20260918/inspection_history.json).

## 실행 계약과 결과

- 원래 관찰 창 12초, 예상 epoch 2개, 의도적 재연결 1회로 계획했다. 성공할 때까지 자동 반복하는 시험이 아니다. 실패한 시도도 관측 이력에 포함하도록 했다.
- 기본 구간 인계 주기 2초, 공용 예약 최대 2개, 기존 작업·상태·RSS·시간 한도를 그대로 사용했다. 기존 수집기 최대 120초 제한도 유지했다.
- 초기 여유 공간 약 30.72GiB 중 16GiB 보존 기준을 유지했다. 이 시점의 여유는 단기 실행 전 확인일 뿐 장기 용량 적격성 근거가 아니다.
- 공개 WebSocket 연결 시도 4회와 snapshot 요청 2회였다. 첫 epoch는 계획한 단절, 두 번째는 원래 종료 시각에 종료됐다. 새 관찰 창을 시작하거나 분모를 줄이지 않았다.

관찰된 최대 부모 감사 검증/저장은 27.04ms, 압축 검증/등록은 1.89ms, 구간 확정은 4.12ms였다. 자식 최대 RSS는 약 34.77MiB다. 요청 생성 시간이나 전체 event loop 지연의 상한을 의미하지 않는다.

이번 공개 자료에서는 미완료 단위 최대 1개였고, 압축과 감사 프로세스가 겹친 표본은 0회였다. 따라서 공개 동시 최대 부하 검증으로 확대하지 않는다. 이전 오프라인 겹침/버스트 근거와 이번 짧은 공개 연결 근거를 구분한다.

## 통과하지 않은 품질 기준

품질 결과는 **`QUALITY_INPUTS_REJECTED`**다. 원래 12초 중 호가·market 연결·mark·시계·영속 기록이 함께 조건을 만족한 기록상 구간은 **8.275246374초, 약 68.96%**였다. 가장 긴 비적격 구간은 약 2.64초다. 이는 기록 상태와 만료 규칙으로 계산한 값이며 실제 연속 가동률이나 거래소 서비스 가용률 인증이 아니다.

거부 사유는 `NOT_REGISTERED_PILOT_DURATION`, `JOINT_COVERAGE_BELOW_FLOOR`, `HOURLY_COVERAGE_BELOW_FLOOR`다. 초기화·재연결 등을 제외해 분모를 줄이거나, 짧은 연결 성공을 24시간 자료 적격성으로 바꾸지 않았다. 이번 시험에서 주문 체결률·메이커 수수료·전략 수익률은 평가하지 않았다.

## 검증기와 이력 보존

공개 실행용 [harness](../../scripts/probe_pipelined_feed.py)를 추가했다. 수집 함수가 성공을 반환하는 것만으로 승인하지 않으며, 다음을 함께 확인한다.

1. 요청한 기간·재연결 횟수·epoch 수가 실제 결과와 일치한다.
2. 모든 단위/작업자/epoch의 최종화가 끝나고 성공 결과가 저장됐다.
3. 수집 종료 후 원본 전체 재생, raw/gzip 전체 바이트, 최종 체크포인트, STOP/deadline 뒤 판단을 대조한다.
4. 실행 전후 53개 소스/정책 파일 hash를 대조한다. 초기 계획과 실행한 소스 사본도 보존한다.
5. 수집에 실패해도 연결·REST 시도 수와 저장되지 못한 수신까지 포함하는 보수적 관측 종료 시각을 남긴다.

실제 공개 실행 전 관련 고유 **857개** 검사(기존 843개+신규 14개)를 통과했다. 최종 파일 재검증 보완 후에는 신규 16개를 다시 검사해 **고유 859개**로 확정했다. 연구 회귀 424개는 Python 3.12, 실행·부품·검증기 433개는 Python 3.14에서 실행했고 실패·오류·건너뜀은 0이었다. 실행 환경은 websockets 16.0, httpx 0.28.1이었다.

초기 개발 검사는 오류 1건·실패 2건이었다. 원인은 동일한 epoch 진단값이 메모리에서는 튜플, JSON에서는 리스트여서 정상 결과를 다르다고 판정한 것이었다. 직렬화한 값끼리 비교하도록 수정했고 해당 초기 코드·실패 로그도 보존했다. 수집기 동작을 변경한 수정은 아니다.

최종 보고서를 만들 때 저장된 결과를 JSON으로 다시 읽자 제외 구간에도 같은 튜플/리스트 차이가 드러났다. 의미 항목 모두를 직렬화 값으로 비교하도록 보완하고, JSON 재로딩 시 동일 판정 및 구간 값 변경 거부 검사를 추가했다. 최종 신규 16개 검사가 통과했고 [오프라인 재검증](../../reports/validation/public_pipelined_feed_20260918/readback_reverification.json)은 당시 공개 재생 결과와 같았다. 추가 네트워크 요청은 없었다. 실제 공개 실행 소스(`qualified_source_snapshot`)와 최종 검증기 소스(`final_source_snapshot`)를 구분해 보존하며, 검증 조건의 의미를 완화한 수정은 아니다.

이전 **8,444건** hash 대조(고유 경로 8,175개)가 일치했다. 이전 관측 이력을 hash로 연결하고 새 관측 종료 상한을 **2026-09-17 20:11:51.378956 UTC**로 전진시켰다. 한국 시각으로 2026-09-18 05:11:51.378956이다. 이후 미관측 자료를 사용하는 전진 전략 검증은 이 이력을 반영해야 한다. 기존 동결 정책 파일의 과거 시각을 조용히 덮어쓰지는 않았다.

## 다음 단계

다음 우선순위는 **통합 파이프라인의 강제 종료와 작업 재구성·복구**다.

- 부모가 압축/감사 작업 실행 도중 사라지는 지점과 체크포인트/완료 영수증 저장 사이를 구분한다. 기존 부품 SIGKILL 시험을 전체 파이프라인 재시작 인증으로 간주하지 않는다.
- 어떤 입력 구간을 승인했는지, 어떤 압축 등록과 감사 상태까지 확정했는지를 재구성할 영속 기록과 외부 영수증 연결을 설계한다. 중복 등록·건너뛰기·이전 상태로의 되돌림을 거부해야 한다.
- 복구한 과거 감사 상태로 실시간 거래를 즉시 재개하지 않는다. 중단 공백을 남기고 새 시장 연결/snapshot에서 다시 시작하는 기존 원칙을 유지한다.

그 뒤 원본 보관 전환·정리의 복구 조건과 장기 파일/작업/저장량 한도를 검증한다. 원본 삭제와 실제 공간 회수는 아직 0이며, 24시간 기술 시험은 미등록이다. 신규 전략 채택·실거래 준비·수익성 확증도 아직 완료되지 않았다.
