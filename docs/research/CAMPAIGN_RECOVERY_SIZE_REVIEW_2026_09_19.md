# 추가의 목적을 전체 운용 회복으로 놓았을 때

17:55 재추가를 가까운 가격에서 왕복하는 거래와 구분하고, 이전 실현손실을 포함한 전체 회복 관점으로 비교했다. 결과는 `reports/validation/campaign_recovery_sizes_20260919/review.md`와 `review.json`이다.

추가 전 상태는 이전 예시의 잔량 0.1 BTC·평단 63,050·실현총손익 −16.29·비용 7.559484다. 이를 초기화하지 않았다. 계좌 10,000 USDC, 편도 수수료 4bp·반스프레드 0.5bp·슬리피지 2bp·펀딩 0, 단순 2배 증거금 산식을 사용했다.

## 추가의 이득과 대가

| 항목 | 추가 없음 | 0.1 BTC 추가 가정 |
| --- | ---: | ---: |
| 총수량 | 0.1 BTC | 0.2 BTC |
| 잔여 평단 | 63,050.00 | 63,019.30 |
| 전체 회복 관찰 가격 | 63,329.8 | 63,192.3 |
| 남은 여력의 단순 계산 | 6,819.79 USDC | 3,667.05 USDC |
| 추가 $3,000 하락 시 전체 손익 | −331.57 USDC | −635.67 USDC |

0.1을 추가하면 회복 가격이 137.5 USDC 낮아진다. 동시에 같은 역행에서 손실이 304.10 USDC 늘어난다. 이 두 변화는 모순이 아니다. 평단과 과거 손실을 더 큰 잔량으로 회복하려는 효과이며, 그 잔량 전체가 역행에도 노출된다.

비교 수량은 0, 0.025, 0.05, 0.1, 0.15 BTC다. 수량별 계산을 보여주는 표본이며 최적화·추천·고정 배분 규칙이 아니다. 실제 계좌의 허용 노출·남겨둘 여력·미체결 예약을 정하지 않았으므로 선택 수량은 비워 두었다.

## 먼 목표로 바꾸면 자동으로 정당화되는가

63,038.5에서 모두 종료한다고 가정하면 추가 없음 −29.10, 0.1 추가 −30.73 USDC다. 평단이 낮아져도 가까운 종료에서는 추가 비용을 회수하지 못해 오히려 전체 손익도 나빠진다.

63,107.2에서는 추가 없음 −22.23, 0.1 추가 −17.00 USDC로 추가가 손실을 줄이지만 전체 회복은 아직 아니다. Z02 하단 63,350에서는 각각 +2.03, +31.52 USDC다. 하지만 목표 도달 가능성은 계산하지 않았고 중간 구조를 통과할 근거도 미확정이다. 먼 목표의 산식이 양수라는 사실만으로 재추가를 승인하지 않는다.

전량 종료는 회복 가격 검산용 가정이다. 그 가격에서 전량 청산하도록 전략을 바꾼 것이 아니다. 실제 되돌림 축소를 판단했을 때 총수량 최소 절반이라는 원칙은 그대로다.

## 구분해 기록할 세 가격

- 잔여 평단: 현재 물량의 평균 진입 가격.
- 추가분 왕복 본절: 이번 추가만의 비용을 회수하는 가격. 이전 계산은 관찰 가격 63,054.9였다.
- 전체 회복 가격: 앞선 실현손실·누적 비용과 예상 전량 종료 비용을 회수하는 관찰 가격. 0.1 추가 예시는 63,192.3이다.

잔여 포지션 비용을 포함한 본절 체결가는 기존 계산기에 별도로 유지한다. 체결가와 관찰 가격은 스프레드·슬리피지·가격 단위 때문에 같지 않다.

## 검증

신규 테스트 3개 통과: 롱·숏 전체 회복의 최소 가격 단위 경계, 과거 실현손실 유지, 무포지션의 회복 가격 없음. 실제 다섯 수량 모두 회복 가격에서는 순손익이 0 이상이고 한 단위 불리한 가격에서는 음수임을 확인했다.

추가 수량 네 개와 목표 세 개의 12개 비교에서 전체 운용 손익 차이가 추가분 단독 왕복 손익과 일치하는지 독립 검산했다. 입력·소스 해시를 저장했다. 실제 펀딩·부분 체결·유동성을 반영한 백테스트가 아니며 주문 생성 0건이다.

다음 판단은 회복 가격을 낮추는 것 자체가 아니라, 해당 시장 근거에 얼마의 추가 노출을 감수할지다. 실제 한도 없이 임의의 손실 예산이나 추천 수량을 채워 넣지는 않는다. 우선 기존 한도·예비 자금 입력과 이 회복 비교를 연결할 수 있는지 점검한다.
