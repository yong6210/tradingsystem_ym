# 공개 호가 L2 재생·오류 차단 v1

2026-09-17. **기존 BTCUSDC 단기 원본의 호가 장부를 복원하고 별도 수치 구현으로 대조했다.** 업데이트 번호 연결 검사에서 가격별 실제 수량/삭제/최우선 호가 검사로 범위를 넓혔다. 새 전략 성과, 체결률, 장기간 수집 안정성을 검증한 것은 아니다.

## 데이터와 결과

대상은 [이전 공개 자료 점검](EXECUTION_DATA_FITNESS_2026_09_17.md)에서 수집한 2026-09-17 13:05 UTC 부근의 짧은 기록이다. 새 표본을 추가한 것이 아니다. REST 이후 12초 관측으로 만들어진 원본이며, 버퍼 구간도 포함한다. snapshot/stream 파일의 기존 SHA-256을 실행 전에 대조했다.

| 검사 | 결과 |
|---|---:|
| REST 초기 매수/매도 호가 | 각각 1,000개 |
| 원본 depth 메시지 | 112건 |
| 스냅샷 이전 버퍼 이벤트 | 1건 — 적용 제외 |
| 적용 후 공개 가능한 장부 상태 | 111건 |
| 별도 Fraction 수치 구현과 전체 보유 레벨 대조 | 111회 일치 |
| 동일한 최종 업데이트 ID의 bookTicker 대조 | 11건, 가격·수량 모두 일치 |
| 원본 재생 중 연결/장부 오류 | 0 |

`Fraction` 검산기는 같은 원본을 별도 파서/수치 표현/갱신 루프로 처리한다. 원본 자료 자체의 독립성을 추가한 것은 아니다. bookTicker 대조는 정확히 같은 `u`에서만 양쪽 최우선 가격과 수량 네 값을 비교한다. 같은 시각에 가깝다는 이유로 다른 업데이트를 일치 검사에 끼워 넣지 않았다. 11건의 중첩 부분만 확인했으며 모든 상태에 거래소 체크섬이 제공된 것은 아니다.

## 구현 규칙

스냅샷 연결, `pu` 연속성, 가격별 절대 수량, 0 수량 삭제는 [Binance 공식 장부 관리 문서](https://developers.binance.com/en/docs/products/derivatives-trading-usds-futures/websocket-market-streams/How-to-manage-a-local-order-book-correctly)의 규칙을 따랐다. 2026-09-17 확인. 존재하지 않는 가격의 삭제 메시지도 정상 처리한다. 업데이트 ID가 숫자상 연속일 필요는 없고 앞 이벤트의 `u`와 다음 `pu`가 맞아야 한다.

- `BUFFERING → AWAIT_BRIDGE → LIVE`: 스트림을 먼저 버퍼링하고 REST 스냅샷을 설치한 뒤 첫 연결 이벤트를 확인한다. `LIVE`는 이 재생기의 장부 사용 가능 상태명이며 실거래 운용 중이라는 뜻이 아니다.
- 매 이벤트는 장부 복사본에 반영한 뒤 교차 호가·빈 호가·확인 범위 소진을 검사하고 원자적으로 교체한다. 중간에 실패한 일부 가격만 장부에 남기지 않는다.
- 바로 앞과 동일한 이벤트는 한 번만 적용한다. 같은 ID의 다른 값, 더 오래된 이벤트, 연결 공백은 `INVALID`로 처리한다. 오래된 이벤트를 임의 정렬해 없어진 자료를 복구한 것처럼 만들지 않는다.
- 잘못된 종목/자료형/범위, NaN·무한대·음수, 단일 이벤트 같은 방향의 중복 가격은 차단한다. 소수 문자열은 길이64·계수40자리·지수 절댓값18의 파서 상한을 둔다. 거래소의 가격/수량 필터 승인과는 별개다.
- 연결 종료나 오류 뒤에는 장부 조회가 실패한다. 새 세션 ID, 새 스냅샷, 새 연결 확인을 거쳐야 다시 사용할 수 있다. 이전 세션의 늦은 이벤트/스냅샷은 새 장부에 섞지 않는다.
- 기본 사전 버퍼 상한은 4,096건이며 넘으면 재동기화가 필요하다. 이 수치는 운영 최적값이 아니다.

## 완전하게 아는 가격 범위

초기 snapshot은 각 방향 1,000개까지다. 이번 초기 경계는 매수 76,511.0 USDC, 매도 77,020.0 USDC였다. 이후 전달받은 더 바깥의 개별 레벨도 보유할 수 있지만, 그 사이의 전달되지 않은 레벨까지 안다는 뜻은 아니다.

최우선 매수가 초기 매수 하한 아래로 내려가거나 최우선 매도가 초기 매도 상한 밖으로 올라가면 새 스냅샷이 필요하다. 관측된 바깥 레벨만으로 전체 유동성·큰 주문의 가격 충격을 계산하지 않는다. 결과에는 `full_market_depth_known=false`, `maker_fill_calibrated=false`를 명시했다. 이 작업의 ‘전체 보유 레벨 대조’는 거래소의 전체 주문장부를 안다는 의미가 아니다.

## 시각과 자료 적격성

기존 수집기는 WS 수신 단조 시각을 저장했지만 REST 수신 단조 시각은 저장하지 않았다. 따라서 이 옛 자료의 재생은 **REST UTC 수신 이후 최초로 기록된 depth 수신 시점**까지 snapshot 공개를 늦추는 호환 규칙을 사용했다. 원본에 없던 정확한 REST 단조 시각을 만들어 넣지 않았다. 이 결과로 주문 지연·망 지연을 추정하지 않는다.

장부의 기본 허용 나이 1초는 로컬 수신/공개 단조 시각 기준의 연구 가정이다. 동일한 중복 이벤트를 받아도 장부의 신선도 시각을 갱신하지 않는다. 수신 시각이 신선하다고 거래소 이벤트가 반드시 신선한 것은 아니므로, 서버 지연·시계 오차 검사는 새 수집 계약에서 별도로 다뤄야 한다.

## 장애 검증

기존 원본은 보존하고 복사본의 고정 위치에 장애를 넣었다.

| 주입한 장애 | 결과 |
|---|---|
| 중간 depth 한 건 제거 | 다음 이벤트의 연결 공백 검출, 이후 장부 공개 차단 |
| 중간 이벤트 payload 두 건 순서 교환 | 연결 공백 검출, 이후 장부 공개 차단 |
| 같은 이벤트 한 건 반복 | 중복 1건 제외, 최종 장부 해시 정상 재생과 동일 |
| 수량을 NaN으로 바꿈 | 형식 오류 검출, 이후 장부 공개 차단 |

추가 단위 검사에는 스냅샷 이전 버퍼링, 경계 ID 일치, 0 삭제, 절대 수량 교체, 원자적 적용, 교차 호가, 초기 확인 범위 소진, 빈 방향, 잘못된 숫자/종목, 버퍼 초과, 단조 시각 역행, 중복의 신선도 부풀림 방지, 연결 종료, 이전 세션 오염, 새 스냅샷 후 재개가 포함된다.

신규21개 포함 관련 **338개 테스트 통과**. 네 가지 원본 변조 재생도 예상 결과와 일치했다. 이번 단계의 네트워크 요청·실주문·계정 요청은 0이다. 재연결 테스트는 모의 이벤트이며 실제 장기 WS 연결/재접속 훈련은 아직 아니다.

## 다음 순서와 판단 기준

1. **수집기와 재생기 연결:** 세션 ID·수집 시작/종료·원시 이벤트·REST 요청/수신 단조 시각·끊김 사유를 함께 기록한다. 오류 시 장부 공개 중단과 재동기화 경계를 원본에 남긴다.
2. **범위를 정한 재연결 훈련:** 공개 데이터만 짧게 수집하고 연결을 끊었다가 새 snapshot으로 복구한다. 이전 세션/새 세션 이벤트가 섞이지 않는지 검사한다. 이 훈련을 장기 운용이나 체결률 검증으로 세지 않는다.
3. **전진 모의 자료 계약 고정:** 시간대/변동성별 관측 범위, 종료 조건, 결측 허용/제외 규칙, 거래소 이벤트와 수신 지연, 비용/체결 가정을 결과를 보기 전에 정한다. 초기 12초가 충분한 표본이라고 간주하지 않는다.

공개 L2만으로 자기 주문의 실제 대기열 위치·maker 체결률을 확정할 수 없다. 실제 계좌 조건/체결 증거·주문 조정기·경보 전달/중단 복구는 계속 별도 미완료다. 기존 전략 성과·비용 가정·채택 판단은 변경하지 않았다.
