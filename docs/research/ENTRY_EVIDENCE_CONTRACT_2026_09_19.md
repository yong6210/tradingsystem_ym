# 최초 진입과 판단 보류 명세 v0.2 초안

## 최신 연결 — 사전 계획 분할 완성 v0.7

최초 `Plan.splits`에 분할 가격·수량과 `expires_ms`를 고정하고 `EntrySubmission.preplanned=true`를 명시한다. 최초 진입과 모든 분할의 비용 후 손익비·전체 손실·수량 여력을 처음부터 평가한다. 분할 가격은 최초 구간 안의 불리한 방향이어야 한다. 최초 진입 이후 가격이 불리해졌다는 이유로 새 분할을 끼워 넣는 API는 없다.

최초 승인 때 실제 주문 의도는 최초 물량만 생성한다. 나머지는 분할 슬롯과 미주문 손실 예약으로 보존한다. snapshot의 `guarded_splits.total_committed_loss`는 기존 원장의 보유·비용·미체결 위험과 미주문 분할 예약을 합한 값이다. 기존 `risk_used` 필드만 보면 미주문 예약이 빠지므로 전체 약정 손실은 이 필드를 사용한다. 원 주문의 계획은 원래 분할 전체를 포함해 유지한다.

각 슬롯은 `SplitSubmission`·`submit_split`·JSONL `type=split`으로 명시적으로 요청한다. 현재 문맥·구간 유효성·원래 구간 버전·실제 미체결·계좌/보호 상태·실행 가격·전체 예약 손실·현재 여력을 다시 확인한다. 새 재접근 확인을 요구하는 역행 추가와 구분한다. 가격·수량은 요청에서 바꿀 수 없으며 슬롯 인덱스로만 선택한다.

현재 실행 가능한 가격이 고정한 한도보다 불리하거나 손절을 넘으면 생성하지 않는다. 여력이 부족하면 기다리며 고정 수량을 임의로 키우거나 바꾸지 않는다. 주문 생성 시 그 슬롯의 예약을 실제 주문 위험으로 이전해 이중 계산하지 않는다. 생성된 주문의 실제 부분 체결은 원장에 기록한다.

한 슬롯은 한 번만 주문한다. 부분 체결 후 취소된 미체결분을 같은 슬롯으로 자동 재주문하지 않는다. 실제 체결분의 위험은 유지하고 취소 확인된 잔량만 해제된다. 미주문 예약이 남으면 다른 목적의 추가 진입을 차단한다. 기한 만료는 미주문 예약을 해제하고 기존 증가 주문을 취소 요청한다. 첫 대응 축소·운용 종료도 남은 예약을 해제한다. 재시작은 예약을 보존하되 계좌 대사 전에는 실행하지 않는다.

컨트롤러는 `recovery-guarded-v0.7`이며 슬롯·예약·주문 연결을 저장하고 복원 시 다시 계산한다. 아래 이전 기록의 사전 분할 미연결 설명은 이 경로로 대체한다. 네 종류의 수량 증가 경로가 모두 연구 엔진에 연결됐지만, 목적 분류와 입력 근거를 자동 생산하는 시장 관측 계층 및 새 자료에서의 비용 후 성과 검증은 여전히 별도 과제다. 실거래 송신은 없다.

## 최신 연결 — 수익 중 추가 v0.6

`ProfitAddSubmission`·`submit_profit_add`·JSONL `type=profit_add`를 추가했다. 단순 평가이익이나 기존 지지 반응만으로는 허용하지 않는다. 이전 구간은 `continuation_zone` 이벤트로 돌파 봉이 시작되기 전에 등록해야 한다. 롱에서는 이전 저항, 숏에서는 이전 지지의 역할 반전을 검사한다.

엔진이 받은 이전 완성 봉 종가는 돌파 경계 안쪽/동일이어야 하고 지정한 돌파 봉은 바깥에서 마감해야 한다. 과거에 이미 넘어선 상태를 새 돌파로 이름 붙이지 않는다. 돌파 후 새 지지 역할 구간은 이전 구간과 ID·범위가 같고 버전이 높아야 한다. 사용 가능 시각도 돌파 수신 이후여야 한다. 이후 새로 시작한 3분봉 회복·1분봉 재접근·유지 확인이 필요하다. 원 돌파 봉이 현재 보존된 최근 분봉 이력에 없으면 근거 부족으로 거부한다.

현재 잔여 포지션의 실행 가능한 반대편 견적으로 평가한 손익에서 예상 청산 수수료와 잔여에 배분된 비용을 뺀 값이 양수여야 한다. 과거 부분 익절 이익으로 현재 잔여의 손실을 덮어 수익 중이라고 분류하지 않는다. 미실현 이익이 있어도 캠페인 손실 예산을 키우지 않는다.

추가 수량은 기존 명시적 증가와 동일하게 추가 후 총손실·회차별 한도·요청 수량·증거금·유동성·노출 여력을 모두 제한한다. 첫 대응 가격까지 비용 후 손익비가 부족하면 목표 바로 앞의 추가를 거부한다. 기존 물량의 손절·첫 대응·최종 기한을 늘리지 않는다. 축소 이후에는 재진입 계약을 사용해야 하며 이 API로 우회할 수 없다. 역행 추가·재진입·수익 중 추가는 같은 캠페인의 증가 이벤트 제한을 공유한다.

구간 등록과 요청은 이벤트로 남기고 복원 시 재평가한다. `recovery-guarded-v0.6`은 등록 구간을 snapshot에 보존한다. 설정의 no_add는 기존 자동 추가 경로를 끈다는 의미이며, 새 경로는 `explicit_increase_contracts`로 표시한다. 아래 이전 기록의 수익 중 추가 미연결 설명은 이 절로 대체한다. 사전 계획 분할 완성은 아직 별도 계약이 필요하다. 단일 봉 돌파의 정의·동일 구간 역할 반전은 연구 시험 규칙이며 수익성 검증 완료를 뜻하지 않는다.

## 최신 연결 — 축소 후 재진입 v0.5

`ReentrySubmission`과 `submit_reentry`, JSONL `type=reentry`를 추가했다. 손실 중 평균가 개선용 `AddSubmission`으로 재진입을 처리하지 않는다. 대상은 **같은 캠페인에 잔여 포지션이 있고 첫 대응 축소가 실제 체결된 경우**다. 전량 청산 뒤 재진입은 새 최초 진입 계약을 사용한다. 손절·강제 축소 체결은 이 계약의 수량 복원 근거로 쓰지 않는다.

재진입 요청은 `reduction_fill_id`로 실제 첫 대응 축소 체결 하나를 지정한다. 최대 수량은 그 체결 수량에서 해당 체결을 근거로 이미 재진입 체결된 수량과 아직 활성 상태인 주문의 미체결 예약을 뺀 값이다. 취소된 미체결분은 예약에서 제외하지만 실제 체결분은 지우지 않는다. 여러 부분 축소 체결을 하나로 합산해 임의로 복원하지 않는다.

엔진의 현재 확인 신호는 가장 최근 실제 축소 체결 **이후에 시작**되어야 한다. 단순히 마지막 유지 봉만 축소 이후인 신호는 허용하지 않는다. 축소가 아직 완료되지 않았거나 주문 취소·체결이 미정산이면 진입을 보류한다. 이전 통과 결과나 확인 신호를 재사용하지 않는다.

재진입 수량도 최신 위험·문맥·구간·손익비·여력 검사를 통과해야 한다. 기존 캠페인 손절·새 재접근 경계·현재 잔여 손절 중 가장 보수적인 지점을 추가 물량의 손절로 선택한다. 기존 물량의 손절과 최종 보유 기한은 완화하지 않는다. 재진입은 잔여 평균가 대비 손실 중인지 여부로 구분하지 않으며, 첫 대응까지 비용 후 손익비가 부족하면 거부한다. 같은 캠페인의 증가 이벤트 제한과 손실 예산은 초기화하지 않는다.

재진입 주문만 내거나 취소했을 때는 첫 대응 축소 상태를 초기화하지 않는다. 실제 첫 재진입 체결이 발생하면 첫 대응 수량 계획을 다시 활성화하고, 다음 목표 도달 때 다시 축소할 수 있다. 잔여 손절은 계속 활성 상태다. 취소 경합의 늦은 체결·계좌 잠금·종료 우선순위는 기존 규칙을 따른다.

재진입 주문과 원 축소 체결의 연결을 snapshot에 보존하고 재생·복원에서 검산한다. 컨트롤러는 `recovery-guarded-v0.5`다. 아래 이전 기록의 재진입 미연결 설명은 이 경로에 한해 대체한다. 수익 중 신규 추가와 최초 계획 분할 완성은 여전히 별도 계약이 필요하다.

## 최신 연결 — 명시적 역행 추가 v0.4

`GuardedRecoveryEngine.submit_add(quote, AddSubmission(...))`와 JSONL `type=add` 이벤트를 추가했다. 가격 이벤트만으로 자동 추가하지 않는다. 엔진이 실제로 받은 완성 봉에서 기존 3분봉 회복 → 이후 1분봉 재접근 → 바로 다음 봉 유지 신호를 생성한다. 제출자가 임의의 confirmed 객체를 공급하는 경로는 없다. 추가 요청은 엔진의 현재 확인 시각과 같아야 하고 확인 봉 이후 견적에서만 평가한다.

제출 내용은 캠페인 ID·판단/확인 시각·현재 지지/목표 관측·문맥 증거·근거 유지 여부·충돌 해소 여부·독립 추가 이유·최대 추가 수량·최대 추가 손실이다. 관측은 엔진의 최신 완성 봉과 동일하고 구간 버전·역할·유효 상태가 일치해야 한다. 기존 포지션이 손실 방향으로 움직였다는 사실만으로 허용하지 않는다.

추가 평가 전에 만료·기존 손절·익절/축소·계좌 문제를 처리한다. 기존 미체결 주문이 있으면 추가하지 않는다. 추가 손절은 원래 캠페인 손절과 재접근 저점/고점 및 버퍼에서 더 보수적인 경계를 택하며 기존 물량의 손절은 넓히지 않는다. 비용 후 손익비는 첫 대응 가격으로 계산한다.

추가 수량은 다음 상한의 최솟값을 주문 단위로 내림한다: 제출 수량, 제출 손실/단위 손실, 캠페인 잔여 손실 예산, 기존 정책의 회차별 손실 제한, 남은 증거금·유동성·노출 여력. 최소 주문을 맞추려고 수량을 올리지 않는다. 실현 손실·비용·기존 보유 위험·미체결 예약을 포함한 추가 후 총손실을 기록한다. 사용자 고정 1/10 수량을 강제하지 않는다. 기존 연구 정책의 최대 두 추가 및 회차별 예산 제한은 그대로 적용한다.

주문 생성에 성공한 확인 신호는 소비한다. 부분 체결 여러 건은 동일 추가 이벤트로 집계한다. 추가 주문 기한은 확인 신호 만료와 최종 보유 기한 중 빠른 시각이다. 첫 대응 축소 시작 이후·실제 부분 축소 이후에는 이 계약으로 추가하지 않는다. 그 단계는 별도의 축소 후 재진입 계약이 필요하다. 수익 중 추가·사전 분할 완성도 이 API의 대상이 아니다.

JSONL 재생은 전체 제출 근거를 다시 파싱·평가하고, 저장 시 확인 신호 상태도 포함한다. 컨트롤러는 `recovery-guarded-v0.4`로 구분한다. 설정의 mode=no_add는 상속된 자동 추가 경로 차단을 뜻하며, snapshot의 guarded_add.admission_mode=explicit_adverse_add가 새 명시적 경로를 나타낸다. 아래 v0.3 이전의 추가 미연결 설명은 역행 추가에 한해 이 절로 대체한다. 실거래 송신은 없다.

## 최신 실행 — 첫 대응 수량 지정 v0.3

`ExitExecution.first_response_qty`를 지정하면 목표 계약의 `first_response_price`에서 해당 수량을 줄이는 실행 계획이 활성화된다. 자동 절반·고정 비율은 없다. 전체 수량을 지정해 전량 종료하는 것도 허용한다. 지정하지 않으면 기존 목표 반응 관리가 유지되고, 먼 목표보다 가까운 별도 첫 대응은 계속 거부한다.

수량을 지정한 경우 가까운 첫 대응을 허용하되 비용 후 손익비는 그 가까운 가격으로 평가한다. 수량은 최초 계획 수량 이하이며 최소 주문 수량·금액·수량 단위를 만족해야 한다. 첫 대응의 손익비가 좋지 않다고 먼 목표 가격을 대신 쓰지 않는다.

롱은 실제 견적의 bid, 숏은 ask가 대응 가격에 도달해야 축소 의도를 만든다. 봉의 고저가 접촉으로 주문 체결을 추정하지 않는다. 만료·손절·잠금·자료/비용 문제를 먼저 처리한다. 첫 대응을 시작하면 미체결 진입을 취소 요청하고, 실제 보유량과 지정 수량 중 작은 수량만 축소한다. 잔여량이 최소 주문 조건을 충족하지 못하면 close-position 방식의 전량 종료를 요청한다. 이 dust 처리는 합성 브로커가 지원하는 기능이며 실거래소 어댑터에서는 별도 확인해야 한다.

최초 도달 때 축소 목표를 고정하고 실제 체결 누계·미체결 예약을 따로 기록한다. 일부만 체결된 주문이 취소 확인되면 다음 정상 견적에서 미체결분만 재요청한다. 이미 시작된 축소는 목표 아래로 되돌아왔다는 이유로 취소하지 않는다. 재시작 잠금 중에는 재개하지 않으며 대사가 필요하다. 종료가 우선하는 상황에서는 잔여 전량 종료가 먼저다.

실제 축소 체결 후 남은 수량에는 잔여 손절과 최종 종료 기한을 적용한다. 지정 수량 방식에서는 기존의 목표 거부 반응에 따른 별도 축소 계산을 함께 실행하지 않는다. 반응 기한 충족은 기존 계약대로 완성 봉 종가로 확인하므로 첫 대응의 견적 도달만으로 반응 기한 조건을 자동 면제하지 않는다.

첫 대응 가격·축소 목표·실제 축소 누계를 snapshot과 재생에 포함했다. `recovery-guarded-v0.3`으로 구분하고 예전 저장 파일을 자동 변환하지 않는다. 아래 이전 기록의 가까운 첫 대응 미연결 설명은 이 지정 수량 경로에 한해 대체한다. 추가 진입 계약은 아직 미연결이며 새 guarded 경로의 자동 추가는 계속 차단된다.

최신 실행 변경: `EntrySubmission.execution`의 `ExitExecution`을 필수로 요구한다. 반응 가격·반응 기한·최종 종료 기한·부분 축소 체결 후 잔여 손절을 구조화했다. 기한과 같은 시각에는 종료가 우선하고, 늦은 반응 봉으로 만료를 취소하지 않는다. 미체결 증가는 취소 요청하고 보유량만 종료한다. 취소 경합 체결도 종료 상태를 유지한다. 실제 부분 축소 전에는 잔여 손절을 활성화하지 않는다. 단절 중 종료는 대기하며 복구 후 다음 이벤트에 재시도한다.

목표 계약의 예상 기한을 최종 보유 기한으로도 사용하는 것은 새로운 연구 시험 규칙이다. 시간·반응 가격은 필수 입력이며 수익성으로 고른 기본값은 없다. 자유 서술을 해석하지 않는다. 현재 timeout_action은 exit_all만 지원한다. 이벤트가 없을 때 스스로 깨우는 타이머는 없다. 실거래 스케줄러는 별도 작업이다.

규칙·반응 여부·잔여 손절 활성화·종료 사유를 저장하고 복원 시 검산한다. 컨트롤러 식별자는 `recovery-guarded-v0.2`로 변경하여 예전 파일을 자동 변환하지 않는다. 아래 v0.1 기록의 시간 만료·잔여 종료 미연결 설명은 이 변경으로 대체한다.

상태: 연구용 제안. 사용자 원칙과 구현자가 제안한 시험 규칙을 구분한다. 기존 recovery v0.1 실행 규칙·과거 결과는 변경하지 않는다. 별도 `GuardedRecoveryEngine`의 최초 진입 주문 의도 생성에 계약 검사를 연결했다. 실거래 송신 기능은 없다.

## 주문 의도 생성 전 연결 — 최초 진입 한정

`app/research/recovery/guarded_engine.py`의 `GuardedRecoveryEngine`을 명시적으로 선택한다. 기존 `RecoveryEngine`은 역사 비교용 v0.1 경로로 보존한다. 새 엔진의 `start(plan, quote, submission=EntrySubmission(...))`은 매번 원 근거를 제출받아 동기적으로 다시 평가한다. 이전 READY 결과 문자열이나 평가 결과 객체를 허가증으로 받지 않는다.

계획 결정 시각과 현재 견적 시각이 다르면 새 근거 제출이 필요하다. 계획에 묶인 구간 버전·방향, 최신 관측, 목표 계약을 다시 검사하고 견적이 바뀌면 현재 가격으로 비용 후 손익비·계획 손실·여력을 다시 계산한다. 현재 계좌 현금과 엔진 손실 비율이 제출 예산의 상한이며, 제출 정책으로 엔진 최소 손익비를 낮출 수 없다. 접속·대사·보호·현재 문맥·계좌 잠금·미정산 운용 상태도 주문 생성 전에 검사한다.

READY일 때만 기존 엔진의 최종 검사를 호출한다. 그 단계에서 만료·이미 사용한 계획·구간 잠금·최소 주문 단위 등을 다시 확인한다. 내부 주문 의도만 만들어지며 체결 사건이 오기 전에는 보유 수량이 늘지 않는다. 거절된 후보는 주문이나 원장을 만들지 않고 사유를 남긴다. 평가를 수행한 경우 후보 계획·견적·제출 근거·실제 적용한 정책·결과를 trace에 저장한다.

현재 연결 범위는 최초 진입이다. 새 엔진은 `no_add`로 시작하며 예정 분할·자동 추가는 거부한다. 추가 근거를 거치지 않는 기존 경로로 위험을 늘리지 않도록 별도 주문 생성 검사도 둔다. 기존 보유의 축소·청산은 유지된다. 본격적인 추가 운용에는 별도의 추가 계약과 매 주문 직전 재평가가 필요하다.

첫 대응 가격이 기존 엔진의 목표 경계보다 가까우면 현재는 거부한다. 통과 후 실제 운용은 먼 목표를 기다리는 불일치를 피하기 위한 제한이며, 가까운 대응 지점의 부분 축소·잔여 종료 실행 계획을 연결하면 확장할 수 있다. 자유 서술의 시간 만료·잔여 종료 조건을 실행 코드로 번역하지 않았으므로 이 계층의 통과가 전체 운용 계약의 실행 완성을 뜻하지 않는다.

이 경로는 별도 `GuardedReplay`의 JSONL/체크포인트 복원 API에 연결했다. 기존 `Replay`는 기존 엔진을 생성하므로 새 검사의 복원에 사용하지 않는다. 실제 시장 문맥·중간 구조 근거 생산, 추가 주문 계약, 만료·잔여 실행 조건이 남은 통합 항목이다.

### 근거를 보존하는 재생·복원

`app/research/recovery/guarded_replay.py`는 start 이벤트의 `submission`을 구간 이력·최신 봉·목표·시간별 변동 근거·정책·문맥으로 복원하고 `GuardedRecoveryEngine.start`를 호출한다. 목표 통계에 저장된 계약을 현재 제출 계약으로 임의 교체하지 않는다. 서로 다르면 거부한다. 근거 없는 기존 start 형식은 주문을 만들지 않는다. 합성 체결 옵션은 JSON boolean만 허용하며, start가 거절되면 그 이벤트로 기존 주문을 체결시키지도 않는다.

체크포인트는 전체 이벤트와 상태, 컨트롤러 식별자 `recovery-guarded-v0.1`, 설정 해시로 묶는다. 기존 `recovery-v0.1` 체크포인트와 양방향 혼용을 거부한다. 복원 시 모든 이벤트를 다시 평가해 저장 상태와 일치하는지 확인한 뒤 restart 잠금을 추가한다. 저장된 READY만 읽고 주문을 허용하지 않는다. 설정 변경·내용 변조·이벤트에 남기지 않은 상태 변경은 복원 검증에서 거부한다. 해시는 실수에 의한 변조 감지용이며 서명이나 신뢰할 수 없는 입력에 대한 인증 수단은 아니다.

미체결 증가는 취소 대기로 전환한다. 취소 확인·계좌 대사 전에는 재개할 수 없다. 계좌 대사를 마친 뒤에도 새 결정 시각의 근거를 제출해야 새 진입이 가능하다. 보유 수량·기존 청산 기능은 복원한다. 재시작 시각을 저장 상태보다 과거로 지정하면 거부한다. 재복원도 동일 잠금 규칙을 따른다.

재현 명령:

```sh
.venv/bin/python scripts/run_guarded_recovery_replay.py --config <설정.json> --events <이벤트.jsonl> --output <새 출력 경로>
.venv/bin/python scripts/run_guarded_recovery_replay.py --config <동일 설정.json> --checkpoint <checkpoint.json> --restart-ms <재시작 시각> --events <재시작 이후 이벤트.jsonl> --output <새 복원 출력 경로>
```

복원만 할 때 `--events`는 생략할 수 있다. 체크포인트에 들어갈 모든 변경은 `process()` 이벤트를 통해 수행해야 한다. 엔진 메서드나 합성 체결 함수를 직접 호출한 결과는 이벤트 저널에 남지 않아 복원이 실패할 수 있다. 이 저장 방식은 오프라인 연구용이며 실거래 장애 복구용 영속 저널을 구현한 것은 아니다.

검증: 신규 재생·복원 13개 포함 총 137개 테스트 및 상태별 하위 검사 5개 통과. 별도 CLI 합성 사례에서 최초 진입의 합성 체결 후 저장·복원하고 restart 잠금 유지 확인. 결과는 `reports/validation/guarded_replay_restart_20260919/{initial,restored}`에 보존한다. 시장 수익성 결과가 아니다.

## 목표 시간 근거와 통합 진입 평가

`entry_assessment.py`에 `measure_reachability`와 `assess_entry`를 추가했다. 이는 오프라인 평가 경로이며 기존 주문 엔진의 `start`를 변경하지 않는다.

목표 예상 시간과 동일한 길이로 과거 완성 분봉을 겹치지 않게 나눈다. 각 구간의 시가에서 유리한 방향의 최대 고가/저가 변동률을 측정하고, 현재 첫 대응 가격까지 필요한 변동률 이상이었던 구간 비율을 기록한다. 관측 창은 필수 입력이며 가장 오래된 불완전 구간은 버린다. 결정 시점까지 마감되고 수신된 봉만 사용한다. 누락·중복·역순은 계산 오류로 처리한다. 목표 계약과 통계가 다르면 진입 평가에서 거부한다.

이 비율은 조건부 목표 도달 확률·승률·기대수익이 아니다. 고저가를 사용하므로 실제 체결 가능성이나 목표 도달 전 손절 여부를 설명하지 못하며, 비중첩 구간도 통계적 독립을 보장하지 않는다. 추세·박스 등 조건별 적합성은 별도 검증 대상이다. 통계가 목표에 관한 구조적 설명이나 중간 저항 점검을 대신하지 않는다.

통합 평가는 구간 버전과 역할, 최신 봉, 목표 기록, 과거 시간별 움직임, 시장 판단과 독립 역추세 근거, 견적 상태, 비용 후 첫 대응 손익비, 최초 및 예정된 모든 추가 수량의 손실 예산을 함께 확인한다. 분할 수량의 합을 현재 유동성·증거금 여력과 비교하는 보수적인 초기 연구 검사이며, 이후 실제 주문 시점마다 재계산이 필요하다.

연구 정책의 최소 표본 수·과거 기준 충족 비율·최소 손익비·손실 예산·허용 견적 나이는 모두 필수 입력이다. 이번에 수익으로 선택하거나 기본 거래값으로 고정하지 않았다. 단위 테스트에 사용한 숫자는 검증용 사례일 뿐이다.

결과 우선순위는 EXECUTION_BLOCKED → INVALIDATED → UNASSESSED → CONFLICTED → REJECTED → READY다. 모든 실패 사유를 보존한다. REJECTED는 근거가 있지만 명시한 수치·수량 조건을 충족하지 못한 경우이며, 새 조건으로 재평가할 수 있다. READY도 연구 입력 검사를 통과했다는 의미이며 `order_authorized=false`를 유지한다. 독립 역추세 근거가 있으면 반대 방향이라는 이유만으로 거부하지 않는다.

아직 남은 연결은 실제 데이터에서 시장 문맥·중간 구조·종료 근거를 생산하는 경로와, 이 평가를 주문 직전 재평가에 강제하는 통합이다. 텍스트 근거의 진실성을 자동 증명하지 않으며 현재 12개 과거 진입의 빈칸을 임의로 채워 READY로 바꾸지 않았다. 기존 역사 비교 결과와 수익성 주장은 변경하지 않는다.

## 완성 봉 관측 어댑터 v0.1

`app/research/recovery/zone_observer.py`는 명시적으로 등록한 구간에 완성 1분봉을 순서대로 적용한다. 구간 탐색기가 아니며, 아래는 수익성으로 선택하지 않은 시험 판정 규칙이다. 기존 추가 진입의 3분봉 확인 규칙을 대체하지 않는다.

| 사건 | 지지 역할의 규칙 (저항 역할은 가격 방향을 반전) |
|---|---|
| 반응 관측 시작 | 봉 고저 범위가 구간과 겹치고 종가가 상단 + 명시된 버퍼보다 높음 |
| 검증 / 추가 반응 | 바로 다음 1분봉 종가도 상단 + 버퍼보다 높음. candidate면 validated, valid면 reaction |
| 붕괴 | 종가가 하단 − 버퍼보다 낮음. 같은 봉의 다른 반응보다 우선 |
| 회복 | broken 이후 종가가 상단 + 버퍼보다 높음. candidate로만 전환 |
| 회복 후 검증 | 회복 봉 이후 새로 구간에 닿는 반응과 그 다음 봉 유지가 필요 |

경계와 같은 가격은 돌파·붕괴로 간주하지 않는다. 꼬리만 경계를 넘었다고 붕괴시키지 않는다. 반응 확인은 바로 다음 봉에만 유효하며 실패한 관측을 여러 봉 뒤까지 연장하지 않는다. 매 반응은 관측 사건이지 별도의 거래 기회나 통계적으로 독립된 표본을 뜻하지 않는다.

버퍼는 가격 단위의 필수 입력이다. 숨겨진 ATR 계수·최적값을 넣지 않는다. 실제 적용할 버퍼와 봉 주기는 이후 별도 사전 고정 대상이다. 구간은 등록 이후 시작된 첫 완성 분봉부터 관측한다. 등록 전이나 등록 시각을 걸치는 봉을 근거에 쓰지 않는다. 첫 봉 또는 중간 봉 누락·수정·역순·수신 시각 역행은 상태를 변경하지 않고 오류를 반환한다. 마지막 동일 봉 재전송은 멱등이다. 누락 자료를 보완한 후 이전 관측 상태에서 재생해야 한다. 이 예외를 주문 중단으로 연결하는 것은 후속 통합 단계다.

`scripts/replay_recovery_zone_evidence.py`는 기존 12개 진입의 지지 역할과 목표의 반대 역할을 각각 등록하고 실제 분봉을 재생한다. 기존 선택 시점에 등록하므로 과거 후보 선택의 타당성을 재구성하지 않는다. 구간 형성 이전 자료로 유효성을 만들어내거나 새 진입을 실행하지 않는다. 실제 수신 지연 자료가 없어 분봉 마감 시각 수신을 가정한다. 지연 수신은 별도 단위 테스트로 확인한다.

재현 예: `scripts/replay_recovery_zone_evidence.py --plans reports/validation/recovery_historical_v01_20260919_verified/plans.json --output <새 출력 경로> --buffer 0 --minutes 60`. 이번 0 버퍼·60분은 엄격한 구간 경계와 관측 동작 확인용 설정이며 거래 권장값이 아니다. 실행 전 소스 해시·설정을 저장하고 원자료 로더의 무결성 검사, 구간별 모든 과거 스냅샷 불변 검사를 수행한다.

## 구현 진행 — 구간 이력·목표 증거 계층

`app/research/recovery/evidence.py`에 변경 불가능한 증거·구간 이벤트·목표 기록과 시점별 점검 함수를 구현했다. 아래 상태 전이는 연구용 입력 계약이며 가격을 보고 자동 판별하는 시장 규칙은 아직 아니다. 각 이벤트 생산자는 출처와 구체적인 판정 근거를 제공해야 한다.

- `formed → candidate → validated → valid`: 형성만으로 유효하다고 판단하지 않는다.
- `valid → broken → reclaimed → candidate`: 회복 이후에도 별도 검증이 있어야 다시 유효하다.
- `retired`: 해당 버전은 재사용하지 않는다. 새로운 범위·근거는 새로운 버전의 이력으로 남긴다.
- `reaction`: 이미 유효한 구간에 확인된 반응을 추가 기록한다.

각 증거에 관측 시각·자료 사용 가능 시각·기록 시각을 보존한다. `as_of`는 결정 시각까지 기록된 사건만 반환한다. 늦게 받은 자료를 과거 결정에 소급하지 않는다. 중복 이벤트, 잘못된 상태 전이, 앞선 관측보다 오래된 사건으로 현재 상태를 바꾸는 입력은 거부한다. 정정 데이터가 필요한 경우 별도 연구 버전으로 재생해야 한다.

목표 기록에는 해당 목표 버전, 방향, 기준 가격, 첫 대응 가격, 반응 기한·목표 예상 기한, 도달 근거, 중간 구조 검토, 시간 만료 처리, 잔여 종료 조건을 포함한다. 시간·가격·버전이 잘못되면 거부하고, 서술 근거가 비었으면 UNASSESSED를 반환한다. 동일 기록을 다른 결정 시각에 재사용할 수 없다. 첫 대응이 선택한 목표 너머에 있으면 근거 미완성으로 처리한다.

점검 결과 `EVIDENCE_COMPLETE`는 이 계층에서 요구한 기록의 완성만 뜻한다. READY나 수익성 판정이 아니며 `order_authorized`는 항상 false다. 글이 채워졌다고 그 주장의 진실성까지 검증하지 않는다. 비용 후 손익비·위험 예산·거래 유형별 충돌·체결 확인은 후속 전체 진입 평가에 필요하다. 현재는 기존 엔진과 연결하지 않았으며 과거 12개 거래에 새로운 사건이나 근거를 임의로 채워 넣지 않았다.

검증: `tests/test_recovery_evidence.py`에서 늦은 자료의 소급 방지, 재검증 필요, 무효화 우선순위, 미래 자료·버전 불일치·누락 근거·목표 건너뛰기·잘못된 시각과 방향·중복·은퇴·숏 대칭·불변성을 다룬다.

## 사용자 원칙

- 큰 흐름과 보유 방향은 독립적이다. 큰 상승 중에도 근거 있는 단기 숏은 가능하다.
- 구간은 근거·형성 시점·상태가 있어야 한다. 무너진 근거나 미래 정보를 진입에 쓰지 않는다.
- 추가 전에 무효화 지점과 계좌 손실을 계산한다. 본절 회복만을 목적으로 버티지 않는다.
- 판단이 애매하면 대기할 수 있어야 한다. 청산 자체가 반대 방향 진입 신호는 아니다.

## 제안하는 진입 계약

각 후보에 아래 항목을 진입 주문 전에 고정한다. 항목이 빠졌다고 임의의 기본값으로 보충하지 않는다.

| 항목 | 기록해야 할 내용 |
|---|---|
| 판단 시점 | 결정 시각, 각 자료의 관측·사용 가능 시각, 완성 봉 여부 |
| 거래 유형 | 추세 지속·박스 반응·돌파 재확인·역추세 단기 중 근거 있는 유형 |
| 시장 판단 | 기간별 방향과 충돌 이유, 모름 여부; 가중합 하나로 근거를 대체하지 않음 |
| 진입 구간 | 버전, 형성 시점, 출처, 최근 유효 반응, 마지막 돌파·이탈 및 회복 상태 |
| 목표 | 첫 대응 구간, 선택 근거, 그 전에 만나는 반대 구조, 비용 후 손익비 |
| 시간 | 반응 확인 기한, 목표를 기대하는 시간 범위, 시간 만료 시 처리 |
| 도달 근거 | 시간 범위와 연결되는 당시 변동·구조 근거; 과거 분포를 쓰면 표본과 관측 종료 시각 |
| 종료 | 진입 근거 무효화 가격·상태, 부분 축소 후 잔여 종료 조건 |
| 수량 | 비용·체결 가정, 손실 예산, 실제 가능한 수량 및 유동성 |

먼 목표를 골라 손익비를 높이는 것만으로는 진입 근거가 완성되지 않는다. 목표 전 반대 구조가 있으면 그곳에서 먼저 대응할 계획을 세워 비용 후 손익비를 다시 계산한다. 대응 구간을 통과했다는 근거 없이 먼 목표로 바꿔 주문을 승인하지 않는다.

## 판단 상태와 주문 연결

| 상태 | 조건 | 신규·추가 주문 | 보유 중 처리 |
|---|---|---|---|
| READY | 필요한 근거가 시점에 맞게 완성되고 서로 양립함 | 기존 위험·체결 검사를 통과한 수량만 허용 | 기존 운용 계획 적용 |
| UNASSESSED | 필요한 기록이 누락되거나 해석이 미정 | 보류 | 보호 주문 유지, 새 위험을 늘리지 않음 |
| CONFLICTED | 근거가 충돌하고 거래 유형별 해소 조건도 미충족 | 보류 | 명시된 무효화·축소 조건을 적용; 충돌 자체만으로 자동 반전하지 않음 |
| INVALIDATED | 기록된 구간·거래 근거가 이미 무효화됨 | 해당 근거로 진입 금지 | 기존 명세의 축소·청산 우선순위 적용 |
| EXECUTION_BLOCKED | 데이터·계좌·주문 상태나 유동성 확인 불가 | 중단 | 기존 복구 명세에 따라 대사·보호·잔여 처리 |

재개는 시간 경과만으로 허용하지 않는다. 누락 근거 확보, 충돌 해소, 새 구간 버전·독립 진입 계약, 실행 상태 대사 등 해당 중단 원인을 해소한 사건을 기록한다. 신규 진입 보류가 기존 보호 주문 취소를 의미하지 않는다.

역추세 단기 거래에는 방향 전환 확정이 필요하지 않다. 대신 반대 흐름 속에서도 거래할 독립 반응, 첫 대응 구간, 반응 지연 시 종료 조건, 전체 방향으로 다시 밀릴 때의 무효화를 명시한다. 현재 데이터에서 손실이었다는 이유로 역추세를 사후 일괄 금지하지 않는다.

## 이번 점검의 범위와 한계

`scripts/review_recovery_entries.py`는 기존의 공통 진입 12개 전부를 점검한다. 진입 직전 완성 1분봉 종가와 직전 24시간 가격 범위를 설명용으로 기록한다. 24시간은 이번 검토의 제안된 고정 관측 창이며 수익으로 선택한 필터가 아니다. 범위 대비 목표 거리는 도달 확률이 아니고 READY 판정 기준도 아니다.

v0.1 계획에는 구간의 사용 가능 시각이 있지만 구간 상태 변경 이력, 목표 예상 시간·도달 근거, 중간 반대 구조가 명시돼 있지 않다. 따라서 12개 모두 새 계약 기준으로는 UNASSESSED다. 이는 모든 거래가 틀렸거나 모두 제외하면 전략이 개선된다는 뜻이 아니다. 원본 자료로 보완할 항목과 사람의 해석이 필요한 항목을 식별한 결과다.

현재 선택된 구간과 과거 봉의 겹침은 설명 자료다. 그 구간이 과거에도 존재했다거나 그때 지지·저항으로 인정됐다고 주장하지 않는다. 이후 손익은 카드의 별도 `after_entry_outcome` 필드에만 붙인다.

다음 구현에서는 구간 상태 이력과 위 계약을 생산하는 관측 계층을 먼저 만든다. 계약 없이 신규 진입을 막는 검사는 해당 계층과 함께 연결하고, 과거 v0.1 결과와 별도 버전으로 평가한다. 이 12개를 보고 수치 임계값을 골라 개선 효과를 주장하지 않는다. 새로운 자료 평가 전에도 손익뿐 아니라 UNASSESSED 비율과 사유를 공개한다.
