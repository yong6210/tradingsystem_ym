# 시장가 전환 위험 재승인 — 오프라인 통합 v1

2026-09-17. [구현](../../app/research/execution/fallback_preflight.py). 실제 네트워크·계정 조회·주문 전송 없이 기존 REST 입력 계약, 위험 수량 계산, SQLite outbox와 모의 디스패처를 연결했다. **일반 지정가 주문의 취소 후 시장가 전환 경로에 한정한다.** 보호 손절 전체 또는 실거래 어댑터 통합 완료가 아니다.

## 연결한 경로

전체 조회 형태의 원 주문 응답 → 종목/ID/방향/수량/종류 대조 → 단일 계좌 위험 경고·중단 상태 영속화 → 최종 미체결 잔량과 손실 예산 계산 → 현재 거래 규격 검사 → 원자적 주문 의도/outbox 저장 → 전송 직전 다시 위험·수량 검사 → 모의 접수/조회/체결 기록.

취소 요청과 취소 확정을 구분한다. 미확정이면 취소 또는 조회 의도만 생성한다. 취소 중 늘어난 원 주문 체결량을 잔량에서 제외한다. 전송 직전에는 저장한 원 주문의 최종 상태/체결 누계가 새 관측과 같은지도 확인한다. 다른 상태이면 자동 전송하지 않는다.

입력은 한 계좌의 대조가 끝난 스냅샷이다. 현재 자산·최고 자산·UTC 일초 자산, 보유 수량과 남은 손절 위험, 다른 주문의 예약 위험/명목, 이미 청산 주문에 예약된 수량, 주기 최초 예산·사용 손실/비용, 증거금상 허용 수량을 명시한다. 현재 마크와 시장가의 불리한 예상 가격, 고정 손절, 테이커 비용·손절 슬리피지·펀딩 예약도 별도 값이다. 누락을 0으로 채우거나 잔고를 추측하지 않는다.

## 추가 진입의 수량

주기 예산 = min(최초 승인 예산, 현재자산 × 0.5% × 경고 배수).

잔여 위험 = max(0, min(주기 예산 − 이미 사용한 손실/비용 − 현재 보유 위험, 현재자산 × 1% − 현재 보유 위험 − 다른 주문 예약 위험)).

단위 BTC 손실은 고정 손절까지의 거리와 불리한 손절 체결가격, 진입/청산 수수료·펀딩 예약을 포함한다. 승인 수량은 최종 미체결 잔량, 잔여 위험에서 가능한 수량, 1배 명목 노출 잔여분, 외부 증거금 검사 상한, 거래 규격 상한 중 최솟값을 수량 단위로 내림한다. 최소 수량 미달이면 대기하며 손절을 좁히거나 수량을 올리지 않는다.

원장에 이미 확정한 대체 주문 수량이 전송 직전 새 허용 수량보다 크면 전송을 차단한다. 같은 ID의 수량을 몰래 수정하거나 자동 새 주문을 만들지 않는다. `BLOCKED` 상태는 후속 재조정 대상으로 남긴다.

경고는 회복 뒤에도 유지한다. SQLite에 위험 경고·DD 중단·일손실 중단을 저장하고 재시작 후에도 반영한다. 이번 버전에는 자동 리셋이 없다. 일손실 중단도 다음 날 자동으로 풀리지 않으며 별도 건강 상태 확인/회복 절차가 필요하다. 이는 일간 중단을 날짜마다 초기화하던 동결 백테스트와 다르므로 과거 수익을 이 경로의 성과라고 하지 않는다.

## 위험 감소와 오래된 입력

- 신규 위험 중단·신호 만료·보호 준비 미완료는 추가 진입을 막는다. 기존 포지션을 줄이는 일반 청산에는 신규 진입 예산을 적용하지 않는다.
- 청산은 반대 방향, reduce-only, 실제 잔량에서 다른 청산 예약을 뺀 범위로 제한한다. 최소 명목 예외와 수량 단위 검사는 기존 계약을 사용한다.
- 계좌·가격·필터의 관측 시간이 현재보다 미래이거나 1초보다 오래되면 새 시장가 전환을 만들지 않는다. 이는 오프라인 정책 가정이며 실측 지연에 맞는 TTL은 미검증이다.
- 위험 입력이 오래돼도 신선한 원 주문 관측에 근거한 취소는 가능하다. 취소된 주문은 새 위험 입력을 받을 때까지 `REFRESH_CONTEXT`로 남겨, 일시적인 자료 지연을 영구 포기로 만들지 않는다.
- 계획 시점/전송 직전의 위험 입력과 판단을 SQLite audit에 남긴다. 원장과 위험 상태를 별도 트랜잭션으로 저장하므로 위험 중단이 먼저 남고 주문 계획 전에 죽어도 중단이 해제되지는 않는다. 여러 계좌/다중 위험 writer의 원자적 예산 예약까지 구현한 것은 아니다.

Binance의 단방향/헤지 모드 및 reduce-only 제약을 구분한다. 이번 모형은 단방향만 대상으로 한다. [공식 USD-M 주문 문서](https://developers.binance.com/en/docs/catalog/core-trading-derivatives-trading-usd-s-m-futures/api/rest-api/trade), 2026-09-17 확인. 현재 계정 모드나 수수료를 조회/변경하지 않았다.

## 검증과 다음 경계

신규 위험/연결 검사 17개: 롱숏 손계산, 부분 체결·비용 차감, 가격 악화, 최소수량 미달, 위험/증거금/노출 예약, 중단 중 청산 허용, 자료 지연·미래 시각, 취소 경쟁, 전송 재검사, 접수 응답 유실·재시작 중복 방지, 영속 경고/중단, 원 주문 최종 상태 변조 차단. 모의 거래소와 기존 실제 프로세스 강제종료 회귀 검사도 함께 실행한다.

여전히 미완료인 부분:

1. 실제 계정의 수수료/증거금/포지션/예약 주문으로 RiskContext를 생성하고 시간·버전 일관성을 보장하는 어댑터. 입력된 `reconciled=True` 자체가 일관성의 증거는 아니다.
2. 부분 체결 즉시 보호 주문 생성/유지, DD·일손실 중단 시 이미 보유한 포지션의 비상 청산. 이번에 신규 진입을 차단한 것만으로 기존 포지션 위험이 제거되지는 않는다.
3. 전송 직전 검사와 접수 사이 가격/상태 변화, 여러 주문의 동시 예산 예약, 다중 계좌 이름 공간. 현재는 계좌별 별도 오프라인 journal과 단일 조정기를 전제로 한다.
4. `BLOCKED`, 응답 불명/not-found, 시장가 부분 체결 후 종료의 경보 전달·운영 해결·재개 절차. 자동 재전송은 하지 않는다.
5. E007 전략 주문 계약 전체와 이 운영 경로의 통합, 실제 지정가 체결/전진 모의 검증.

다음 운영 작업은 2번 보호 상태 감시와 즉시 위험 감소 경로, 4번의 영속 경보/미해결 상태 처리다. 시장가 전환 테스트 통과를 실제 자동매매 실행 준비 완료로 해석하지 않는다.
