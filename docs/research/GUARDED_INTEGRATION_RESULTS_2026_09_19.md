## 검산 방식

`integration_audit.py`는 기존 Ledger·Costs의 계산 함수를 호출하지 않고 Decimal로 다음을 재구성한다.

- 주문 생성·취소·체결 상태, 각 체결의 실제 보유 수량과 로트 배분
- 부분 청산의 실현손익, 수수료·펀딩 반영 현금, 남은 로트의 배분 비용
- 손절 가격의 방향별 틱 반올림, 보유 및 미체결 증가 주문 위험
- 미주문 분할 예약과 실제 주문 이전, 전체 약정 손실의 중복 계산 여부
- 중복 축소 예약의 초과 매도 여부, 실제 축소 수량을 넘는 재진입 예약 여부

각 입력 이벤트 직후 검산하므로 최종 손익만 우연히 일치하는 경우를 피한다. 별도로 시나리오별 주문 이유와 횟수를 단정하고, 목표 앞 추가 거절도 명시적인 거절 기록으로 확인한다. 입력 이벤트를 새 엔진에서 재생한 상태가 시나리오 실행 상태와 같은지 비교한다.

검산기 테스트 8개는 정상 사례와 현금·로트 수량·예약·고정 분할 수량·실현손익·체결 시각·주문 상태의 의도적 손상을 다룬다. 입력 생성기는 기존 단위 테스트의 고정 fixture를 재사용하므로 입력 자체의 독립성은 주장하지 않는다. 독립적인 부분은 회계·수량·예약 계산이다.

## 결과 파일과 재현

최종 출력: `reports/validation/guarded_integration_v07_20260919_verified/`

`registration.json`에 소스 해시와 합성 입력임을 기록했고 종료 시 변경 없음을 확인했다. 각 시나리오 폴더에 events.jsonl, decisions.jsonl, ledger.jsonl, snapshot.json, checkpoint.json, config.json, prefix_audit.json, restored_snapshot.json을 보존했다. 초기 검산 실행도 별도 폴더에 남겨 두었다.

```sh
python scripts/validate_guarded_integration.py --output <새 결과 디렉터리>
```

표준 라이브러리만으로 실행한다. 신규 검산기 포함 독립 단위 테스트 155개와 기존 회복 엔진 68개, 총 223개가 통과했다. 번들 런타임에서 DB 공통 초기화를 제외한 연구 모듈을 검증했다. 저장 파일을 재생하려면 `scripts/run_guarded_recovery_replay.py`를 사용할 수 있다.

## 해석 범위

이 결과는 시장 수익성 검증이 아니다. 가격은 고정 합성 자료이며, 최초 구간 유효성 등 일부 입력은 명시적 fixture다. 시나리오 끝에는 잔여 원장을 검산하기 위해 독립적인 근거 무효화 사건과 종료 견적을 넣었다. 이것을 실제 전략의 수익·보유 기간·최적 청산 규칙으로 해석하지 않는다.

전체 애플리케이션의 DB·거래소 API·네트워크 체결 품질은 포함하지 않았다. 이 8개 경로는 전체 가능한 상태 공간이나 롱·숏 시장 표본을 대표하지 않는다. 숏 대칭과 다른 예외는 별도 단위 테스트 범위다. 다음 단계는 시장 관측에서 현재 계약의 입력을 자동 생성하는 어댑터와 사전 고정된 새 자료 평가다. 기존 8월 재사용 데이터의 결과를 새 표본 검증으로 바꾸지 않는다.
