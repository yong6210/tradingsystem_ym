# 닫힌 저장 세대의 증분 감사 v1

2026-09-18. 이 변경은 저장·검증 처리 비용을 줄이는 엔지니어링 변경이다. 전략 수익성, 실제 지정가 체결, 장기 수집 품질을 증명하지 않는다. 기존 역사 자료와 동결 구현은 수정하지 않는다.

## 문제와 변경

기존 압축 조정기는 세대 i의 원본/압축 검증 때 각각 0..i를 재생했다. N개 세대를 처리할 때 같은 앞부분을 반복해서 계산했다. 새 경로는 검증된 직전 상태와 새 세대 i만 재생한다. 원본과 압축본의 두 번 검사는 유지한다.

- [합성 실행기](../../app/research/data/incremental_generation_capture.py): 기존 동일 연결 저장기·공용 예산에 새 감사 조정기를 연결한다.
- [조정기](../../app/research/data/incremental_generation_pipeline.py): 원본/압축 작업자 결과와 원래 end fence를 비교하고 검증 영수증을 기존 archive-proof.json 안에 저장한다. 증명 파일 증가량도 기존 비용 판정에 포함된다.
- [영수증·오프라인 상태 복원](../../app/research/data/generation_audit_anchor.py): 직전 검증의 hash, 원래 end/handoff 및 현재 seed를 대조한다.
- [한 세대 재생기](../../app/research/data/incremental_generation_audit.py): 원래 전역 순번/hash·봉인·관찰·processor/reducer·종료 검사를 유지하며 현재 세대만 연다. 전체 root glob/rglob를 하지 않는다.
- [작업자](../../app/research/data/incremental_generation_worker.py): 부모 PID·15초 이내 수명·384MiB RSS 감시·입출력 한도를 유지한다.

## 신뢰 경계

첫 세대는 반드시 원점에서 시작한다. 이후에는 **같은 실행의 부모가 직전 원본/gzip 감사 및 보관 처리를 마치고 메모리에 유지한 증명 파일 hash**가 필요하다. 디스크의 증명 파일 hash를 새로 읽었다는 사실만으로 이 신뢰를 재구성할 수 없다.

증명에는 세대 번호, 계획/보관 정책/구현 hash, 직전 증명 hash, 원래 end/seed hash, 전역 원본·감사 순번/hash, 감사 요약 hash를 포함한다. 부모는 원본·gzip 결과의 영수증 일치와 새 구간 처리량을 확인한다. 영속 증명·보관 처리까지 성공한 후에만 메모리의 최신 hash를 전진시킨다. 부모 상태는 최신 hash와 다음 번호이며 진단 배열은 기존 최대16세대 안에서만 유지된다.

프로세스 손실 후에는 이 영수증으로 live 상태를 복원하거나 과거 검사를 건너뛰지 않는다. [기존 archive-aware 전체 재생기](../../app/research/data/read_archived_generation_capture.py)가 처음부터 원본/gzip을 다시 검사한다. 증분 감사는 과거 저장 파일이 이후에도 손상되지 않았다는 인증이 아니다. 테스트에서 앞선 저장 파일을 제거한 경우 새 세대 증분 검사는 가능하지만, 전체 복구는 실패해야 함을 확인한다.

## 고정 검증 계약

조건 탐색 없이 정상40초(per_tick20), 높은 입력18초(per_tick200), 전환8초, 봉인0.5초, 방향별1000레벨을 사용한다. 기존120초/16세대/대기2개/공유 예약2개 한도를 늘리지 않는다.

검증 항목:

1. 각 원본/gzip 작업자의 논리 재생 기록 수가 현재 end-start 차이이고, 전체 합은 실제 총 기록의 정확히2배다.
2. 같은 실행의 원래 end fence들로 계산한 기존 방식의 반복 재생량과 비교한다. 이전 실행의 시간과 직접 비교해 속도 배율을 주장하지 않는다. 이 수치는 논리 processor 재생량이며 파일 검증의 전체 I/O 바이트가 아니다.
3. 전체 재생·독립 기존 저널 재생·live 감사의17항목을 비교하고, 수신 후 dequeue된 프레임과 저장 수를 대조한다.
4. 저장 비용에 증명 추가 필드·부가 파일을 포함하고 공용 예산을 실제 모든 파일 합과 대조한다.
5. 부모 SIGKILL8곳(증명 승격 전후 포함)을 별도 프로세스로 복구·재복구한다. 파일 변경0, 새 연결0, 미완료 창 유지가 필요하다.
6. 기존 검사 및 새 경로의 변조·후보 범위·상태 일관성·실패·취소 검사를 실행한다.

## 수집 기반 작업의 남은 종료 조건

이 변경으로 과거 전체를 반복 재생하는 계산량 문제를 종료한다. 전체 수집 기반 완료와 구분한다.

- 남은 저장 범위: 장기 등록 길이에 따른 전체 파일/metadata/seed/압축/임시 예약의 최대 비용, 부모의 per-file 목록과 복구 읽기 비용에 상한·실패 정책을 둔다. 현재 공용 저장기의 sizes 목록과 전체 cold recovery는 역사 길이에 따라 커진다.
- 그 계약을 고정한 실행에서 입력 증가·작업 지연·공간 부족·중단을 확인한 뒤 짧은 공개 연결 검증과 장기 시험 등록을 판단한다. 24시간을 임의로 실행하거나 짧은 합성 결과를24시간 품질로 해석하지 않는다.
- 이 필수 조건을 충족하면 저장 기능 추가를 멈추고 미체결→시장가 전환, 슬리피지·펀딩·체결 불리함의 비용 검증과 고정 전략의 전진 모의로 돌아간다. 추가 전략 조합·파라미터 탐색은 이 단계의 필수 작업이 아니다.

새 공개 관측·private API·실주문0. 최종 채택 전략 없음. 모든 장에서 수익이 난다는 보장 없음.

논리 재생량은 원본·gzip 각1회로 정확히 전체 기록의2배였다. 파일 봉인 검증·압축 검증·상태 codec의 작업까지2배라는 뜻은 아니다. 누적 processor 상태·merged intervals는 기존 상한 안에서 여전히 검사한다. 높은 입력에서 대기열 상한2에 닿은 사실을 보존하며 장시간 여유가 충분하다고 결론내리지 않는다.

전체 원점 재생·별도 기존 raw 저널 재생·live 감사17항목이 일치했다. 부모 강제 종료8곳에서 별도 프로세스 복구/재복구가 일치하고 파일 변경0이었다. 증명 승격 전후는 두 번째 세대에서 중단해 이미 직전 영수증이 존재하는 경로를 확인했다.

합성 공동 적격 시간 비율은99.8185%/99.6078%이나 등록된24시간 자료가 아니므로 두 결과 모두 `QUALITY_INPUTS_REJECTED / NOT_REGISTERED_PILOT_DURATION`이다. 새로운 시장 관측 및 전략 성과는 없다.


## 회귀 검증에서 발견한 미해결 사항

연구424개와 수정 후 새 경로42개 검사는 통과했다. 그러나 첫 전체 실행 검사704개는 **실패10·오류5**였다. 같은 조건의 실패15개 분리 진단은 모두 통과했으나 전체 실행을 통과로 바꾸지 않는다. 전체 고유1,129개는 시도한 수이지 모두 통과한 수가 아니다. [회귀 검토 기록](../../reports/validation/incremental_generation_20260918/REGRESSION_REVIEW.md).

압축 작업자를 순차 종료하는 중 첫 작업자의 취소가 전파되면 둘째 작업자 종료가 생략될 수 있었다. 결정적인 취소 순서를 주입해 기존 코드의 미정리 상태를 재현했고, 새 조정기는 남은 모든 작업자를 보호된 정리 작업으로 닫은 후 취소를 전달한다. 첫 전체 실패의 정확한 스케줄이 동일했음을 증명한 것은 아니다. 동결된 과거 구현은 보존한다.

우선순위를 수정한다. **장기 확대 전에 시간에 의존하는 기존 테스트의 분기 도달 조건, 늦은 초기화, 예산 실패 이후 결과 저장·정리 경로를 결정적으로 재현하고 보완한다.** 0.45초 자료가 압축 비용을 상쇄한다고 가정하거나100ms 내 초기화가 끝난다고 가정한 검사를, 성능 시험과 구분해야 한다. 비용/위험 한도 완화나 통과할 때까지 반복 실행은 해결책으로 쓰지 않는다. 그 후 위 장기 자원 계약·공개 확인·체결/전진 검증 순서로 진행한다.

전체 회귀 승인 및 장기 수집 승인은 보류한다. 이 판단과 실패 원문을 최종 검증 기록에 포함한다.
