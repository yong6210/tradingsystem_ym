# 주문 영속화·재시작 복구 검증

2026-09-17. 상태: **오프라인 구현·24개 검사 통과. 실거래 미연결.**

## 구현

- 상태 전이와 전송 대기 명령을 같은 SQLite 트랜잭션에 저장. 저장 중 오류면 둘 다 롤백.
- READY→SENDING을 송신 전에 영속화. 동시 작업자가 같은 명령을 가져가도 하나만 점유.
- 응답이 사라지거나 재시작해 SENDING/UNCERTAIN이면 기존 ID 조회만 수행. 다른 ID/같은 ID 자동 재전송 없음.
- 시장가 체결은 누계와 새 증분으로 기록. 중복/역순 이벤트가 재고를 늘리지 않음. 누계 감소·의도 수량 초과·종료 상태 변경은 오류.
- 송신 직전에 외부 authorize 검사 필수. 현재 주문 최종 상태·시장가 위험·포지션·계약 규격 확인은 실제 어댑터의 책임. False면 BLOCKED로 남김.

## 확인한 장애 사례

| 사례 | 확인 결과 |
|---|---|
| 상태 수정과 outbox 삽입 사이 예외 | 재연결 후 상태/명령 모두 이전 상태 |
| 기록 후 전송 점유 전 재시작 | 한 번 전송, 완료 뒤 반복 호출은 재전송 없음 |
| 전송 점유 직후 실제 프로세스 강제 종료 | 재시작 후 조회, 미발견이어도 자동 재전송 없음 |
| 모의 거래소 접수 직후 실제 프로세스 강제 종료 | 접수된 주문을 조회해 복구, 총전송1회 |
| 접수됐지만 응답 타임아웃 | 기존 ID 조회로 체결 복구, 재전송 없음 |
| 취소 중0.001→0.002 BTC 체결 증가 | 목표0.003에서 잔여0.001만 시장가; 재시작 후 전체체결0.003 확인 |
| 두 작업자 동시 전송 점유 | 한 작업자만 성공 |
| 동일 부분체결 통지 반복/오래된 통지 | 체결 증분 중복 반영 없음 |
| 시장가 부분체결 뒤 종료 | 잔량 검토 필요 상태, 새 시장가 자동 생성 없음 |
| 전송 직전 위험 승인 실패 | 실제 모의 송신0회, BLOCKED 유지 |

판단 모듈9개 + 영속화/복구15개. 강제 종료는 별도 프로세스의 os._exit로 수행했고 모의 거래소 접수 기록은 별도 파일에 flush/fsync해 애플리케이션 재시작과 분리했다. 하드웨어 전원 장애나 실제 거래소 동작을 재현했다고 주장하지 않는다.

## 남은 경계

- 명령별 시장가 송신 시도를 한 번으로 제한하는 설계다. 거래소 차원의 exactly-once 보장이 아니다.
- 점유 직후 실제 송신 전에 죽은 경우는 미전송이어도 자동 복구 송신하지 않는다. 중복 위험 대신 명시적 미해결 상태를 선택했다. 운영 경보·원장 대조·권한 있는 해결 경로는 후속 과제다.
- 실제 REST/스트림의 순서/정체성/누계를 신뢰 가능한 Receipt로 정규화하는 어댑터는 미구현이다.
- SQLite 파일은 향후 계정·거래소·종목별 네임스페이스를 확정해야 한다. 현재는 단일 오프라인 범위이며 서로 다른 계정의 같은 original ID를 공유하면 안 된다.
- 체결 수량 증분 저장이며 실제 체결가격·수수료를 포함한 운영 회계와의 연결은 미완료다. 거래소 연결·키·실주문은 추가하지 않았다.
- DB 손상/디스크 오류, 통신 단절 중 비상 청산, 보호 주문 복구, 시장가 잔량 재승인, 사용자 경보는 미검증이다.
