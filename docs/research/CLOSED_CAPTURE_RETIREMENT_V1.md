# 종료된 수집 자료의 압축 보관 전환 v1

2026-09-18. [재시작 감독](RESTARTABLE_FEED_CAPTURE_V1.md) 다음 단계다. 새 합성 자료에 한해 원본 제거와 압축본 전용 재검증을 구현했다. 기존 사용자 데이터·연구 보고서·공개 관측 원본은 변경하거나 제거하지 않았다. 수집 중 원본 정리나24시간 운용을 허용하는 단계는 아니다.

## 제거하기 전에 필요한 증거

보관 정책은 저장 루트에 `storage.json`과 소유 잠금만 있는 시점에 등록한다. 이미 자료가 존재하는 수집 디렉터리에는 소급 등록할 수 없다. 정책은 실행 ID·루트·구현 해시를 고정한다. 기존 자료는 이 정책이 없으므로 대상이 되지 않는다.

준비 단계는 완료된 작업 원장과 마지막 외부 영수증, 각 journal의 소유 잠금, 전체 원본/감사 순번과 해시를 확인한다. 미확정 꼬리·임시 checkpoint·인계되지 않은 구간·사용 중인 작업 예약이 있으면 거부한다. 각 원본과 등록 gzip의 전체 복원 바이트가 같아야 한다.

그다음 새 감사 상태에서 **gzip만 명시적으로 읽어** 처음부터 재생한다. 기존 완료 결과의17개 의미 항목과 일치해야 보관 전환 계획을 저장한다. 계획에는 원본의 정확한 경로/크기/해시, gzip descriptor, 입력 cursor, 재생 작업 순서, journal metadata/checkpoint와 재생 증거의 해시를 묶는다. 호출자는 계획의 외부 해시 영수증을 보관해야 한다.

## 중단에 안전한 전환 순서

원본별로 **삭제 의도 저장·fsync → gzip 재검증 → 원본 unlink → 원본 디렉터리 fsync → 완료 기록·fsync**를 수행한다. 전체 입력/등록 상태를 먼저 검사하고 실제 제거 직전에도 다시 검사한다. 원래 파일과 알려진 완료/의도 상태가 모순되면 조용히 덮어쓰거나 재삭제하지 않는다.

원본이 없을 때는 유효한 의도 기록과 검증된 gzip이 모두 있어야 중단된 전환을 마무리할 수 있다. 의도 없이 사라진 파일은 손실로 간주해 거부한다. 임시 파일은 자동 채택하지 않는다. 이름 교체 후 응답을 잃은 기록은 파일과 디렉터리를 다시 fsync한다. 무관한 원본·orphan·임시 파일은 보존한다.

전환 후에는 `replay_retired_capture()`가 고정된 계획과 명시적인 gzip 참조로 감사한다. 기존 `recover_admitted_work()`는 원본 의존 경로이므로 전환된 자료에 사용하지 않는다. 등록 descriptor의 `originals_retained=true`는 등록 당시 증거로 보존하고, 현재 원본 보관 상태는 새 의도/완료 기록이 설명한다. 기존 완료 결과의 저장량도 수집 종료 당시 값이지 현재 inventory가 아니다. 이 차이를 실제 감독기의 결과 읽기/복구 경로에 통합하는 작업은 남아 있다.

- 과거11,099건 해시 대조(고유10,830경로)를 확인했다. 이번 전환으로 제거한 것은 새 합성 시험의 목록에 명시된 원본뿐이다. 기존 관측/전략 연구 증거를 삭제한 것은 없다.

## 공간은 실제 전체 비용으로 판단

원본을 지운 바이트 수만으로 절감 효과를 발표하지 않았다. 계획·의도/완료 기록·전환 전후의 두 감사 checkpoint까지 포함해 수집 종료 당시와 비교했다.

## 하루 저장량에 대한 재판단

[24개 조건부 용량 시나리오](../../reports/validation/closed_capture_retirement_20260918/capacity.json)는 기존에 본 입력률을 재사용한다. 압축률20%/100%, 입력률1배/2배,120초/1시간/24시간을 비교한다. 이는 가정별 계산이며 미래 시장률이나 운영 승인 기준이 아니다. 메타데이터21,641바이트/단위는 이전 짧은 감독 시험의 관측 대용치다. 새 보관 계획/추가 감사 비용까지 포함한 장기 상한이 아니며, 작은 시험의 실제 증가가 이 한계를 보여 준다.

관측된 이동1초 최대 레코드량612,159바이트/초가 하루 지속되고 압축률20%라고 가정하면, 미래의 **수집 중 원본 전환**을 가정한 정상 보관량은 약10.72GiB다. 하지만 현재 구현은 종료 후에만 전환하므로 원본과 압축본을 함께 유지하는 예상 최대량은 약59.98GiB다. 측정 당시16GiB 예비 공간 위 여유는 약15.26GiB여서 현재 방식은 이 가정에 맞지 않는다. 종료 후 절감을 장중 최대 공간 절감으로 계산해서는 안 된다.

공간과 별개로2초마다 seal하면 하루43,200단위다. 현 구현의 전체 시도 한도7회×62단위=434단위를 넘고, supervisor 영수증만 최소86,400개로4,096개 한도를 넘는다. 원래 수집 창120초 제한도 그대로다. 압축률이 좋아도 하루 수집은 승인되지 않는다.
