# 연속 순환과 전체 연구 엔진 저장·복원

## 결과

현재 `CyclingPlanRecoveryEngine`의 장부뿐 아니라 판단·주문 조정·계획 복원 상태를 JSON으로 저장하고 복구하는 경로를 구현했다. 세 번의 연속 순환에서 단계마다 재시작한 경로와 연속 실행 경로의 전체 저장 상태가 같았다. 기존 실제 48시간 자료에서도 다섯 지점에서 복원·모의 대사한 결과가 연속 실행과 같았다.

연속 검사에서 새 축소 계획을 만든 뒤에도 이전 `plan_recovery`가 남아 후속 추가를 막는 버그를 발견했다. 새 축소 의도가 채택되면 이전 복원 대기를 해제하도록 수정했다. 명시적 새 계획과 자동 복원 각각을 반복 검사했다.

## 저장하는 상태

- 포지션 방향·수량·평단·실현손익·비용, 장부 사건과 주문·체결 기록.
- 주된 방향의 판단 상태·근거 레지스트리, 고정 구간·구조 참조와 폐기 상태.
- 마지막 처리 봉·가격 반응 이력·처리 시계.
- 증가 주기·총수량 절반 축소 목표·미체결 잔량·반복 신호 사용 기록.
- 지정가 계획과 명시적 일시 중단, 취소 대사 중 조정 의도, 추가 불발/부분 체결 뒤 복원 의도.

체크포인트는 `cycling-complete-1` 형식이다. 지원 대상은 현재 연구 엔진 클래스 하나다. 생성자 입력을 다시 검증하고 하위 주문 장부를 사건 순서대로 재생한다. 판단 이력·증가 체결 수·계획 가격·참조·대기 의도의 연결도 대조한다. 지원되지 않는 새 상태 필드가 생기면 조용히 누락시키지 않고 저장을 거부한다.

실행 코드 해시가 바뀐 체크포인트는 자동으로 읽지 않는다. 코드 변경 이후 복구에는 명시적인 형식 이전 작업이 필요하다. 체크섬은 파일 손상 감지용이며 신뢰할 수 없는 작성자의 위변조를 인증하는 서명은 아니다.

## 복원 뒤 재개 조건

복원된 주문 컨트롤러는 항상 대사 필요 상태다. 외부에서 별도로 얻은 실제 포지션 및 미체결 주문 목록과 맞아야 해제한다. 불일치 시 장부를 덮어써 맞추지 않는다. 이번 검증의 외부 스냅샷은 연속 모의 실행에서 복원 전에 별도로 채취한 것이며 거래소 계좌 자료가 아니다.

대사 전에 새 봉을 전달해도 주문이나 판단 이력을 진행시키지 않는다. 따라서 대사 후 같은 봉을 정상 처리할 수 있다. 기존 봉 이력을 건너뛰는 데이터 공백은 여전히 보수·재생이 필요하다. 중복 체결 ID가 재전달돼도 수량을 두 번 더하지 않는다.

파일은 임시 파일 쓰기·동기화 후 원자적 교체로 저장하고 디렉터리도 동기화한다. 거래소 접속, 누락 체결 수집, 서비스 프로세스 자동 재시작은 구현한 범위가 아니다.

## 검증

신규 9개를 포함한 cycling 117개, 장부 9개 통과. 확인한 상황은 취소 중 재시작·늦은 체결, 부분 추가 체결·취소 중 재시작, 명시적/자동 계획으로 세 차례 순환, 대사 실패와 봉 미소비, 중복 체결, 파일 왕복, 손상·누락 상태·틀린 계획 가격 거부다.

실제 자료 재생: 2,880개 봉, 재시작 5회, 최종 잔량 0.05 BTC. 연속 실행과 전체 상태·판단/체결 기록이 일치했고 별도 장부 검산도 통과했다. 기존 v1의 세 경로 사건 기록도 유지됐다. 실제 경로에는 가상 초기 보유·비용·체결 가정이 포함되므로 전략 수익성이나 실거래 안정성의 입증은 아니다.

재현:

```sh
PYTHONDONTWRITEBYTECODE=1 .venv/bin/python scripts/verify_complete_cycling_restart.py
PYTHONDONTWRITEBYTECODE=1 .venv/bin/python -m unittest discover -s tests -p 'test_recovery_cycling_engine_checkpoint.py'
```

산출물: `reports/validation/cycling_complete_restart_20260919/summary.json`, `final_checkpoint.json`.

## 남은 우선순위

연구용 연속 실행·복구 검사를 마쳤으므로, 다음 검토는 주문 보조 기능 확장보다 **주된 추세 판단과 무효화된 운용 자리를 대체할 새 자리의 근거**로 돌아간다. 지금도 그 근거가 없으면 추가·전환을 보류하며, 유효한 새 매물대를 자동으로 찾는 전략은 완성되지 않았다. 실주문은 없다.
