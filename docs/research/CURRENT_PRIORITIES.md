## 시장가 전환 정책

‘주문이 밀림’의 최초 연구용 정의는 일반 지정가 주문 제출 후3초 동안 목표 수량 미체결이다. 3초는 성능이 검증된 최적값이 아니며 모의 주문 로그로 적합성을 확인한다. 제출 응답 자체가 불명확하면 타이머 만료를 실패로 해석하지 않고 원 주문 ID로 조회한다. 분봉만으로3초 대기열/체결률을 백테스트했다고 주장하지 않는다.

흐름: 지정가 제출 → 미체결 기한 → 취소 요청 → 거래소 최종 상태와 누적 체결량 확인 → 현 포지션/위험/수량 규격 재검사 → 남은 수량만 시장가 의도 생성.

- 취소 요청을 취소 완료로 간주하지 않는다. 취소 도중 체결된 수량도 제외한다. 전량 체결이면 시장가0.
- 신규 진입은 신호가 아직 유효하고 시장가 수수료·슬리피지·잔여 주기 손실 예산을 충족할 때만 전환한다. 유효성이 사라지면 취소 후 대기.
- 일반 청산의 전환은 현재 잔여 포지션까지 reduce-only로 제한한다. 모델은 단방향 모드만 대상으로 하며 헤지 모드에 그대로 적용하지 않는다.
- 손절·위험 한도 위반은 지정가3초 대기 대상이 아니다. 별도 보호 주문/시장가 청산 경로를 우선한다. 신규 진입을 차단한 상태에서도 위험 감소 청산은 막지 않는다. 통신 장애로 청산이 불가능하면 반복 생성 대신 상태 대조와 경보가 필요하다.
- 시장가 응답을 받지 못해도 다른 ID로 다시 보내지 않는다. 기존 시장가 client ID로 체결/상태를 대조한다. 시장가 주문 자체의 부분 체결·거절 처리도 디스패처의 후속 구현 대상이다.
- 현재 주문/위험/포지션 스냅샷의 기본 허용 나이는1초(연구 가정). 오래되면 새로 조회한다. REST/스트림의 순서 뒤집힘과 누적 체결량 감소는 외부 조정기가 차단해야 한다.

## 구현 계약과 한계

`app/research/execution/market_fallback.py`는 네트워크 없는 순수 판단 모듈이다. 다음 상태와 CANCEL/QUERY/MARKET_INTENT 등을 반환하며 실제 API를 호출하지 않는다. Decimal 수량으로 잔량을 계산하고 원 주문 기반의 결정적 시장가 ID를 만든다.

`durable_fallback.py`에서 상태와 outbox를 SQLite 트랜잭션으로 함께 저장한다. WAL/FULL 동기화, 원자적 전송 점유, 체결 누계/증분 기록을 추가했다. 실제 프로세스를 송신 직전·모의 접수 직후 강제 종료해 복구를 검사했다. 실제 거래소 통합 안전성의 완료를 뜻하지 않는다. 거래소의 client ID만으로 영구 exactly-once를 보장하지 않는다. 원 주문과 대체 주문, 체결 원장을 함께 대조해야 한다.

외부 위험 검사기는 새 시장가 가격으로 허용 수량·증거금·최소/최대 수량과 명목을 검사한다. 순수 판단 모듈은 그 결과보다 더 큰 수량을 승인하지 않는다. 디스패처는 시장가 의도의 최종 수량을 다시 필터 검사해야 한다. 정규화·상태 신뢰성은 어댑터 통합 검증 전 미완료다.
