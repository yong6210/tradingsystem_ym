# 같은 방향 순환매 — 사용자 확인 원칙

> 최신 정정: 사용자는 4시간봉을 예시로 든 것이며 유일하거나 필수인 방향 기준이 아니라고 명시했다. 아래 4시간봉 고정 설명은 과거 기록이고 이 정정에 의해 대체된다. 현재 판단 정리 기준은 [통합 판단 명세](CYCLING_DECISION_SPEC_2026_09_19.md)다.

이 문서는 2026-09-19 대화의 정정 내용을 기록한다. 충돌하는 기존 recovery 시험 규칙보다 우선한다. 실행 코드 반영 완료를 뜻하지 않는다.

## 확인된 원칙

- 4시간봉은 예시이며 유일하거나 필수인 추세 전환 기준이 아니다. 구체적인 전환 판정식은 아직 확정하지 않았다. 단기 반대 신호나 축소 체결을 추세 전환으로 대신하지 않는다.
- 롱 방향이 유지되면 롱, 숏 방향이 유지되면 숏으로 진입·추가·축소·재진입을 반복한다. 반대 방향 신규 진입은 추세 전환 판단이 있을 때만 허용한다.
- 진입·추가 자리는 시점 당시 알 수 있는 지지·저항 구간과 반응을 근거로 삼는다. 무너진 근거와 사후에 형성된 구간으로 추가를 정당화하지 않는다.
- 수량은 기존 논의대로 근거, 추가 후 노출·손실, 남은 증거금·대응 여력, 체결 가능량을 함께 평가한다. 고정 1/10 또는 영상의 5:5 예시를 의무 배분으로 만들지 않는다.
- BTC 가격이 $2,000~3,000 역행할 수 있는 운용을 고려한다. 이는 계좌 손실액, 고정 손절폭, 무조건 보유해야 할 구간을 뜻하지 않는다.
- 되돌림에서는 축소 직전 총 보유 수량의 최소 50%를 덜어낸다. 추가분만을 분모로 삼지 않는다. 기존 5 BTC에 5 BTC를 추가해 총 10 BTC라면 최소 5 BTC를 축소한다. 전체 본절 도달을 축소의 필수 조건으로 삼지 않는다.
- 부분 축소 또는 무포지션 상태와 방향 판단은 별개다. 잔여 물량을 항상 보유하도록 강제하지 않는다.
- 짧은 보유 시간이나 가까운 가격 간격만으로 자동 종료하는 기존 시험 규칙을 이 전략의 확인된 원칙으로 사용하지 않는다.

## 장부와 평가

거래소의 실제 포지션 회계 방식에 맞춘 수량·통합평단·실현손익과 전략의 물량별 기여도 장부를 구별한다. 영상이 가정한 선형 상품의 통합평단 방식에서는 부분 축소 후 잔여 평균가는 유지된다. 전체 손실 상태의 축소로 실현손실이 생겨도 평균가 개선과 노출 감소를 함께 평가한다.

잔여 포지션 본절과 누적 실현손익·비용을 포함한 전체 운용 회복 가격을 따로 계산한다. 개별 물량의 보유 시간과 방향 운용의 지속 시간도 구별한다. 전체 운용 성과는 실현손익·미실현손익·비용을 합산한다.

참고 영상: [최고의 매매 방법](https://www.youtube.com/watch?v=4o5Wgh3vGsc). 자동 자막을 읽고 예시 산식을 검산했다. 영상의 역행 숏 예시는 관리 산식 설명이며, 사용자 방향 원칙에 반하는 신규 거래의 허용 근거가 아니다.

## 미확정 사항

이 항목을 자동으로 확정한 것은 아니다. 후속 [시세 입력 후보 v01](CYCLING_SIGNAL_CANDIDATE_V01_2026_09_19.md)에 검토용 판정식과 실제 자료의 신호 관찰 결과를 분리 기록했다.

- 어떤 시간대의 구조 변화와 구간 이력으로 전환을 판정할지, 완성 봉 확인을 어떻게 적용할지, 되돌림 축소를 발동할 반응 조건은 아직 구체화되지 않았다. 시간대 지정만으로 임의의 지표·봉 개수·가격 임계치를 확정하지 않는다.

## 기존 시험과의 관계

v01~v03 결과는 이전 시험 구현의 기록이다. 사용자가 정정한 같은 방향 순환매의 수익성 검증 결과로 해석하지 않는다. 기존 자료와 동결 코드는 보존하고, 새 원칙에 맞춘 장부·방향·순환 주문 흐름부터 정합성을 검증한다.

## 첫 구현 범위 — 장부

`app/research/recovery/directional_cycling.py`에 기존 엔진과 분리된 선형 상품 체결 재생 모듈을 추가했다. 통합평단 유지, 실현·평가·비용 합산, 두 본절, 방향과 보유 상태 분리, 총 보유량의 최소 절반 축소, 부분 체결 후 잔량, 중복 이벤트 처리, 축소 완료 후 재추가를 다룬다. 절반 수량은 주문 단위로 올림한다. 하나의 축소 이벤트는 최초 총수량을 유지하며 재시도 때 다시 절반을 계산하지 않는다.

4시간봉 방향 판단과 되돌림 판단은 외부에서 명시적으로 입력받는다. 첫 장부 모듈 자체에는 실제 판단식·자동 자리 탐색·주문 수량 산출·주문 실행이 없다. 이후 추가한 수량 산출, 주문, 저장·복구 범위는 아래 후속 구현 절을 따른다. 실제 거래소 체결 대사기로 사용하지 않는다. 별도의 보호 종료 정책이나 시간 제한을 임의로 도입하지 않았다.

`tests/test_recovery_directional_cycling.py`는 영상의 2회 순환, 롱 대칭, 되돌림 부재의 손실 확대, 부분 체결과 재시도, 최소 절반 올림, 추세 전환 후 반대 진입 전 기존 포지션 정리, 무포지션 후 같은 방향 재진입, 비용·펀딩·본절, 중복 충돌을 검산한다. 이는 주문 흐름과 산식 검증이며 수익성 검증이 아니다.

## 후속 구현 — 수량 산출과 오프라인 주문

`cycling_admission.py`는 기존 `ZoneHistory`의 그 시점 유효 상태와 최신 반응 이벤트, 명시적인 허용 진입 가격 범위를 받아 수량을 계산한다. 구간 역할과 진입 범위는 외부 입력이며 자동 매물대 탐색이나 반응 판정식을 새로 확정한 것은 아니다. 사후 근거, 무효 구간, 오래된 호가·계좌 스냅샷, 미래 방향 판단을 거부한다.

수량은 요청량·총 노출 잔여량·유동성·증거금 한도·남겨둘 증거금·역행 시 전체 운용 손실 한도를 함께 적용해 주문 단위로 내림한다. 수수료와 예상 불리한 체결 가격도 포함한다. 모든 계좌 한도·예비 증거금·역행 폭·자료 허용 나이는 호출자가 명시하는 입력이다. 테스트의 숫자는 사용자 확정값이 아니다. 역행 시나리오는 수량 검토용이며 손절 주문을 생성하지 않는다. 청산가·유지증거금·변동 펀딩을 예측하는 모델은 아직 없다.

`cycling_orders.py`는 한 번에 하나의 활성 주문만 허용해 미체결 상태에서 여력을 중복 사용하지 않는다. 취소 요청 중 부분 체결은 반영하고, 취소 확정의 누적 체결량이 장부와 일치해야 다음 주문으로 진행한다. 축소 취소 후 재주문에서는 최초 총수량 기준 목표에서 실제 축소 체결량을 뺀 잔량만 주문한다. 같은 반응 근거로 증가 주문을 재사용하지 않으며, 새로운 계좌 스냅샷은 호출자가 제공해야 한다.

거래소 최소 주문량·금액을 충족하지 못하는 축소는 명시적으로 거부하며 임의로 전량 종료하지 않는다. 종료가 확정된 주문의 뒤늦은 새 체결은 불일치 잠금으로 처리한다. 외부 거래소에서 실제 체결을 수집·복구하는 기능은 미구현이므로 실거래용으로 사용하지 않는다. 저장·복구 및 방향 전환 정리의 후속 연결 범위는 다음 절과 같다.

검증: 장부 9개와 수량·주문 10개, 총 19개 테스트 통과. `scripts/replay_directional_cycling.py`로 최초 진입부터 영상의 두 차례 추가·절반 축소를 모의 주문 경로에서 재생했다. 최종 5 BTC, 평균가 $102,000, 누적 실현손익 −$2,000, 가격 $102,200에서 전체 손익 −$3,000, 전체 회복 가격 $101,600으로 산식과 일치한다. 비교 재생은 비용 0이며 비용 포함 산식은 별도 테스트했다. 실제 시장 수익성 결과가 아니다.

## 후속 구현 — 저장·복구와 추세 전환 종료

`cycling_checkpoint.py`는 장부 이벤트, 주문별 체결, 반응 근거 사용 이력, 진행 중 전환을 버전·체크섬과 함께 JSON으로 저장한다. 이벤트를 재생한 장부가 저장된 평단·손익·수량·축소 목표와 일치하는지, 주문 누적 체결량이 체결 장부와 맞는지 검증한다. 검증과 임시 파일 쓰기·flush·fsync 후 교체하므로 실패한 저장으로 기존 파일을 덮어쓰지 않는다. 체크섬은 파일 손상 탐지용이며 인증 수단은 아니다.

복원 직후 새 주문을 잠근다. 외부에서 따로 확보한 보유 방향·수량·평단과 활성 주문 ID·누적 체결량·상태를 `reconcile`에 전달해 일치해야 재개한다. 누락된 알려진 주문의 체결은 먼저 반영할 수 있다. 불일치를 장부 덮어쓰기로 없애지 않으며, 종료 확정 주문의 예기치 않은 체결 등 기존 실행 오류 잠금은 정상 스냅샷만으로 해제하지 않는다. 외부 자료 취득·최신성 보장·알 수 없는 체결의 복구는 호출 측에 남아 있다.

`request_transition`은 외부의 명시적인 4시간봉 방향 변경 판단을 받고 현재 주문의 취소를 요청한다. 취소 중 체결까지 반영하고 최종 수량이 대사된 뒤 `continue_transition`으로 실제 보유 잔량 전체를 종료 주문으로 만든다. 진행 중인 절반 축소 계획은 이때 전량 종료 계획으로 대체하되 과거 축소 기록과 손익은 보존한다. 종료 주문도 부분 체결·취소 후 실제 남은 수량으로 재주문한다. 전량 종료 체결 완료 전에는 증가 주문을 막고, 완료 후에는 새 반대 방향의 별도 자리·수량 검사를 거쳐야 한다. 자동 반대 포지션 개설은 없다.

검증: 복원·전환 13개 추가, 관련 합계 32개 테스트 통과. 취소 대기 중 재시작, 늦은 체결, 절반 축소 도중 전환, 전량 종료 부분 체결 후 재시작·재주문, 반대 진입 선행 차단, 파일 손상·누적 체결 불일치, 실패한 저장의 기존 파일 보존을 확인했다. 영상 예시 재생도 다시 통과했다. 4시간봉 전환 판정식과 되돌림 신호 생성 자체는 여전히 외부 입력이며 시장 수익성·실거래 검증은 아니다.
