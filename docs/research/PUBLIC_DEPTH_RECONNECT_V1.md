# 공개 호가 수집·재연결 검증 v1

2026-09-17. 범위: Binance BTCUSDC 공개 depth/bookTicker 수집과 기존 L2 장부 연결. 실제 주문·계정 조회·전략 채택은 수행하지 않았다. 이전 연구·L2 재생 구현은 수정하지 않았다.

## 결과와 실패 기록

**수정 후 두 연결의 정상 종료, 새 스냅샷 복구, 원본 재생 일치를 확인했다.** 첫 시도의 실패도 보존했다. 성공할 때까지 동일 실행을 반복한 것이 아니라, 종료 수신 처리의 구체적인 결함을 보완하고 한 번 재검증했다.

첫 시도에서는 첫 연결 종료 후 두 번째 연결/스냅샷으로 복구했으나, 마지막 종료 코드1006 때문에 통과시키지 않았다. 수신기를 취소한 채 종료 응답을 기다리는 코드에는 **대기열이 가득 차면 종료 프레임 처리가 막힐 수 있는 결함**이 있었다. 이제 호가 사용 권한을 먼저 제거한 뒤, 종료 중 메시지도 계속 읽어 원본에 기록한다. 닫는 중의 데이터는 L2에 반영하지 않는다. 제한된 대기열을 쓰는 모의 소켓으로 이 경로를 검증했다. 최초1006의 유일한 원인이 이것이었는지는 서버 측 기록 없이 확정할 수 없다.

수정 후 관측 UTC는 `2026-09-17T13:59:57.445566Z`부터 `14:00:14.347625Z`다. 일반 수집 구간 depth121건, bookTicker4,882건, 종료 수신204프레임, 전체 원본 봉투5,217개다. 스냅샷 전 버퍼/오래된 갱신 처리가 있으므로 depth121건과 공개 호가116건은 서로 다른 단위다. 두 번째 세션의 스냅샷 이전 버퍼를 실제로 처리했고, 새 스냅샷 반영 전에는 새 호가가 공개되지 않았다.

첫 세션 호가 사용 중단부터 두 번째 세션 첫 사용 가능 호가까지 약2.783초였다. 이 값에는 정상 종료 대기·새 연결·REST·동기화가 포함된다. 장애 복구 시간의 보장치나 네트워크 지연 추정값이 아니다.

## 구현 계약

- [봉투 처리기](../../app/research/data/depth_capture.py): 원본을 기록하고 flush한 뒤 상태에 반영한다. `sequence`, `session`, 단조 처리 시각으로 처리 순서를 고정한다. flush는 전원 장애까지 보장하는 fsync가 아니다.
- [한정 수집 실행기](../../scripts/probe_depth_reconnect.py): 공개 스트림 두 세션만 순차 실행한다. 세션마다 새로운 REST 스냅샷을 한 번 받는다. 기본 관찰6초, 명시 가능한 관찰 시간1~15초, 별도 연결/REST/종료 timeout을 둔다. 상시 수집기·자동 재시도 서비스가 아니다.
- REST 요청 시작/응답 본문 수신 시각은 실제 요청 스레드에서, 반영 시각은 수집 루프에서 기록한다. 스냅샷 장부의 사용 가능 시각은 **반영 시각 이후**다. 수신보다 나중에 반영된 자료를 과거 시점에 소급 사용하지 않는다.
- WebSocket 시각은 애플리케이션 `recv()`가 반환한 로컬 관측 시각이다. 운영체제 패킷 도착 시각, 거래소 시각 오차, 라이브러리 내부 큐 대기를 각각 측정한 것은 아니다.
- `SESSION_END`에서 장부를 즉시 차단한다. 실제 종료 응답은 별도의 `CLOSE_RESULT`로 기록한다. 사이의 `CLOSING_WS_MESSAGE`는 원본만 남기고 판단에 사용하지 않는다. 종료 후 수신이라도 새 세션의 데이터로 넘기지 않는다.
- 재연결은 새 소켓/새 세션/새 스냅샷/새 연결 갱신 사슬을 요구한다. 스냅샷만 받았다고 장부를 사용 가능하게 만들지 않는다.
- 동기화 실패, 잘못된 봉투, 수신 오류, 원본 로그 실패는 호가를 차단한다. 이 단계의 대응은 중단과 증거 보존이며 무한 자동 복구가 아니다.
- bookTicker는 별도 원본 관찰로 기록한다. 이번 실행에서 동시 최우선 호가의 독립 수치 검산이나 체결 증거로 사용하지 않았다.

## 검증

[새 검사](../../tests/test_depth_capture.py)16개를 포함한 관련354개 검사 통과. 기존 동결 자료의 해시 대조855건(고유 경로586개) 일치. 잘못된 시각/순서/세션/스냅샷 요청, 갱신 누락, 로그 flush 실패, REST 대기 중 연결 종료, REST 실패, 중복 스냅샷, 종료 수신/비정상 종료를 확인했다.

수정 후 원본 재생에서 호가116개·처리 결과·세션 통계가 실시간 처리 결과와 동일했다. 모든 출력은 해당 세션 스냅샷 반영 후이고 `SESSION_END` 이전이며, 종료 수신 기록을 입력으로 삼는 출력은0개였다. **동일 엔진의 재현성 검사**이며 수치 계산의 별도 구현 검산과 구분한다. 이전 자료111개 장부의 Fraction 검산은 [이전 검증](PUBLIC_DEPTH_REPLAY_V1.md)에 한정된다.

두 번의 실제 시도를 합해 공개 WS 연결4회·공개 REST4회, 실제 주문0·비공개 요청0이다. 이번 결과로 새 백테스트 수익률이나 채택 후보는 생성하지 않았다.

## 재현

프로젝트 루트에서 `websockets`가 있는 실행 환경으로:

```bash
.venv/bin/python scripts/probe_depth_reconnect.py --output reports/validation/NEW_UNIQUE_DIRECTORY --seconds 6
```

출력 디렉터리가 이미 존재하면 덮어쓰지 않는다. 원본은 `capture.jsonl`, 출력은 `online_quotes.jsonl`, 상태 처리 결과는 `processing_results.jsonl`이다. 재생만 하려면 `scripts.probe_depth_reconnect.replay_capture(path)`를 호출한다. 원본 봉투가 손상됐으면 성공 판정을 내리지 않는다.

공식 연결 규칙은 [Binance 로컬 장부 절차](https://developers.binance.com/en/docs/products/derivatives-trading-usds-futures/websocket-market-streams/How-to-manage-a-local-order-book-correctly)와 [스트림 경로 변경 안내](https://developers.binance.com/en/docs/products/derivatives-trading-usds-futures/websocket-market-streams/Important-WebSocket-Change-Notice)를 따른다.

## 남은 작업과 다음 순서

1. **전진 자료 수집 계약**: 관측 시간·공백·시계·저장 실패·재연결 처리·자료 제외와 보존 기준을 수집 전에 고정한다. 가격/체결/호가 원본을 연결할 자료 구조와 운영 용량을 명시한다. 현재의 초 단위 샘플로 장기 통계나 maker 체결률을 추정하지 않는다.
2. **체결 모형 적격성**: 실제 거래 집계·호가 정렬, 부분 체결/대기/역선택, 비용 민감도를 검증한다. L2는 개별 주문 대기열 순번을 알려주지 않으므로 가격 접촉을 체결로 확정하지 않는다.
3. **운영 통합과 전진 모의**: 실제 계좌 증거 생산기, 조건부 주문과 실행 주문 대응, 외부 경보, 리더/복구, 공통 진입 위험 예산을 연결한다. 후보·기간·비용이 미정인 전진 채택 계약은 계속 등록 차단 상태다.

장시간 수집, 서버 강제 종료·정전·프로세스 강제 종료의 실제 네트워크 복구, 네트워크 단절 중 손실 한도, 계좌 권한/수수료, 지정가 체결률, 전략 수익성은 이번 완료 범위에 포함되지 않는다. 장기 수집이나 실주문 프로세스는 시작하지 않았다.
