# 실행·원장·위험 엔진 상세 계약

상태: 목표 설계. E001 가격 진단은 이 매매 엔진을 구현하지 않는다. 기존 시뮬레이터도 아래 모든 항목을 충족했다고 간주하지 않는다.

## 1. 자료와 단위

MarketSpec: venue, symbol, linear/inverse, quote/settlement asset, tick_size, qty_step, min_qty, min_notional, position_mode, margin_mode, fee_schedule_version. 이 계획의 손익 식은 선형 계약 연구용이며 실제 계약 확정 전 역계약에 재사용하지 않는다.

Bar: open_time, close_time, available_at, OHLCV, source_hash. Event: event_id, event_time, received_time, sequence, payload_version. 동일 시각은 sequence로 정렬하고 동일 ID는 한 번만 반영한다. 수정된 과거 자료는 새 데이터 버전이다. 결측·중복·역순·잘못된 단위는 실패 처리하며 조용한 보간을 하지 않는다.

금액은 결제 통화, 수량은 BTC, 가격은 quote/BTC, 비율은 fraction, 비용은 bp 필드로 구분한다. 주문 가격·수량은 계약 규격에 맞춰 의도별 보수적 반올림하며 반올림 후 최소 주문과 위험을 재검사한다. 원장 비교 허용 오차는 통화/수량 정밀도에 따라 명시한다.

## 2. 인과적 처리 순서

각 이벤트에서: 시간/중복 검사 → 기존 활성 주문과 시장 이벤트 처리 → 체결·비용·펀딩 원장 반영 → 평가/위험 갱신 → 가용해진 완료 봉 특징 → 전략 의도 → 공유 위험 승인 → 신규 주문 제출. 새 주문은 submit_time + latency 이후에만 활성화된다. 동시 이벤트는 거래소 순서가 있으면 따르고, 없으면 동률 정책을 실행 명세에 기록한다.

분봉의 전체 고저가는 봉 마감 전 특징에 사용하지 않는다. 이전 활성 주문의 봉 내 체결 추정과 다음 판단에 쓰는 완료 봉을 구분한다. 신규 주문을 제출한 봉의 과거 고저가로 체결시키지 않는다.

한 봉에서 손절과 익절 모두 닿았으면 단일 경로를 사실처럼 주장하지 않는다. 기본은 불리한 허용 순서를 사용하고 반대 순서 민감도를 함께 보고한다. 결론이 순서에 따라 바뀌면 더 세밀한 자료 없이는 불충분이다. 갭 손절은 손절선 가격 보장 대신 다음 실행 가능 가격과 비용을 적용한다.

## 3. 주문 생명주기

CREATED → SUBMITTED → ACKNOWLEDGED → ACTIVE → PARTIALLY_FILLED → FILLED. 거절·만료·취소 완료는 종료 상태. CANCEL_REQUESTED는 종료가 아니므로 취소 확인 전에 추가 체결이 발생할 수 있다. 취소/체결 경쟁, 수정 주문, 지연 ACK를 이벤트로 남긴다.

Post-only 시장성 주문은 거절 또는 거래소 정책에 따른 처리이며 무료 시장가로 전환하지 않는다. reduce-only는 남은 실제 재고까지만 체결하고 반대 포지션을 만들지 않는다. 주문 의도 ID로 재전송 중복을 막는다. 유효기간 이후 미체결 잔량은 해제하되 취소 확인 전 위험 예약은 유지한다.

분봉 가격 관통은 체결 대용 가정일 뿐 대기열 증거가 아니다. 단순 터치는 자동 전량 체결로 세지 않는다. 모든 전략/주문이 같은 봉의 허용 체결량을 공유한다. 체결 우선순위와 참여율은 등록한다. 취소 지연·부분 체결·미체결·불리한 체결 후 가격 이동을 보고한다.

## 4. 원장 식과 불변식

선형 계약에서 방향 s∈{-1,+1}, 수량 q≥0, 진입 평균 a, 청산 p이면 실현 손익 = s×q×(p−a). 같은 방향 추가의 평균은 수량 가중 평균. 부분 청산 후 잔여 평균은 유지한다. 수수료는 각 실제 체결 명목금액×해당 요율이다.

잔액 = 초기 잔액 + 누적 실현 손익 − 누적 수수료 − 순 펀딩 지급 + 입출금.
평가자산 = 잔액 + 미실현 손익. 평가용 mark와 체결가격을 구분한다. 펀딩은 실제 지급 시각의 적격 포지션과 부호로 반영한다. 익절한 총액을 수익으로 세지 않는다.

항상 체결 누계 = 포지션 변화 + 닫힌 수량의 대응 관계가 맞아야 한다. 잔량 음수, 한 체결의 중복 반영, 실현/미실현 중복, 미체결 주문 수익 반영은 오류다. 별도 원장 재생기로 최종 잔액뿐 아니라 모든 이벤트 직후 상태를 대조한다.

수수료/펀딩/슬리피지/순수 가격 손익을 분리해 합계가 전체 손익과 일치하도록 한다. 가상 전략별 장부와 실제 순포지션 장부는 별도다. 상계 시 내부 기여 배분 규칙을 고정하고 가상 양방향 재고를 거래소 헤지 모드로 오인하지 않는다.

## 5. 위험과 충돌

주문 승인 전에 현재 포지션+살아 있는 주문의 최악 체결 수량, 총/순노출, 최초 손절까지 손실, 잔여 예산, 증거금, 최소 주문을 검사한다. 승인 이후 갭이나 지연으로 한도를 넘을 수 있으므로 승인 한도를 손실 보장으로 표시하지 않는다.

동시 후보가 예산을 초과하면 사전 고정 우선순위/비례 축소 규칙으로 처리한다. 손익을 본 뒤 유리한 주문을 먼저 체결하지 않는다. 청산 주문은 신규 위험과 별도 큐지만 동일 시장 유동성을 사용한다. 레버리지·유지증거금 구간·청산 수수료는 실제 계약 확정 전 미구현 상태를 표시한다.

## 6. 장애·종료·재개

자료 지연, 연결 끊김, 주문 상태 미확인, 원장 불일치 시 신규 위험을 차단한다. 기존 포지션은 사전 확정된 보호 주문/비상 청산 정책으로 관리하며 시스템 중단을 포지션 소멸로 처리하지 않는다. 재시작은 이벤트 재생→거래소 잔고/주문 대조→불일치 해결→재개 순서다.

백테스트 종료 시 (a) 종료 직전 평가자산 (b) 명세상 강제 청산 비용 후 자산을 구분한다. 종료 밖 가격으로 청산하지 않는다. 열린 재고·미체결 잔량·종료 제외 건수를 보고한다.

## 7. 모듈 입력/출력

features: Bar→FeatureSnapshot; signals: Snapshot→SignalIntent; risk: Intent+PortfolioState+OpenOrders→ApprovedIntent/RejectReason; execution: ApprovedIntent+MarketEvent→OrderEvent/Fill; accounting: Fill/Funding/Transfer→AccountState; portfolio: 전략 의도들→배분된 의도; metrics: 원장/이벤트→지표. 보고서는 저장된 지표만 읽는다.

특징/신호는 계좌를 변경하지 않고, 위험 모듈은 체결을 생성하지 않으며, 회계 모듈은 전략 판단을 하지 않는다. 실거래 어댑터는 연구 계산 모듈의 의존 대상이 아니다.

## 최신 실행 우선순위와 시장가 전환

[현재 우선순위](CURRENT_PRIORITIES.md)를 따른다. 사용자 결정으로 일반 미체결 지정가는 지연 시 취소 확정 후 잔량을 시장가로 전환한다. 신규 진입은 신호/시장가 비용 포함 위험을 재검사하며 위험 청산은 별도 우선 경로다. 판단·영속 기록·모의 전송 복구 관련24개 테스트를 통과했다. 실제 거래소 연결과 운영 경보는 미완료다. 기존 E004 시장가 기준 실험은 변경하지 않았다.
