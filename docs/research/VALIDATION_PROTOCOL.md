# 연구 등록·평가·탈락 절차

상태: 후속 실험 설계 규칙. E012 이후 적용 범위는 [진행 검토](RESEARCH_REVIEW_2026_09_17.md)를 함께 읽는다. 과거 등록/판정은 불변 기록으로 보존한다.

## 2026-09-17 평가 계약 점검

최근 E005~E011에는 실행 전 고정한 탐색 선별 기준이 있지만, 아래에서 요구한 최소 경제적 효과·정밀도의 수치 계약이 충분하지 않다. 이를 확증적 채택 절차 완료로 해석하지 않는다. 기존 실패를 없애거나 새 문턱으로 소급 합격시키지 않는다. E006/E012의 원인/방법 진단은 수익성 선발과 구분한다.

향후 확증 등록은 효과의 단위·대조군·최소 개선 수치, 추정 구간 정밀도와 표본 의존성/다중 비교 처리, 관찰 종료 규칙, 비용·DD·일손실·미회복 기간 기준을 모두 고정해야 한다. 미정 필드가 있으면 `DRAFT_NOT_ELIGIBLE_FOR_CONFIRMATION`이며 실행 가능한 탐색 코드가 있어도 확증적 합격을 판정하지 않는다. [전진 평가 계약 v1](FORWARD_ACCEPTANCE_CONTRACT_V1.md)과 `check_forward_acceptance.py --require-ready`에서 등록 구조/미정 차단을 구현했다. 실제 통계 판정 실행기와 새 전진 runner 연결은 아직 미완료다.

100주기는 검정력 계산의 대용이 아니고 매년 양수는 보편적 요구가 아니다. 기존 등록에 적용한 기준은 유지하되, 새 설계에서는 허용 손실과 회복 기간의 목적에 근거해 기준을 정한다. 이미 본 자료는 새 분할에서도 회고 자료다. 운영 주문 품질 검사와 수익성 확증은 별도 완료 조건으로 관리한다.

## 1. 실험 등록 양식

필수: experiment_id, parent_id, question, economic_rationale, falsification, change_axis, controls, candidate_count, primary_metric, secondary_metrics, minimum_effect, precision_target, periods, warmup, label_span, purge/embargo, exclusions, costs, risk_budget, seeds, source/data hashes, dependencies, resource_budget, stopping_rule, evidence_kind.

minimum_effect와 precision_target이 미정이면 합격 판정을 위한 실행 등록을 막는다. 방법 감사는 효과 합격 대신 계산 일치/편향 평가 기준을 등록한다. 시간·거래 수만 임의로 늘려 통계적 확신을 만들지 않는다. 전진 모의 관찰 기간은 독립 블록 수·변동성·최소 효과를 토대로 실행 전에 결정한다.

## 2. 자료 분리와 반복 탐색

2023-01~2026-08은 이미 관측한 자료다. 이 범위의 새 분할과 워크포워드는 회고적 평가다. 훈련에서 고른 규칙은 다음 평가 구간 동안 고정한다. 특징 준비 구간은 과거만 허용하고 평가 라벨이 훈련/선택 경계를 넘는 사건을 제거한다. 중첩 길이는 최대 결과 관찰/보유 기간과 처리 지연을 반영한다.

새 전진 자료도 중간 결과를 보고 설계를 바꾸면 다음 버전에서는 선택에 사용된 자료다. 원래 동결 버전의 전진 결과와 수정 버전의 탐색 결과를 분리한다. 후보/기간/지표를 시험한 전체 수를 기록하며, 역사적 전체 시도 수가 불명확하면 미상이라고 남긴다.

최초 후보 연구는 후보당 한 등록 규칙으로 시작한다. 민감도 분석의 범위·개수는 실행 전에 등록하고 최고점을 최종값으로 자동 선택하지 않는다. 자원 한도와 종료 조건은 실험마다 고정한다. 유의해질 때까지 실행을 추가하거나 좋은 연도만 남기지 않는다.

## 3. 측정 정의

| 지표 | 정의/주의 |
|---|---|
| 총수익 | 입출금 없는 동일 초기 자본에서 종료 평가자산/초기−1; 단위 신호 bp와 별개 |
| 최대 낙폭 | 평가자산/그 시점까지 최고 평가자산−1의 최저값; 샘플링 간격 공개 |
| 회복 기간 | 최고점 하회부터 회복까지; 미회복은 우측 검열로 표시 |
| 거래 기대값 | 비용 후 주기 손익 평균; 부분 익절을 독립 주기로 부풀리지 않음 |
| 꼬리 위험 | 일/주 손익 및 하위 꼬리 평균; 빈도·표본수·정의 고정 |
| 위험 효율 | 변동성·노출·손절 위험 사용량을 함께 보고; 손실이면 비율만으로 순위 숨기지 않음 |
| 체결 품질 | 승인/거절/부분/미체결 수, 의도 대비 체결량, 지연, 역선택 |
| 비용 | 수수료·펀딩·슬리피지 분리; 이중 차감 금지 |
| 장세 | 온라인 가용 분류와 사후 설명 분류를 별도 필드로 저장 |

연환산/Sharpe는 주기와 무위험률·표본 의존성 가정을 밝히며 적은 거래 수의 높은 비율을 확정 우위로 해석하지 않는다. 보고서는 전체·연도·롱숏·장세·비용 시나리오별 수치와 제외 건수를 포함한다.

## 4. 지지·기각·불충분

구현 검증 실패: 성과 판정 금지. 자료 또는 체결 해상도 부족: 불충분. 사전 최소 효과보다 신뢰 구간 전체가 낮으면 해당 경제적 효과를 기각할 수 있다. 구간이 기준을 가로지르면 불충분. 지지는 사전 주 지표·최소 효과·위험 기준·비용 스트레스·기간 일관성 기준을 모두 만족해야 한다. 구체적인 수치는 실험 등록 전에 확정한다.

다중 후보 비교는 선택 편향을 반영할 방법과 한계를 사전 지정한다. 블록 재표집은 모든 의존성을 자동 해결하지 않는다. 블록 길이·빈 날짜·가중 방식·대조군 재사용을 공개하고 독립 구현으로 검산한다. 이미 선택한 전략의 결과를 새로운 독립 발견이라고 부르지 않는다.

## 5. 검증 피라미드

1. 수식: 롱숏, 부분 청산, 평균단가, 양/음 펀딩, 수수료, 단위 변환을 손계산.
2. 인과성: 미래 자료 변경 불변성, 완료 봉 경계, 지연, 준비 구간, 연도 경계.
3. 사건: 부분체결 후 취소, 취소 중 추가체결, 중복 이벤트, 갭 손절, reduce-only, 공유 유동성, 충돌 승인.
4. 회계: 별도 재생 원장과 매 이벤트 상태 일치; 총손익 기여 합계 일치.
5. 실험: 고정 입력/seed 재현, 해시 변경 감지, 실패 기록 보존, 제외 표본 검산.
6. 통계: 작은 열거 사례와 독립 구현; 기간/표본 가중과 재사용 의존성 점검.
7. 통합: 새 엔진/기존 엔진의 공통 규칙에서 거래 이벤트 차이를 설명. 동등하지 않으면 별도 버전.
8. 전진: 동결 주문 의도와 실제 모의 체결의 차이를 기록. 분봉 시뮬레이션으로 이 단계를 대체하지 않음.

## 6. 실험 산출물 계약

registration.json(실행 전), status.json, data_quality.json, signals, orders, fills, ledger, exclusions, metrics.json, verification.json, report, environment/dependency lock 정보를 남긴다. 해당 없는 주문/원장은 not_applicable로 표시한다. 결과 경로는 새로 만들고 덮어쓰지 않는다. 오류 시 FAILED와 마지막 완료 단계·원인을 남긴다.

모든 표의 행은 실험 ID·모델 버전·기간·비용·자료·원장으로 추적 가능해야 한다. 보고서 숫자를 수작업으로 수정하지 않는다. 코드 리팩터링은 등록된 엔진을 그대로 옮기는 대신 새 버전에서 동등성 검증 후 적용한다.
