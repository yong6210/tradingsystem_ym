# 순환매 시세 입력 후보 v01 — 판정식 검토용

## 사용자 원칙과 시험 규칙 구분

사용자 확인 원칙은 4시간봉 추세 전환, 같은 방향의 반복 운용, 되돌림에서 총수량 최소 절반 축소다. 아래 고점·저점 정의, 확인 봉 수, 구간 폭, 반응 방식은 아직 사용자 확인을 받지 않은 연구 후보다. 기본 실거래 경로에는 연결하지 않았고 방향 처리 연결에도 `enable_research_candidate=True`가 필요하다.

- 4시간봉: UTC 정렬된 연속 1분봉 240개가 모두 완료돼야 생성한다. 시작 지점의 불완전한 4시간 구간은 제외한다. 누락·역순·수정 봉은 거부하고 정확히 같은 마지막 봉의 재전달은 신호를 다시 발행하지 않는다.
- 방향 후보: 좌우 각각 1개 완성 4시간봉으로 확인한 고점·저점을 사용한다. 최근 두 고점과 두 저점이 함께 높아지면 롱, 함께 낮아지면 숏이다. 엇갈림·동일 가격은 이전 방향을 유지한다. 근거가 부족한 최초 구간은 판단 불가다. 전환이 늦어질 수 있으며, 이것이 사용자 매매법에 가장 적합하다고 검증한 것은 아니다.
- 자리 후보: 60분봉 좌우 1개 확인 피벗으로 지지·저항 구간을 만든다. 폭은 중심 봉 범위의 10%와 2 가격 단위 중 큰 값이다. 구간 생성 이후의 1분봉 접촉·유리한 종가와 다음 봉 유지를 기존 `ZoneObserver`로 관찰한다. 반응 버퍼는 2 가격 단위다. 모두 설정 파일의 시험값이다.
- 진입 후보: 현재 방향과 같은 역할의 유효 구간에서 새 반응이 생겨야 한다. 허용 가격 범위는 구간과 유리한 방향으로 구간 폭 한 개를 더한 범위다. 실제 주문은 기존의 수량·비용·여력 검사까지 통과해야 한다.
- 축소 후보: 보유 방향 반대 역할의 구간 반응이며 최신 추가/진입 체결 가격보다 유리하게 되돌아온 경우다. 통합평단 본절은 조건이 아니다. 반환하는 축소 비율은 총수량의 0.5다. 이는 되돌림 발동 조건의 후보이지 사용자 확정 세부식이 아니다.

## 구현과 검증

`cycling_signals.py`가 입력 집계·피벗 확정·방향·구간 반응·행동 후보를 생성한다. 방향 연결은 기존 `CyclingOrders.request_transition`으로 이어져 취소·대사·잔량 종료 순서를 보존한다. 자동 체결이나 신규 반대 포지션을 생성하지 않는다.

신호 검사 10개 추가, 관련 총 42개 테스트 통과. 미완성 봉·부분 시작 구간·누락 봉·피벗 확인 지연·미래 데이터 없는 접두 구간 재생·혼합 구조의 기존 방향 유지·본절 전 축소 후보·중복 재전달·방향 연결의 명시적 연구 활성화·수신 시점 보존을 확인했다.

## 기존 실제 자료 점검

`scripts/inspect_cycling_signals.py`를 실행했다. 입력은 기존 BTCUSDC 공개 선물 아카이브 2026-08-31~2026-09-17의 18개 일별 ZIP이며, 각 파일을 동반 체크섬과 대조했다. 이전에 사용한 개발 자료로, 새로운 미사용 검증 자료가 아니다. 역사적 수신 시각은 봉 종료 시각으로 가정했다.

구간 중첩으로 같은 시각에 여러 반응이 나올 수 있다. 위 숫자는 거래나 물타기 횟수가 아니다. 반대 역할 반응도 보유 상태·최근 추가 가격 등 축소 조건을 아직 결합하지 않은 관찰 수다. 구간 중첩 우선순위와 구간 수명 관리도 추가 검토가 필요하다.

결과: `reports/validation/cycling_signal_candidate_v01_20260919/summary.json`, `four_hour_assessments.jsonl`, `zone_reactions.jsonl`, `config.json`. 설정과 실행 소스 및 원자료 해시를 기록했다. 다음 단계는 이 후보의 시점별 근거를 주문 재생에 결합해 원하는 순환 흐름이 발생하는지 검토하는 것이다. 수익성·안전성·실운영 적합성 판정은 하지 않았다.
