2026-09-17. [기계 판독 정책](../../configs/research/forward_data_policy_v1.json), [계약·시간 적격성 검사](../../app/research/foundation/forward_data_contract.py), [검사 실행기](../../scripts/check_forward_data_contract.py).

**완료: 자료 품질 정책과 등록 구조 검사, 시간 적격성 계산, 기존 짧은 자료의 한계 진단. 미완료: 이 계약을 실행할 장시간 수집기·파일 내구성·복구·시계 감시·시장 스트림 통합. 실제 24시간 수집은 시작하지 않았다.** 정책 숫자는 사전 기술 기준이며 성능이 최적임을 검증한 값이 아니다. 이번 버전의 숫자를 결과에 맞춰 바꾸지 않고, 변경이 필요하면 이유와 별도 버전을 남긴다.

## 기존 계획에서 바로잡은 구분

| 구분 | 이번 자료 시험 | 수익성 전진 평가 |
|---|---|---|
| 질문 | 원본·시계·저장·재연결이 모의 실행의 입력으로 충분히 추적 가능한가? | 후보가 비용 후 경제성과 위험 조건을 만족하는가? |
| 기간 | 시작부터 연속86,400초, 종료 시점 고정 | [기존 평가 계약](FORWARD_ACCEPTANCE_CONTRACT_V1.md)의730일도 충분성이 입증된 기간이 아님 |
| 후보 | 선택하지 않음 | 후보·대조·버전의 사전 고정 필요 |
| 중간 확인 | 자료 품질/저장 공간/장애 감시 | 위험·품질 확인, 좋은 성과를 보고 조기 종료하지 않음 |
| 통과의 의미 | 선언한 입력 시간의 품질 기준 통과만 | 정밀도·경제성·위험·실행 조건까지 별도 검증 필요 |
| 현재 실행 상태 | 등록 차단 | 계속 등록 차단 |

24시간은 날짜 경계와 장시간 저장/재연결을 점검하기 위한 **첫 기술 시험**이다. 주말·모든 장세·희귀 장애·수익성을 대표하지 않는다. 이 시험이 통과해도 자동으로 장기 수집 또는 전략 평가를 시작하지 않는다. 다음 관찰 기간은 품질 결과와 전략의 정보·정밀도 요구를 근거로 새로 등록한다.

## 수집 범위와 이벤트 단위

대상은 Binance USDⓈ-M BTCUSDC다. 공개 경로의 depth100ms/bookTicker와 market 경로의 aggTrade/markPrice1s를 함께 저장한다. 경로 분리는 [Binance 공식 스트림 안내](https://developers.binance.com/en/docs/products/derivatives-trading-usds-futures/websocket-market-streams/Important-WebSocket-Change-Notice)를2026-09-17에 재확인했다. 계정·개인 데이터는 이 수집 범위에 없다.

필수 봉투는 `run_id`, `process_epoch`, `channel`, `connection_session`, 전체 수집 순번, 원문, 원문 해시, 수신 UTC/단조 시각, 처리 UTC/단조 시각이다. REST는 요청 ID·요청 시작·원문 응답 수신·상태 코드를 별도로 기록한다. 거래소 이벤트/거래 시각과 로컬 수신 시각은 다른 필드다. 서로 다른 프로세스/부팅의 단조 시각을 그대로 이어 붙이지 않는다.

- depth는 기존 엄격한 스냅샷/갱신 사슬로 복원한다. 재연결 때 새 세션과 새 스냅샷으로 다시 연결될 때까지 사용할 수 없다.
- bookTicker는 별도 관찰이다. 호가 사슬 오류를 덮거나 자체적으로 지정가 체결을 증명하지 못한다.
- aggTrade는 집계 체결 사건이다. 중복 ID의 원문 충돌·역순·누락 의심을 보존하고 검증한다. 거래가 없는 시간 자체는 결측으로 세지 않는다. ID 의미와 연결 복구 정합성을 검증할 어댑터는 아직 미구현이다.
- markPrice는 별도 신선도 조건을 가진다. mark에서 보이는 펀딩 관련 값과 실제 정산된 펀딩 원장은 구분한다. 손익 평가에는 실제 정산 증거가 필요하다.
- 두 연결의 자료는 로컬 수신/반영 순서로 결합한다. 늦게 도착한 사건을 거래소 시각으로 과거 판단에 삽입하지 않는다. 사후 REST 보충은 연구용 별도 자료로 보존하며 당시 판단 가능했던 이력을 복원한 것으로 취급하지 않는다.

## 시간 적격성과 공백 처리

모의 실행 입력의 공동 적격 시간은 다음 다섯 조건의 **교집합**이다: `l2`, `market_connection`, `mark`, `clock`, `durable_log`. 장부 동기화·채널 생존·마크가격 신선도·시계 및 루프 감시·원본 영속화가 모두 성립해야 한다. 각 조건의 유효 구간은 반열린 구간 `[시작, 종료)`로 기록한다.

| 고정한 기술 기준 | v1 값 | 해석 |
|---|---:|---|
| 전체 공동 적격 시간 비율 | 99.5% 이상 | 전체86,400초를 분모로 사용 |
| 시작부터 각1시간 구간 비율 | 99% 이상 | 하루 평균으로 특정 시간의 장애를 숨기지 않음 |
| 가장 긴 부적격 구간 | 10초 이하 | 장기 복구 실패를 평균에 희석하지 않음 |
| L2 마지막 유효 갱신 나이 | 1초 이하 | 장부가 조용하더라도 신선도 가정을 자동 연장하지 않음 |
| mark 마지막 수신 나이 | 3초 이하 | 가격 입력의 보수적 기술 기준 |
| 감시 간격 / 허용 루프 지연 | 250ms / 500ms | 실행기에서 실제 측정해야 함 |
| UTC와 단조 시계의 변화량 차이 | 100ms 이하 | UTC 절대 시각 정확도나 네트워크 지연을 증명하는 값이 아님 |

영속화 순번 유실·같은 ID의 내용 충돌·갱신 사슬 공백·단조 시각 역행·미영속 원본으로 판단 공개·파싱 오류는 적발 수량을 보존하고 해당 시험을 미통과 처리한다. 정상 재연결에 따른 공백도 위 시간 분모에서 제거하지 않는다. 모든 결측 구간과 실패 자료를 남긴다.

겹친 구간은 합집합으로 합쳐 중복 관측이 시간을 부풀리지 못하게 한다. 첫 유효 시점 이전·종료 후 남은 시간·재연결 중·프로세스 중단 시간을 포함한다. 조기에 중단하면 원래 종료 시각까지 나머지를 부적격으로 남기며, 뒤에 성공한 시간으로 시험 구간을 밀지 않는다. 종료 시점 이후의 좋은 자료로 연장하거나 실패 세션을 삭제하지 않는다.

`calendar_quality`는 이 구간 산술과 문턱을 검사한다. 입력 구간을 생성하는 실제 감시기의 진실성·서로 같은 시계 영역인지까지 증명하지 않는다. 반환값도 `QUALITY_INPUTS_PASS_ONLY`로 제한했다. 누락된 채널은 다른 채널의 정상 데이터로 대체할 수 없다.

## 저장·복구·자원 계약 — 실행기 구현은 다음 단계

1. 원문을 먼저 기록하고 파싱한다.128MiB 단위로 파일을 교체하며 파일 순번·전 파일 해시·마지막 봉투 순번을 묶는다. 봉투 원문과 오류도 보존한다.
2. fsync 주기의 상한은1초다. **원본의 영속화가 확인된 연속 순번까지만** 판단용 데이터를 공개한다. fsync가 끝나기 전에 RAM에 있던 자료로 판단을 내리면 안 된다. 반영·공개 시각은 fsync 이후 실제 시각이며 과거로 소급하지 않는다. 이 지연으로 신선도 기준을 만족하지 못하면 부적격으로 남긴다.
3. 원본 fsync → 원자적 checkpoint 교체 → checkpoint/부모 디렉터리 동기화를 검사한다. 장애 뒤에는 마지막 확인된 prefix만 재생하고 찢어진 마지막 줄/미확정 꼬리를 별도로 보존한다. hash는 변경 탐지를 돕지만 fsync나 디스크 정상 상태를 대신하지 않는다.
4. 가용 공간16GiB 이하 또는 시험 원본64GiB 한도에 도달하면 중단한다. 재시도는 전체 시험에서 정한1·2·4·8·16·30초의 유한 재시도 예산을 공유하며 성공 때마다 예산을 무한 초기화하지 않는다. 거래소 제한 응답의 대기 조건도 존중해야 한다. 예산 소진 뒤 남은 기간은 부적격으로 유지한다.
5. 최소 가용 공간·최악 구간 처리율·큐 상한·쓰기 지연·메모리 사용과 프로세스 종료 복구를 실제 시험한 기록이 있어야 실행기 등록 역할에 묶는다. 현재의 짧은 수집기와 flush 성공만으로 이 역할을 채우지 않는다.

이전 원본은16.902초 동안3,142,400바이트였다. 그 한 구간의 비율을 하루로 단순 환산하면 약16.06GB(14.96GiB)다. 두 스트림의 짧은 관측이며 종료 구간도 포함하므로 최대 트래픽·4개 스트림 총량·일일 저장량 보장이 아니다.64GiB는 정책상 중단 한도이지 충분하다고 검증한 용량이 아니다. 아직 공간을 예약하거나 큰 파일을 생성하지 않았다.

## 비용·체결 가정

| 시나리오 | maker 수수료 | taker 수수료 | 시장가 추가 불리한 가격 이동 |
|---|---:|---:|---:|
| 사용자 maker0 가정 | 0bp | 5bp | 2bp |
| 스트레스 가정 | 2bp | 7bp | 5bp |

1bp=0.01%. 각 체결 명목에 대한 편도 수수료다. 위 값은 민감도 비교용 가정이며 계정 수수료표로 확정한 것이 아니다. 시장가의 기준 가격은 해당 시점 반대편 장부의 실제 수량별 소진 가격이고, 여기에 추가 불리한 이동을 붙인다. 스프레드/장부 소진과 추가 스트레스를 구분해 보고하며 동일 비용을 다시 더하지 않는다. 관측 깊이가 부족하면 가격 불명으로 남기고0비용으로 만들지 않는다. 이 L2 체결 모형은 이번에 구현한 것이 아니다.

일반 지정가 대기3초와 취소 중 체결→종료 확인→잔량 위험 재승인→시장가 전환은 기존 주문 계약을 유지한다. 취소 ACK를 종료로 간주하지 않으며 보호 손절은 일반3초 대기 정책과 분리한다.

메이커는① 수동 체결 없음 시나리오와② 별도 검증이 필요한 대기열 가정 모형을 구분한다. 가격 접촉만으로 체결을 만들지 않는다. ‘체결 없음’도 전체 전략 손익의 엄밀한 최악 경계는 아니다. 놓친 수익과 회피한 손실이 함께 달라지기 때문이다. 실제 순번·부분 체결·취소 경합·주문 지연 증거 없이 실체결률을 제시하지 않는다.

실제 계정 요율과 운영비는 `null`이다. 자료 수집 준비를 막는 이유로 사용하지 않지만, 실현 순이익 판정에서는 반드시 확인해야 한다. 실제 정산 펀딩이 없는 구간도0펀딩으로 대체하지 않는다. 기존 전략 백테스트의 비용이나 결과에는 소급 적용하지 않았다.
