# 체결 후 보호 상태 감시·영속 경보 v1

2026-09-17. [구현](../../app/research/execution/protection_supervisor.py), [검사](../../tests/test_protection_supervisor.py). **보호 상태 판단·필요 조치·로컬 경보 저장까지 구현했다. 실제 보호 주문 생성, 비상 시장가 전송, 외부 알림 전달은 아직 연결하지 않았다.** 요청/명령 의도와 실제 체결을 구분한다.

## 범위와 입력 계약

첫 체결 이후의 단방향 포지션을 대상으로 한다. 최초 미체결 신규 주문을 승인하는 코드가 아니다. `scope`는 모의계좌/종목/거래주기를 포함하며 한 주기마다 별도다. 단일 조정기가 포지션, 해당 주기의 전체 진입·보호·일반 청산 주문 목록을 대조한 스냅샷을 공급해야 한다. 입력 `version`은 조정기의 증가 버전이며 거래소 updateTime을 그대로 쓰지 않는다.

이번 보호 계약은 **MARK_PRICE 기준의 고정 손절**이다. CONTRACT_PRICE를 사용하는 과거 계좌 실험과 동일 실행 조건으로 주장하지 않는다. 실제 거래소 보호 주문의 트리거 종류/가격보호 옵션/청산 제약까지 검증한 것은 아니다. 이후 어댑터는 이 모형에 포함되지 않은 조건을 확인하거나 별도 버전으로 처리해야 한다.

## 판단 순서

1. 스냅샷이 오래됐거나 대조되지 않았으면 신규 위험 동결·포지션/전체 주문 재조회·경보를 요구한다. 모르는 잔량으로 비상 주문 수량을 만들어내지 않는다.
2. 평탄 상태라도 남은 진입/보호/응답 불명 주문이 있으면 주기가 끝났다고 보지 않고 정리·재조정을 요구한다. 완료 주기가 같은 scope로 다시 열리면 비정상 재진입으로 중단한다.
3. 보호 수량에는 신선한 `ACTIVE` 관측이며 반대 방향·reduce-only·고정 손절·MARK_PRICE가 일치하는 주문만 합산한다. `PENDING`/`UNKNOWN` 요청은 보호로 인정하지 않는다. 잘못된 방향·손절·가격 기준은 즉시 위험 상황으로 처리한다.
4. 새 부분 체결로 보호 수량이 부족해지면 신규 위험을 동결하고 진입 잔량 취소를 요구한다. 아직 보호 요청이 없으면 부족 수량의 `ENSURE_STOP_REQUIRED`를 저장한다. 요청 중/응답 불명이면 새 보호 주문을 중복 요구하지 않고 조회한다.
5. 보호 공백이1초에 도달하거나 손절 접촉/위험 위반이 있으면 `URGENT_REDUCE_ONLY_REQUIRED`를 저장한다. 일반 지정가의3초 만료를 기다리지 않는다. 1초는 연구용 정책 값이며 실측 최적 지연이 아니다. 실제 비상 주문이1초 이내 체결된다는 보장도 아니다.
6. 알려진 진행 중 청산 수량은 비상 청산 요구량에서 제외한다. 기존 청산의 상태가 불명이면 조회·경보를 요구하고 자동으로 두 번째 청산을 만들지 않는다. 이때 위험이 남아 있음을 감추지 않는다.

위반 중단 상태는 보호가 나중에 확인돼도 자동 해제하지 않는다. 수량 증분/최소 주문/증거금 검사나 실제 송신을 수행하지 않으므로 `URGENT_REDUCE_ONLY_REQUIRED`를 체결 완료나 실행 가능한 주문으로 해석하면 안 된다.

## 영속화와 경보

SQLite WAL/FULL, `BEGIN IMMEDIATE` 안에서 현재 관측·판단·요구 조치·경보를 함께 저장한다. 중간 예외는 전부 롤백한다. 구버전/동일 버전의 상충 자료/주기 중 손절 이동은 거부한다. 보호 공백 시작 시각과 중단 원인은 재시작 후에도 남는다.

`requirements`는 **현재 필요한 조치의 스냅샷**이다. 매 판단 때 최신 목록으로 교체하며 전송 가능한 주문 outbox가 아니다. 주문으로 전환할 때 별도 client ID/중복 방지/예약/접수 대조가 필요하다.

`alarms`는 scope·원인별로 중복을 억제하고 최초/최근 발생 시각을 남기는 로컬 outbox다. 상태 `PENDING_LOCAL`은 사용자에게 경보가 전달됐다는 뜻이 아니다. 알림 연결·재시도·전달 확인은 미구현이며 메시지를 외부에 보내지 않았다.

## 완료와 남은 작업

신규14개 검사: 첫 부분 체결·보호 요청 대기·추가 체결 부족분·보호 확인·공백 시간 초과·손절/위험 즉시 청산 요구·청산 중복 방지·자료 불명·잘못된 보호 주문·롱숏·평탄 후 정리·재시작/경보 중복·원자적 롤백·버전/손절/주기 재진입 검사. 한 테스트 안의 여러 경계 조건을 새 독립 테스트로 부풀리지 않는다.

다음은 감독기의 요구 조치를 기존 주문 원장/위험 예약과 연결하는 오프라인 조정기다. 부분 체결의 보호 주문 생성→확인→거절/응답 불명→비상 청산→부분 잔량→평탄 후 주문 정리를 모의 거래소로 처음부터 끝까지 재현해야 한다. 지금 완료한 일반 시장가 전환 경로와 별개의 부분이며 운영 안전성 완료로 표시하지 않는다.
