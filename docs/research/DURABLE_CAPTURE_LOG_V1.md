# 원본 로그 영속화·프로세스 종료 복구 v1

2026-09-17. [구현](../../app/research/data/durable_capture_log.py), [단위 검사](../../tests/test_durable_capture_log.py), [강제 종료·원본 왕복 실행기](../../scripts/run_durable_capture_drill.py).

**완료: 원본 분할 저장, 기록/파일 연결 해시, fsync 후 사용 가능 순번, 불완전 꼬리 보존, 새 실행 구간으로 재개, 실제 SIGKILL 복구.** 실제 public/market 통합 수집기와250ms 감시·1초 fsync 스케줄은 아직 연결하지 않았다.24시간 수집·실주문·새 전략 평가는 시작하지 않았다.

## 저장과 판단의 경계

`append(payload)`는 원본을 쓰고 순번을 반환한다. 이 반환값은 판단에 사용할 수 있다는 뜻이 아니다. `commit()`은 다음 순서를 성공한 뒤 `CommitReceipt(sequence, record_sha256, available_monotonic_ns)`를 반환한다.

1. 변경된 원본 파일들을 fsync하고 새 파일 이름이 있는 디렉터리를 동기화한다.
2. 임시 체크포인트에 파일별 확인된 바이트 길이·해시·마지막 순번을 기록하고 fsync한다.
3. `checkpoint.json`을 원자적으로 교체하고 디렉터리를 fsync한다.
4. 여기까지 완료한 실제 단조 시각을 기록하고 공개 가능한 순번을 전진시킨다.

오류가 나면 writer는 실패 상태가 되고 `publication_fence()`·추가 쓰기·commit이 거절된다. 기존 데이터를 파일에서 읽을 수 있다는 사실로 실패 상태를 우회하지 않는다. 종료 함수는 미확정 기록을 자동 commit하지 않는다. `os.fsync`의 로컬 파일시스템 의미에 의존하며 컨트롤러·전원 차단의 영구 보장 시험을 대신하지 않는다.

이 API를 실제 판단 경로가 따르도록 연결하는 일은 다음 단계다. 저장 모듈만 추가했다고 기존 실시간 수집기의 판단 공개가 이미 영속 순번에 묶인 것은 아니다.

## 파일·레코드·동시성

- 각 원본은 `sequence`, 실행 구간 `epoch`, 직전 기록 해시, `payload`, 현재 기록 해시를 가진다. payload에 들어온 원문 문자열을 그대로 JSON 인코딩해 보존한다. NaN·무한대·크기 초과는 쓰기 전에 거절한다.
- 각 파일 머리는 run ID, epoch, 파일 번호, 첫 순번, 직전 **확인된 파일 구간**의 해시를 가진다. 체크포인트는 파일 이름/바이트 길이/해시의 순서 목록과 마지막 기록을 고정한다.
- 회복 후 이전 파일의 미확정 꼬리가 남아 있어도 새 파일을 만든다. 이전 파일의 전체 길이를 확인된 길이로 오인하지 않는다. 새 머리의 연결은 직전 체크포인트가 가리킨 구간까지만이다.
- 체크포인트를 읽을 때 모든 확인된 파일·해시·기록 사슬·순번·epoch·종단 값부터 검사한다. 이후에만 순회자가 기록을 내준다. 손상된 확인 구간은 빈 로그로 바꾸지 않고 오류로 중단한다.
- 로컬 POSIX `flock`으로 협력하는 writer/recovery reader 하나만 접근한다. 같은 writer 객체에 대한 호출도 소유자가 직렬화해야 하며 여러 스레드의 동시 호출을 지원하지 않는다. 다른 호스트·네트워크 파일시스템·외부 프로세스의 임의 파일 변경을 방어하는 분산 잠금/보안 서명은 아니다.
- 기본 파일 분할128MiB, 단일 레코드4MiB 상한, 원본 총64GiB, 가용 공간16GiB 기준을 구현했다. 분할 머리까지 포함해 추가 쓰기 예산을 검사한다. 실패 기록도 사용한 공간으로 남는다. 운영 처리량·여유 공간의 충분성은 별도 용량 시험이 필요하다.

## 복구 규칙과 응답 유실

미확정 꼬리·새로 생긴 미등록 파일·남은 임시 체크포인트를 삭제하거나 덮어쓰지 않는다. 복구 결과에는 꼬리의 파일 이름·시작 바이트·길이·해시가 남는다. 체크포인트에 없는 완전한 JSON도 확정된 기록처럼 재생하지 않는다. 손상된 마지막 줄 역시 그대로 남는다.

복구는 확인된 구간을 전부 검증한 뒤 원본·체크포인트·디렉터리를 다시 동기화한다. 다음 쓰기는 새 epoch와 새 파일에서 시작한다. 확인된 순번은 연속이며, 이전 미확정 꼬리에 같은 숫자가 있어도 그 바이트는 공개 기록에 포함되지 않는다. 감사 시에는 epoch와 파일/위치도 함께 식별해야 한다.

**체크포인트 교체 후 응답 전에 죽으면 재시작에서 새 기록이 보일 수 있다.** 이를 무조건 유실로 처리하거나 이전 응답 순번으로 강제 되돌리지 않는다. 교체된 체크포인트와 원본이 일치하면 다시 동기화해 복구한다. 이 사실은 소비자 처리나 주문 송신의 exactly-once를 보장하지 않는다. 재생은 상태 재구성용이고 주문 등의 부수 효과를 다시 실행해서는 안 된다.

과거 기록 복구는 현재 시장 상태 복구가 아니다. 결과는 `live_market_state_restored=false`이며, 실제 수집 재개에는 새 연결·스냅샷·시계 영역 검증이 필요하다. 복구 시점의 단조 시각으로 오래된 시장 기록을 최신 시세로 만들지 않는다.

모든 시나리오에서 복구 뒤 새 기록 하나를 commit하고 순번·내용을 대조했다. 강제 종료 직후의 모든 원본 파일 해시는 재개 후에도 동일했다. 이는 같은 시스템에서의 프로세스 종료 시험이며 실제 정전·커널 종료·디스크 고장 시험이 아니다.

또한 기존 공개 자료5,217개를 새 로그에 넣어34개 파일로 분할한 뒤 재생했다. 원문 봉투에서 나온 호가116개, 처리 결과, 세션 통계가 이전 결과와 정확히 같았다. 이 왕복 검증은128KiB 분할/작은 테스트 예산을 사용했다. 당시 기록의 시각을 보존한 **오프라인 저장·재생 검사**이며, 현재 fsync 지연을 실제 시세와 결합하거나 새로운 전진 관측을 한 것은 아니다.

신규18개 포함 관련389개 검사 통과. 검사 범위는 기록/동기화/교체 오류, 부분 쓰기, 부족한 공간, 예산 초과, 동시 writer 차단, 확정 구간 손상/절단/해시 오류, 체크포인트 누락·타입 오류, 재개 시 원본 보존이다. 기존 동결 자료 해시 대조883건(고유614경로) 일치. 실제 주문0·비공개 요청0·시장 데이터 요청0이다.
