# 주문 행동 계약 v1 — 2026-09-17

## 현재 위치와 이번 범위

**E005 실제 BTCUSDC 2년·6개 구현 비교와 E006 손실/조기 청산 진단 완료 → 이번: 주문 행동 명세와 순수 판단 코드 → 다음: 버전별 고정 비교 등록·실행과 모의 주문 통합.** 전체 연구 목록 S01~S13을 최근6개 구현으로 축소하지 않는다.

본 계약은 목표가 있는 R0/F0 계열부터 적용 가능한 연구용 계약이다. T0처럼 목표 없이 추세를 보유하는 후보에 강제하지 않는다. 새 계약의 수익성 백테스트·실거래 연결은 아직 하지 않았다. E005/E006 소스·원장·설정은 보존한다.

구현: `app/research/execution/order_rules.py`. 설정: `configs/research/order_rule_profiles_v1.json`. 검사: `tests/test_order_rules.py`, `scripts/check_order_rule_profiles.py`. 주문 전송·계정 접근 없는 순수 입력→판단 코드다.

## 1. 신호·진입 의도·실제 포지션을 분리

- `SignalState`: 완료 봉의 방향과 신호 구간(episode). account/paper 이름 공간+BTCUSDC+전략/규칙 버전을 scope로 둔다. 같은 방향이 유지되면 같은 episode다. 완료 봉에서0(무신호)을 거치거나 반대 방향이 되면 새 episode를 만든다. 체결·손절 자체는 신호를 새로 만들지 않는다.
- `EntryBook`: 사용한 신호 구간·마지막 판단시각·진행 중 진입 의도·최종 종료 확인시각. `reserve_entry` 성공은 주문 의도 예약이지 전송이나 체결이 아니다. 같은 판단을 다시 호출해도 새 의도를 만들지 않는다.
- 실제 주문/포지션: 별도 조정기가 누적 체결·남은 주문·보호 주문 상태를 대조한다. 부분 진입은 포지션이 있으면서 진입 잔량이 미체결인 상태다. 단순히 미체결 주문을 취소했다고 포지션0으로 처리하지 않는다.
- 모든 주문·포지션이 정리됐다고 대조한 뒤 `finish_cycle`로 진행 의도를 닫는다. 취소한 미체결 시도도 fresh-episode 기회를 소비한다. 같은 의도의 조회/잔량 시장가 전환은 기존 복구 경로이며 새 신호 재진입이 아니다.

동일 시각의 동일 완료 봉 재수신은 멱등 처리한다. 동일 시각 상충 입력과 과거 입력은 거부한다. 이 순수 상태를 재시작 때 초기화하면 중복 방지가 사라지므로 실제 연결 시 상태와 outbox를 같은 트랜잭션에 영속화해야 한다. 현재 이 모듈과 SQLite outbox의 원자적 통합은 미완료다.

## 2. 재진입 조건 — 두 규칙을 혼합하지 않기

| 모드 | 다음 진입 조건 |
|---|---|
| CONTINUING_NEXT_DECISION | 포지션0·관련 주문 최종 정리 확인 뒤에 마감된 새 판단 봉에서 기존 방향이 여전히 유효하면 검토 |
| FRESH_EPISODE | 위 조건에 더해 아직 사용하지 않은 신호 구간이어야 함. 같은 방향 지속만으로 재진입 금지 |

두 모드 모두 마지막 종료 확인시각보다 **엄격히 뒤에 가용해진 완료 봉**이 필요하다. 종료 직전 신호를 종료 직후 새 신호로 재활용하지 않는다. 같은 봉 손절→즉시 재진입, 미해결 주문 상태의 반전, 같은 의도의 중복 송신은 허용하지 않는다. 반대 신호도 원 주기 청산/주문 정리 뒤 새 판단을 받아 새 주기로 처리한다.

신호 유효성, 계정 위험, 현재 포지션/미체결 주문, 거래 규격과 비용은 호출자가 최신 자료로 승인해야 한다. 알 수 없는 상태를 True로 대신하지 않는다. 이 모듈의 boolean 입력은 대조 결과를 받는 경계이며 자체 계정 검증을 뜻하지 않는다.

fresh-episode가 더 낫다는 판정은 없다. E006에서 동일 방향 재진입 묶음이 T0에는 양수였으므로 전체 전략에 재진입 금지를 강제하지 않는다.

## 3. 목표 설정 시점과 고정

| 모드 | 목표 원천 | 이후 가격이 변하면 |
|---|---|---|
| EPISODE_START | 신호 구간이 최초 생성될 때의 완료 봉 목표 | 동일 신호 재진입에도 최초 목표 재사용 |
| ENTRY_DECISION | 실제 주문 의도를 계획하는 완료 봉의 목표 | 재진입 의도마다 그 시점 자료로 다시 고정 |

목표는 주문 제출 **이전**에 고정한다. 실제 체결을 본 후 좋은 목표를 사후 선택하지 않는다. target_source_ms와 decision_ms를 보존하며 미래 원천을 거부한다. 완료 봉 채널/평균이 바뀌어도 열린 주기의 목표를 자동으로 멀리 이동하지 않는다.

R0 공급 계약: 목표는 해당 원천 시점 완료1시간봉24개 종가 평균. F0 공급 계약: 해당 원천 시점 직전 완료12시간봉 고저 범위의 중간값. 코드 `Levels`는 숫자와 가용시각을 받으며 지표 공급 어댑터가 이 산식을 검증해야 한다. 미래 봉으로 확정한 pivot은 공급 금지다.

롱은 손절<예상 진입<목표, 숏은 목표<예상 진입<손절이어야 한다. 가격 단위에 맞춰 손절은 진입에서 멀어지는 쪽, 목표는 진입에 가까워지는 쪽으로 반올림한다. 진입 지연/갭으로 목표를 이미 지나쳤으면 신규 주문을 거부한다. 목표/손절을 옮겨 억지로 진입시키지 않는다.

## 4. 익절 감지와 실행을 구분

| 모드 | 감지 | 판단 결과와 체결 의미 |
|---|---|---|
| CLOSE_CONFIRM_MARKET | 해당 전략 판단 봉 종가가 고정 목표 통과 | 봉 완료+명시 지연 이후 청산 예약. 확인한 종가 자체에 소급 체결 금지 |
| TOUCH_MARKET | 계약 거래가격이 고정 목표 접촉 | 시장가 청산 요구. 봉의 목표 가격은 연구용 기준가격이며 실체결 가격 아님 |
| RESTING_LIMIT | 목표 지정가의 체결/상태 | 가격 접촉만으로 체결 확정 금지. OHLC만 있으면 체결 증거 필요 판정 |

R0/F0 신규 계약은1시간봉 종가 확인, 실험용 판단 지연은1분이다. R0의 기존 이동 z=0 출구와 새 고정 목표 출구는 동일하지 않다. C00 계약 기준도 E005 정확한 재현이 아니며 새 실험으로 등록해야 한다.

일반 지정가가 지연되면 사용자 결정대로 취소 확정→누적 체결 재조회→실제 잔량/위험 재승인→시장가 전환한다. 3초는 기존 연구용 기한이다. 목표 주문의 부분 체결은 잔여 포지션까지만 청산하고, 반대 포지션을 만들지 않도록 reduce-only 및 기존 주문 충돌 대조가 필요하다. 가격 접촉과 주문 접수는 체결이 아니다.

## 5. 손절 기준과 실행

| 기준 | 최초 고정선 |
|---|---|
| ATR | 주문 판단 완료 봉 종가∓3×ATR14 |
| STRUCTURE | 롱: 그 시점 이미 알려진 구조 하단−1tick. 숏: 구조 상단+1tick |

구조 공급 계약은 R0의 판단 시점 직전24개 완료1시간봉 고저, F0의 돌파 실패를 정의한12봉 범위다. 해당 원천은 진입 판단 때 가용해야 한다. 공급 어댑터 연결 전 구조 손절 계좌 백테스트 완료로 간주하지 않는다.1tick은 경계 일치 방지를 위한 초기 설정이지 적정 손절 폭으로 검증된 값이 아니다.

ATR3은 기존 비교 기준이다. 어떤 기준도 손실 후 더 멀리 옮기지 않는다. 새 구조가 허용 손실 예산/최소 주문을 만족하지 않으면 건너뛰며, 주문을 맞추려고 손절을 좁히지 않는다. 후행 손절/본전 이동은 이번 계약에 섞지 않는다.

손절 감지는 **계약 거래가격(CONTRACT_PRICE)** 기준이다. 마크가격 청산/유지증거금 위험은 별도의 계정 보호이고 아직 실제 청산 엔진으로 구현하지 않았다. 보호 손절은 일반 지정가3초 대기 대상이 아니다.

첫 부분 체결부터 실제 체결 수량의 보호가 필요하다. 매 누적 체결마다 원래 고정한 손절·목표와 평균 체결가/수량·예약 손실·왕복 비용을 재검사한다. 원래 위험 예산을 넘거나 목표/손절이 잘못된 위치가 되면 미체결 진입 잔량 취소와 긴급 청산을 요구한다. 이미 체결된 물량을 없었던 것으로 처리하지 않는다. 실제 보호 주문 접수/수량 조정 확인은 외부 조정기 책임이다.

## 6. 충돌과 봉 내부 순서

1. 계정 위험 중단은 우선 긴급 청산/대조 요구. 진행 중 익절 주문이 있어도 보호 요구를 숨기지 않는다.
2. 시가가 손절을 넘어 갭을 만들면 손절 가격이 아니라 시가를 연구 기준가격으로 사용한다.
3. 진행 중 청산은 조회·잔량 대조하며 새 주문을 무조건 중복 송신하지 않는다. 손절도 겹치면 긴급 대조로 승격한다.
4. 시가에 이미 시간 만료라면 이후 봉 고저보다 먼저 시가 청산 요구.7일 상한은 첫 실제 체결 시각부터다. 부분 추가 체결로 만료 시각을 연장하지 않는다.
5. 시장가 목표를 시가에 이미 넘은 경우는 이후 극값보다 먼저 시가 목표 청산 요구. 지정가에는 이 체결 가정을 적용하지 않는다.
6. 시가 이후 같은 봉이 손절과 장중 목표를 모두 건드리면 순서 불명 표시+보수적 손절 우선. 실제 거래 순서를 확인한 것으로 표현하지 않는다.
7. 진입 또는 만료가 봉 중간에 있으면 FINER_DATA_REQUIRED. 그 봉의 진입 전 고저를 활용해 익절/손절을 만들지 않는다.
8. 종가 확인은 해당 전략 봉이 실제 완료된 경우만 판정하며 미래 시각 청산 예약을 반환한다.

`evaluate_bar`는 이 OHLC 연구 판단만 한다. 현재 포지션 잔량을 모르므로 매도 수량·거래소 주문을 생성하지 않는다. EXIT_REQUIRED는 조정기에 보내는 요구이지 FILLED가 아니다. 실제 운영에서 가격 스트림이 끊기면 신규 진입 차단·기존 보호 주문 확인·경보로 처리해야 하며, 이 운영 경로는 아직 통합하지 않았다.

## 7. 비교 설정과 다음 실행

계약 기준 하나에서 재진입/목표 시점/익절 감지/손절 기준을 한 번에 하나씩만 바꾸는 설정 파일을 만들었다. 이 설정들은 새 전략6개가 아니다. 전체 조합 최적화나 최고 수익 설정 선택은 하지 않았다. RESTING_LIMIT은 실제 체결 증거가 필요한 별도 경로다.

다음은 지표 공급·계좌/주문 조정기에 이 계약을 연결하고, 고정된 첫 비교의 기간·횟수·검증 기준을 등록하는 것이다. 먼저 E005 재현 경로와 신규 계약 경로를 분리해 바뀐 거래만 대조한다. 목표가 체결을 분봉에서 확정할 수 없는 지정가 경로는 전진 모의 실행 증거로 남긴다. 새 규칙의 수익률은 아직 없다.
