# 동일 연결의 저장 세대 압축·정리 통합 v1

2026-09-18. 동일 연결/processor를 유지하는 기록 전환에 **닫힌 세대의 비동기 압축, 원본/압축 감사 비교, 복구 기록, 원본 정리**를 연결했다. 다음 저장 세대의 수집은 계속 진행한다. 기존 소스와 이전 시험 결과를 수정하지 않으며, 이 문서와 별도 opt-in 실행기가 새 경로다.

## 고정된 범위와 시험

정상40초, public100ms당20프레임, 방향별1000레벨, 8초 세대 전환/0.5초 봉인으로 먼저 시험한다. 별도 높은 입력량 시험은18초, 같은 나머지 설정에100ms당200프레임이다. 결과를 보고 봉인 주기나 대기열 한도를 늘리지 않는다. 정상 시험은62봉인 단위 초과, 같은 연결2개·최초 snapshot1개, 전역 순번 보존, gzip 전용 재생, 기존 전체 재생기와17항목 일치가 필수다. 높은 입력량 시험의 중단은 안정적인 정상 운용 성공과 구분한다.

작업 실패/시간 초과/부모 저장 지연/공용 공간 부족/취소를 별도로 시험한다. 압축 등록 rename, 보관 등록 rename, 삭제 의도 임시 저장, 실제 unlink 직후, 완료 임시 저장, 완료 디렉터리 fsync 뒤6곳에서 실제 부모 SIGKILL과 별도 프로세스 복구·재복구를 수행한다. 복구 시 원래 창, raw/gzip 명시적 선택, 미확정 꼬리 및 임시 파일을 보존한다.

근거: [최종 검증 도구와 소스 고정](../../reports/validation/archived_generation_20260918/qualification_plan_v4.json), [정상/높은 입력량/강제 종료 결과](../../reports/validation/archived_generation_20260918/qualified/summary.json), [최종 검증](../../reports/validation/archived_generation_20260918/verification.json). 최초40초 수집의 생산 코드는 최초 계획과 동일하다. v2~v4는 아래에 설명한 보고서 계산/저장 자료 비교 수정이며40초를 다시 수집하지 않았다.

두 실행 모두 예정 시각에 수집을 종료하고 drain을 완료했다. dequeue된 프레임 수와 저장된 원본 수가 일치하며 gzip만으로 재생한 결과가 기존 전체 재생기의17항목과 같다. 실제 SIGKILL6곳은 각각 별도 프로세스 복구와 재복구에서 파일 증가·수정0이다. 앞 세대 gzip과 중단된 다음 세대 raw를 함께 읽는 경우도 확인했다. 종료 시 producer 큐 잔량은 별도로 기록하며 시장 전체 무손실로 확대하지 않는다.

품질 판정은 두 사례 모두 `QUALITY_INPUTS_REJECTED / NOT_REGISTERED_PILOT_DURATION`이다. 합성18/40초를 등록된24시간 자료로 바꾸지 않는다. 높은 입력량에서 pending2개 상한까지 도달했으므로 긴 수집의 처리 여유를 입증한 것도 아니다.

최종 고유1,087개 검사(기존1,062+신규25, 연구424/실행663)는 실패·오류·건너뜀0이다. 과거17,581건 hash 대조/17,312개 고유 경로 불일치0이며 기존 사용자·관측 자료는 변경하지 않았다. 신규 검사에서 작업자 실패·시간 초과·저장 지연·예산 부족·취소·경제성 거부·손상 archive의 raw 우회 금지·과거 자료 opt-in 금지를 다뤘다. 개발 실패와 보고서 수정 이력은 별도로 보존하며 최종 회귀 통과와 혼동하지 않는다.

## 실행 경로

1. [archived_generation_capture.py](../../app/research/data/archived_generation_capture.py)는 기존 전역 순번·seed·handoff 코드를 상속하고, `end.json`으로 닫힌 세대만 작업자에게 넘긴다. 정리 정책은 처음부터 opt-in한 새 capture에만 생성하며 과거 자료에는 소급하지 않는다. 합성 전송만 허용하고 공개/주문 연결은 만들지 않는다.
2. [generation_archive_pipeline.py](../../app/research/data/generation_archive_pipeline.py)는 전체 pending 세대2개, 공용 예약2개를 상한으로 둔다. raw/audit 각각 세대당 최대64개 압축 작업, 세대당62개 봉인 단위, 전체16세대/120초 한도를 유지한다. 각 작업과 세대 전체 처리/마지막 drain은15초 상한이다. overflow는 자료를 버리지 않고 실패한다.
3. 압축은 기존 parent-bound 작업자를 사용한다. 자식은 원본만 읽으며 부모가 응답 gzip을 직접 풀어 길이/hash를 검증한 뒤 파일과 descriptor를 저장한다. 부모만 파일을 쓴다.
4. [generation_audit_worker.py](../../app/research/data/generation_audit_worker.py)는 별도 프로세스에서 원본 및 candidate gzip으로 각각 재생한다. 전체 processor/reducer seed hash가 원래 세대 끝과 같고17개 감사 의미가 같아야 정리를 허용한다. 부모 소멸/15초 수명,50ms 표본 방식의384MiB RSS guard를 적용하며 OS 강제 메모리 한도로 표현하지 않는다. 감사 응답8MiB도 공용 예산에서 사전 예약한다.
5. 실제 gzip·descriptor·candidate·감사 증명·보관 등록·의도/완료 기록·정책 비용까지 계산한다. 양의 절감이 없으면 원본을 지우지 않고 거부 기록을 남긴다. 이 경우 시험 중 만든 압축/진단 파일은 보존되므로 전체 저장량이 증가할 수 있다.
6. `retention.json`→`retire-intent.json`을 fsync한 뒤 각 원본의 길이/hash와 압축본을 다시 검사한다. unlink→원본 디렉터리 fsync→마지막 `retire-done.json`을 기록한다. 한 파일 처리 후 yield하여 수신 작업이 실행될 수 있게 한다. 동기 부모 단계500ms를 넘으면 실패한다.

## 복구와 무결성

[generation_archive_custody.py](../../app/research/data/generation_archive_custody.py)가 각 세대의 source 선택을 담당하고, [read_archived_generation_capture.py](../../app/research/data/read_archived_generation_capture.py)가 원래 raw reader를 별도 버전으로 확장한다. 구형 reader를 monkeypatch하거나 seal 크기/hash/0시작 규칙을 완화하지 않는다.

- 외부 plan/policy hash, 구현 hash, 세대 end·checkpoint·seal·proof·candidate를 대조한다. 보관 등록이 있는 소스는 gzip을 명시적으로 읽고, gzip이 잘못돼도 남은 raw로 조용히 우회하지 않는다.
- 삭제된 원본에는 일치하는 의도 기록이 필요하다. 의도 없는 삭제, 바뀐 봉인 파일, 바뀐 감사 증명, 다른 세대/경로의 참조는 거부한다.
- 완료 기록이 유실됐어도 원래 등록·의도·압축본이 유효하면 자료를 읽을 수 있다. **복구 reader는 파일을 바꾸거나 미완료 삭제/작업을 자동으로 재개하지 않는다.** 중단 후 시장 상태를 살리거나 종료 시각을 연장하지 않는다.
- 기존 metadata/checkpoint/seed/unit/end/handoff는 보존한다. 이번 삭제 대상은 새 합성 capture에서 감사가 완료된 raw/audit segment뿐이다.
- 작업자 실패가 공용 예산을 먼저 실패시켜도 세부 원인이 결과에 남도록 전달 경로를 보완했다. 취소/실패 시 자식 회수와 예약 해제를 확인한다.

## 비용 집계의 정의

실제 capture 전체 파일 바이트는 공용 예산과 별도 inventory를 비교한다. 원본 삭제 바이트와 전체 저장 감소량은 별개다. 파일시스템의 물리 회수량으로 표현하지 않는다. 압축본과 원본이 함께 존재하는 동안의 peak, 아직 쓰지 않은 작업 예약을 포함한 effective peak도 보고한다.

동일 실행의 세대별 비교는 `end` 시점의 기록 크기에 일반 handoff 파일을 더한 원본 보존 기준과, 압축/증명/보관 metadata를 모두 포함한 완료 크기를 비교한다. 첫40초 검증에서 end 이후 생기는 일반 handoff205바이트/세대를 비교식에서 빠뜨려 보고서 assertion이 실패했다. 저장 자료를 다시 읽을 때 tuple/list 표현 차이가 감사 제외 구간과 파일 inventory 비교에도 남아 있어 canonical JSON으로 통일했다. 생산 코드나 실험 설정을 변경하지 않고 **동일40초 자료**로 계산을 바로잡았다. 실패 로그와 이전 script snapshot을 모두 보존하며 최종 v4 보고서 소스 고정으로 구분한다.

기존 raw-only 시험과는 실제 받은 프레임/시간이 다르므로 두 실행의 최종 바이트를 직접 수익처럼 비교하지 않는다. 별도 reference 재구성과 검증 보고서의 저장량은 capture 밖 시험 비용이다.

## 남은 종료 조건

이번 경로는 유한 세대 안의 압축·정리 통합이다. **현재 감사 작업자는 각 닫힌 prefix를 처음부터 재생한다.** 세대가 계속 늘면 누적 계산량이 커지며 공용 예산의 파일 목록도 커진다.16세대 상한을 장기 이력 처리 해결로 주장하지 않는다. 다음 필수 항목은 검증된 이전 감사 상태에서 이어가는 제한된 작업량의 인계 및 이력/전체 용량 계약이다. 과거 증거의 full cold replay는 독립 검증 경로로 유지한다.

그 조건과 고정 부하 시험을 충족한 뒤 짧은 공개 수집 확인을 등록하고, 공개 증거와 용량에 따라 더 긴 기술 시험을 판단한다. 이후 체결/시장가 전환 비용과 고정 후보 비교·전진 모의 검증으로 돌아간다. 새로운 매매 모델 채택·수익성 개선·24시간 운용을 이번 구현 결과로 주장하지 않는다.
