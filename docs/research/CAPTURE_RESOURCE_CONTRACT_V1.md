# 장기 수집 자원 계약 v1

2026-09-18. 범위는 선택한 합성 세대 경로의 장기 자원 심사다. 전략·수익성·실운용 승인이 아니다. 기존 수집 코드와 source binding, 120초/16세대 한도, 64 GiB 논리 예산과 16 GiB 여유 공간 기준은 보존했다.

## 이번에 구현한 것

- `app/research/foundation/capture_resource_contract.py`: 엄격한 정수/필드 검증과 조건부 자원 계산. 미확정은 `null`이며 0·무제한·통과로 바꾸지 않는다.
- `configs/research/capture_resources_v1.json`: 24시간/8초 세대/0.5초 봉인의 공개 수집 요청. 검증되지 않은 입력 상한과 정하지 않은 자원 예산을 명시적으로 비워 둔다.
- `scripts/review_capture_resources.py`: 수집기를 호출하지 않는 읽기 전용 사전 심사 명령. 현재 v1은 실행 자격을 발급할 수 없으며 차단 결과와 종료 코드 2를 반환한다. 기존 수집 진입점에 연결된 운영 게이트가 아니다.
- `scripts/verify_capture_resources.py`: 고정된 정상40초/고입력18초 자료에서 실제 `SharedStorageBudget.reconcile()`와 원점 전체 재생을 별도 프로세스로 측정한다. 관측/주문/과거 자료 삭제는 없다.

## 계산 범위와 실패 조건

전체 세대 수는 기간/전환 간격을 올림한다. 각 세대의 단위 수는 길이/봉인 간격을 올림하고 시작·종료 여유 2개를 더한 보수적 예산이다. 실제 생성 파일 수의 예측값으로 부르지 않는다.

논리 저장 예산에는 고정 파일, 모든 세대의 raw와 archive, seed, 세대 및 단위 metadata, 동시에 필요한 임시/예약 공간, 실패 꼬리를 포함한다. 보관 전환 비용 심사가 원본 정리를 거부할 수 있으므로 원본 조기 삭제에 따른 공간 이득을 미리 주지 않는다. 각 입력은 겹치지 않는 전체 비용을 포함해야 하며, 별도 검증용 원본 사본은 capture 예산 밖의 디스크 비용으로 더한다.

이미 존재하는 capture 바이트는 논리 예산에 더하지만 현재 디스크 사용량에 재차 더하지 않는다. 디스크 여유는 16 GiB와 기존 검사 여유 65,536바이트를 차감한다. 모든 바이트 계산은 논리 길이이며 APFS 할당량·snapshot·배타적 회수 공간을 보장하지 않는다. 운영 게이트로 연결하기 전에 실제 할당량과 동시 외부 사용량도 다뤄야 한다.

파일 수와 부모 목록 메모리를 별도 예산으로 다룬다. `reconcile()`는 새 사전을 만든 뒤 교체하므로 기존 목록과 새 목록이 동시에 존재하는 비용을 포함한다. Python 객체 추정량만으로 RSS를 보장할 수 없으며 기타 부모 메모리·작업자 전체·allocator/순회 임시 비용이 추가로 필요하다. 원점 복구는 전체 기록 수, 고정 시작 비용과 세대별 비용, 최대 RSS를 분리한다. 체크포인트를 이유로 과거 손상 검사를 생략하지 않는다.

500ms 부모 동기 작업 한도 초과와 pending 세대 2개 상한 도달을 별도로 보고한다. 입력률·메시지 크기·책 상태/구간 목록 성장·작업자 지연 등이 실제 제한되고 장기 부하로 검증되기 전에는, 숫자가 모두 채워지고 조건부 공간 계산을 통과해도 실행을 승인하지 않는다. `QUALIFIED` 문자열만 넣어 승인 상태를 만들 수 없다.

## 현재 심사 결과

24시간 요청은 **10,800세대**, 보수적 단위 예산 **194,400개**를 요구한다. 구현의 120초/16세대 제한을 넘고, 선택된 세대 경로에는 공개 transport가 연결되지 않았다. 자원 상한·일부 예산 역시 미확정이다. 따라서 **RESOURCE_PREFLIGHT_BLOCKED**다. 194,400은 하루 실측이나 파일 수가 아니다.

실행 예:

```sh
.venv/bin/python scripts/review_capture_resources.py
```

짧은 샘플의 평균 바이트/초·파일/초·복구 속도를 하루로 외삽해 빈 상한을 채우지 않는다. 현재 남은 공간이 충분한지에 대한 하루 판정은 미확정이다.

각 시나리오·종류당 측정 프로세스 1회이며 반복 중 최솟값 선택은 없다. 목록 시간은 tracemalloc을 끈 상태, 할당은 별도 추적 구간이다. 추적 할당은 정확한 객체 그래프 크기나 전체 프로세스 RSS가 아니다. RSS는 import와 측정 전 단계도 포함한 OS high-water다. 복구는 새 프로세스에서 처음부터 수행했지만 파일 hash 확인으로 OS 캐시가 데워졌을 수 있다. 전원 복구 후 느린 디스크나 장기 자료의 복구 시간을 인증하지 않는다.

이전 전체 회귀 1,238개는 재실행하지 않았다. 이번 관련 **59개(신규22·기존37)**는 등록 후 모두 통과했고 실패·오류·건너뜀0이다. 기존 증거 2,529파일을 전후 대조했고 불일치0, 원본 capture 변경0이다.

첫 시도에서는 54개 검사는 통과했지만 측정 도구의 JSON 비교가 실패했다. 재생 중 interval tuple과 저장한 JSON array를 Python 값으로 직접 비교한 도구 오류였다. 기존 검증처럼 정규 직렬화로 비교하도록 고쳤고, 실제 값 변경·bool/정수 차이·미완료 복구를 거부하는 검사도 추가했다. 첫 소스 snapshot과 오류/진단을 보존하고 `qualified_v2`에 새 등록·측정을 남겼다. 수집/복구 구현이나 기준값은 바꾸지 않았다.

## 다음 순서와 종료 조건

1. **장기 이력 처리 구조를 제한한다.** 활성/미완료 파일 목록과 완료된 불변 세대의 저장 회계를 분리하고, 완료 이력 인덱스는 제한된 페이지로 읽는다. 파일/바이트 상한, 실패 꼬리, unknown 파일, 외부 변경, hash 연결, 원점 검증을 보존해야 한다. 사전 심사만 추가하고 운영 구조가 개선됐다고 주장하지 않는다.
2. **고정된 이력 크기와 입력/지연으로 자원 한도를 검증한다.** 정상뿐 아니라 최대 책 상태·파편화 구간·대기열·원본 보존 실패 조건, 전체 프로세스 RSS, 재시작 비용을 측정한다. 미확정 예산을 근거 없이 먼저 통과값으로 정하지 않는다.
3. **실제 실행 전 게이트와 공개 경로를 연결한다.** 출처가 고정된 적격 자료를 검증하고 저장/연결 전에 거부하도록 통합한 뒤, 짧은 공개 확인과 24시간 사전 등록을 판단한다.
4. 그 범위를 끝내면 체결·지연 주문의 시장가 전환 비용, 고정 후보 전진 모의로 돌아간다. 현재 단계는 수익 모델 개선 성과가 아니다.
