# 대기 축소 주문과 추가·한도 대응의 조정

`CyclingCoordinatedEngine`에서 대기 지정가를 취소·대사한 뒤 새 판단으로 넘어가는 경로를 연결했다. 기존 단일 활성 주문 제약을 유지하면서, 대기 주문 때문에 이후 판단을 무조건 막던 문제를 일부 해소한다. 연구용이며 거래소 연결이나 자동 주된 방향 판정은 아니다.

## 처리 순서

1. 대기 지정가가 있을 때 유효한 주된 방향 아래 새 실행 구간 반응이 나타나거나, 국소 추가 근거 실패와 최신 한도 초과가 함께 발생하면 취소를 요청한다. 추가 쪽은 후보 단계이며 비용·수량 심사 통과를 뜻하지 않는다.
2. 취소 요청만으로 잔량이나 여력을 되돌리지 않는다. 늦은 체결을 장부에 반영하고 누적 체결량이 맞는 취소 확인을 기다린다.
3. 대사가 끝나면 이전 축소 의도를 `superseded_not_assumed_filled`로 기록한다. 미체결을 체결로 간주하지 않는다. 미완료 계획의 재설정 필요 여부를 별도 `replan_required`로 남긴다.
4. 추가 목적이면 대사 봉에서 바로 주문하지 않는다. 이후 새 반응에서 최신 수량·한도·비용을 다시 심사한다. 취소를 유발했던 옛 신호를 재사용하지 않는다.
5. 한도 대응이면 실제 잔량과 현재 한도로 필요한 부분 축소량을 다시 계산한다. 늦은 체결로 한도 문제가 이미 해소됐다면 추가 축소를 강제하지 않는다.
6. 다음 축소 계획을 명시적으로 만들 때는 현재 총수량의 절반을 사용하고 새 계획 버전을 부여한다. 같은 증가 주기에서 재계획해도 과거 미완료 목표와 혼동하지 않는다.

사용자가 명시적으로 계획을 일시 중단한 상태는 자동 조정보다 우선한다. 주된 추세 전환의 취소·대사·종료 경로도 기존 우선순위를 유지한다.

## 검증한 수량 예시

- 6 보유, 3 축소 지정가 대기 → 취소 중 1 체결 → 대사 후 실제 5.
- 이후 새 반응·심사를 통과해 2 추가 체결 → 총 7 → 명시적으로 새로 계획한 절반 축소는 3.5.
- 같은 초기 6에서 한도 4 초과 대응 → 취소 중 1 체결 → 실제 5이므로 필요한 부분 축소는 1.
- 취소 중 원래 3이 모두 체결되어 잔량이 3이면, 한도 4를 맞추기 위한 추가 축소는 없다.
- 대사 뒤 최대 수량 한도가 이미 꽉 찼다면 새 접촉이 생겨도 추가 주문을 내지 않는다.

이 사례는 합성 입력이다. 실제 BTC 수량 추천이나 계좌 한도 제안이 아니다.

## 실제 자료와 검증 범위

기존 48시간·주된 방향 미확정·가상 롱 0.1의 경로도 새 엔진으로 재생했다. 새 추가 근거가 승인되지 않으므로 조정 요청을 억지로 발생시키지 않았다. 결과는 이전처럼 사전 축소 0.05 체결, 잔량 0.05였고 미래 자료 제거 불변성과 독립 장부 대조를 통과했다. 따라서 실제 시장에서 조정 판단의 수익성이 입증됐다고 해석하지 않는다.

신규 조정 검사 7개를 포함한 cycling 97개, 장부 9개 통과. 합성 기록에는 주문·체결·장부 사건과 최종 잔량을 보존했다.

## 남은 범위

이전 축소 계획이 취소됐다고 무조건 같은 가격에 새 계획을 재설정하지 않는다. **새 추가가 거절되거나 신호가 사라졌을 때, 어떤 유효한 자리로 축소 계획을 복원할지의 자동 판단은 아직 없다.** 현재는 재계획 필요 상태와 명시적인 계획 API를 제공한다. 다음은 그 복원 정책과 부분 추가 체결 후 계획 갱신을 연결하는 것이다. 전체 통합 엔진 상태 저장·재시작, 실제 계좌 대사, 자동 주된 방향 판단도 미완성이다.
