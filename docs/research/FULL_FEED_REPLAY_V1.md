# 하루 분량 전체 파일 재생·중복 검증 축소·다음 병목

2026-09-18. [검증 기록](../../reports/validation/full_feed_replay_20260918/verification.json), [다음 단계 판정](../../reports/validation/full_feed_replay_20260918/readiness.json).

## 결론

**하루를 나타내는 합성 원본3,110,408개와 감사1,728,001개, 약3.34GiB의 실제 파일을 끝까지 검증·재생했다.** 해시/순번/연결 상태/호가/관찰/적격 구간 대조를185.67초, 프로세스 최대 RSS28.63MiB로 완료했다. 이전의 구간 집계만 시험한 단계에서 전체 파일 시험으로 진행했다.

새 읽기 경로는 확정 부분 전체를 검증한 뒤에만 재생을 허용하며, 검증 중 잠금을 유지해 중복 전체 순회를 줄인다.1시간 합성 파일에서는 기존12.19초→새7.73초였다. 기존 공개 자료8개 epoch, 원본13,297개/감사1,349개의 결과도 모두 일치했다.

**24시간 실제 운용은 아직 승인하지 않는다.** 이번 파일은 작은 고정 호가와 일정 입력률의 합성 자료다. 현재 수집기는 재연결 전에 종료된 epoch의 전체 감사 재생을 동기 실행한다. 긴 epoch에서는 이 시간이 재연결 공백을 늘린다. 이 구조와 저장 여유가 다음 우선순위다.

## 구현 범위

- [잠금 유지 검증 뷰](../../app/research/data/verified_journal_view.py): 동결된 `load_state`/`scan_records` 검사기를 사용한다. 첫 레코드를 반환하기 전에 전체 확정 부분과 마지막 체크포인트 일치를 검증한다. 이후 동일 잠금 안에서 재생한다. 미확정 꼬리/임시 체크포인트도 기존 방식대로 보고한다.
- [전체 감사 재생기](../../app/research/data/snapshot_feed_audit.py): 기존 관찰 대조·만료·원래 시간창·최종 관찰 이후 추정 금지·구간 예산을 유지한다. 기존 감사 결과 필드와 같은 구조를 반환한다.
- [합성 파일 생성기](../../app/research/data/synthetic_feed_fixture.py): 고정 시계·가격·입력 프로필을 실제 분할 파일 형식으로 작성한다. 기존 파일은 덮어쓰지 않는다.
- [단계별 측정](../../scripts/measure_full_feed_replay.py), [제약 판정](../../scripts/report_full_replay_readiness.py), [검사](../../tests/test_full_feed_replay.py).

기존 감사기는 원본 레코드를3번, 감사 레코드를5번 전체 검증/순회했다. 새 경로는 각각2번으로 줄인다. 각 `scan_records` 내부에는 별도의 파일 해시 읽기도 있으므로, 이를 물리적으로 파일을 정확히2번만 읽는다고 표현하지 않는다. 전체 선검증을 생략하거나 일부만 확인하는 최적화가 아니다.

두 번의 읽기는 협조적 잠금을 사용하는 한 소유자의 로컬 파일 계약 안에서 진행한다. 다른 프로세스가 잠금을 무시하고 파일을 바꾸는 경우까지 지원하지 않는다. 끝부분 손상, 최종 체크포인트 순번 불일치, 심볼릭 링크, 조기 종료 시 잠금 해제, 잘못된 관찰, 감사 유실, 구간 예산 초과도 검사했다.

**새 재생기는 이번에 오프라인에서 검증했으며 실시간 수집 경로에는 아직 연결하지 않았다.** 현재 최대120초의 공개 수집기는 이전 v4다. 다음 변경에서는 재연결을 막는 감사 실행 순서를 함께 개선해야 한다.

## 먼저 고정한 시험 조건

[측정 계획](../../reports/validation/full_feed_replay_20260918/measurements/plan.json).

10분→1시간→하루 순서로 확장했다. 각 worker의 시간 상한600초, 진단 RSS 상한384MiB, 합성 파일 전체 한도6GiB, 물리 여유 보존 기준16GiB를 먼저 고정했다. 다음 단계는 앞 단계의 검증이 성공해야 진행했다. 각 worker는 새 Python 프로세스이며 OS 파일 캐시는 비우지 않았다.

합성 입력은 bookTicker20Hz, depth10Hz, mark1Hz, aggTrade1Hz, watchdog4Hz, 감사20Hz다. 호가는4개 가격 수준이며 가격/수량은 고정되고 업데이트 ID와 시각은 전진한다. 일반 구간 원본36개/초이며 시작·종료 레코드는 별도다. 실제 거래소의 순간 폭주·많은 호가 수준·대형 snapshot·상관된 장애를 대표하지 않는다.

파일의 `committed_ns`와 관찰 시각은 **합성 시계**다. 생성기는 버퍼를 사용하고 파일 전환/마지막에 물리적으로 동기화한다. 따라서 생성 시간은 실제 수집기의50ms 간격 commit 지연이나24시간 fsync 내구성 증거가 아니다. 완성된 파일은 실제 생산용 형식/검증기로 읽었다. 생성된 관찰과 재생 관찰의 일치 외에도 원본 수 `36×초+8`, 감사 수 `20×초+1`, 정상 합성 입력의 전체 시간창 구간을 독립적인 기대값으로 확인했다.

RSS는 인터프리터를 포함한 프로세스 메모리다. OS의 파일 캐시와 시스템 전체 메모리 사용량을 나타내지 않는다. 캐시를 통제하지 않았으므로 차가운 디스크 캐시의 성능이나 다른 기기의 처리 시간을 확정하지 않는다. 하루 합성 파일이 실제60초 관측의 하루 환산10.21GiB보다 작다는 점도 유지한다.

## 큰 합성 파일 보관 정책

계획에 따라10분 파일은 남겼고,1시간/하루 파일은 검증 성공 후 각 파일의 크기·SHA256·재현 계획을 저장한 다음 이번 생성기가 새로 만든 디렉터리만 삭제했다. 실패한 파일은 자동 정리하지 않는 정책이다. 사용자 원본 ZIP·기존 실험·공개 수집 파일은 삭제하지 않았다.

[1시간 manifest](../../reports/validation/full_feed_replay_20260918/measurements/synthetic-3600s/fixture_manifest.json), [하루 manifest](../../reports/validation/full_feed_replay_20260918/measurements/synthetic-86400s/fixture_manifest.json). 큰 파일 자체는 현재 남아 있지 않다. 생성 코드/매개변수/해시로 재생성할 수 있으며 작은 fixture의 바이트 단위 결정성도 검사했다. 실제 여유 공간 반환 시각은 파일 삭제 완료와 같다고 가정하지 않고 별도 측정했다.

## 새로 확인한 운영 병목과 순서

1. **재연결 경로에서 긴 감사 작업을 분리한다.** 현재 [v4 수집기](../../app/research/data/compact_feed_collector.py)는 `collect_epoch → 동기 audit_epoch → 재시도 판단/대기 → 새 epoch` 순서다. 이번1시간 합성 자료는 현재 감사기로12.19초가 걸렸으며, 정책의 최대 비가용 구간10초보다 길다. 실제1시간 시장 세션의 재연결을 측정한 결과는 아니지만, 긴 감사가 재연결을 막는 설계 위험은 확인했다. 단순히 빠른 감사기로 교체하는 것만으로 임의 길이의 중단 문제를 해결하지 않는다. 감사 작업 수·메모리·종료 대기를 제한하고, 감사 실패가 전체 실행을 거부하게 하면서 재연결을 막지 않는 구조가 필요하다.
2. **저장 여유와 입력률 상한을 확인한다.** 이번 정리 후 측정에서16GiB를 남긴 공간은15.20GiB였다. 이전60초 관측률의2배 가정은 하루20.43GiB이므로 약5.22GiB 부족하다. 이2배는 진단 시나리오이고 검증된 최대 입력률이 아니다.6GiB짜리 합성 시험 예산을 실제 시장 하루 저장 예산으로 대체하지 않는다.
3. **확장 시험의 입력과 저장 지연을 검증한다.** 더 큰 호가 장부·메시지·버스트, 실제50ms commit, 재연결 중 감사 병행과 종료/용량 실패를 확인한 뒤 시험 기간을 늘린다. 현재120초 제한과 미등록24시간 계약은 유지한다.

## 검증 상태

신규20개를 포함한 관련 고유 **578개 검사**(연구424+실행기/저장/재생154), 기존 증거 **1,860건·고유1,591경로** 해시 대조가 통과했다. 초기18개와 단독20개 실행을 최종 합계에 중복 가산하지 않았다. 기존 동결 소스·계약·산출물은 보존했다.
