# 역행·추가·회복 판단 엔진 v0.1

상태: 연구용 이벤트 엔진 구현 및 합성 시나리오 검증. 실제 시장 수익성 또는 거래소 실행 검증과 구별한다.

## 검증 결과

새 엔진 테스트 68개와 기존 E056/E057 회귀 테스트 18개, 총 86개가 통과했다. 기본 CLI의 15개 합성 시나리오에서 41개 체결행을 검산했다. 원본 JSONL 재생의 최종 상태가 저장 결과와 일치하고, 체크포인트 복원 후에는 재시작 잠금이 걸리는 것도 확인했다.

[최종 시나리오 결과](../../reports/validation/recovery_controller_v01_20260919_verified/verification.json) · [테스트·재생 검증](../../reports/validation/recovery_controller_v01_20260919_verified/verification_addendum.json) · [새 엔진 JUnit 결과](../../reports/validation/recovery_controller_v01_20260919_verified/unit-tests.xml).

대표 잔여 종료 경로는 `4 → 54.95 → 4 → 2.94 → 0`으로 진행했다. 이는 설명용 합성 계약 수량이며 BTC 권장 수량이 아니다. 회복 후 추가분 정리, 위험에 맞춘 기존분 축소, 재차 저항 거절 때 잔여 전량 종료를 각각 다른 체결로 확인했다. [해당 체결 원장](../../reports/validation/recovery_controller_v01_20260919_verified/residual_final_exit/ledger.jsonl).

수치 미조정 원칙을 유지했다. 테스트용 최초 진입이 명세의 손익비를 충족하지 않아 거절된 초기 fixture는 유효한 합성 진입으로 수정했으며, 이를 시장 성과 개선으로 취급하지 않는다. 최종 결과의 소스·설정 해시를 저장했다. 기존 회귀 테스트는 로컬 `.venv`에 numpy가 없어 번들 Python의 기존 numpy/pandas 환경으로 실행했고 18개 모두 통과했다.

## 구현 목적

[판단 명세](ADVERSE_POSITION_RECOVERY_SPEC_2026_09_19.md)를 주문 의도, 실제 체결, 포지션 잔여량으로 연결했다. 이전 E057의 최소 물량 강제 보유를 사용하지 않는다. 기존 평균가 장부만으로는 추가분의 개별 근거 실패를 표현하기 어려워 독립 연구 모듈로 구현했다. 기존 E056/E057 코드·설정과 실거래 경로는 변경하지 않는다.

## 결정된 동작

- 반응 확인 추가가 기본이고, `no_add`는 추가 없는 대조, `planned`는 최초 주문 전 지정가 분할 비교 모드다. 수익 중 추가의 별도 전략을 임의로 넣지 않는다.
- 관찰 직전 완료 3분봉으로 ATR을 고정한다. TR14에 필요한 이전 종가까지 확보하기 위해 완료 3분봉 15개가 필요하다.
- 관찰 만료와 확인이 같은 시각이면 만료가 우선한다. 따라서 5번째 3분봉 종료 시 회복 관찰은 만료하며, 회복 시각에서 정확히 9분인 봉·호가도 추가를 발동하지 않는다.
- 구간은 해당 1분봉 시작 전에 알려져 있어야 한다. 구간이 봉 중간에 생성됐는데 그 봉의 과거 저가를 사후 접촉 근거로 쓰지 않는다.
- 유지 확인 봉 종가에는 체결하지 않는다. 이후 호가에서 경제성·수량을 다시 판단하고 주문 의도를 만든다. 실제 수량은 별도의 체결 이벤트로만 바뀐다.
- 사전 분할은 총 위험·총수량을 처음부터 예약하고, 명시한 구간·틱 안의 지정가와 만료 시각을 요구한다. 손절 침범·근거 실패·실행 불명·만료 때 미체결을 취소 요청한다.
- 추가 이벤트는 실제 일부 체결부터 횟수에 포함한다. 부분 체결 여러 건을 여러 추가로 세지 않으며, 취소·축소로 이미 사용한 횟수나 손실 예산을 초기화하지 않는다.
- 국소 추가 근거 실패는 추가분에 귀속된 물량을 종료한다. 전체 근거나 공통 보호 종료가 실패하면 전체 물량을 종료한다.
- 저항 거절·둔화 시 추가분을 먼저 정리하고 실제 체결 비용 반영 후 잔여량을 계산한다. 추가분 취소·청산이 미확정인 동안 다음 잔여 목표 수량을 확정하지 않는다.
- 잔여 물량은 보호 종료가·남은 위험으로 계산하고, 다시 목표에서 거절·둔화가 발생하면 끝낸다. 최소량을 강제로 남기지 않는다.
- 시장의 큰 흐름은 `market_view`로 별도 기록한다. 보유 방향은 독립 진입 계획에 속하며 큰 상승 판단이 롱 보유를 강제하지 않는다.
- 이미 끝난 거래의 진입 계획을 새 ID로만 바꿔 재사용하지 못하도록 종료 이후 생성된 새 진입 근거 시각을 요구한다.

## 회계·복구 계약

실현 손익과 손실 예산은 다른 장부다. 실현 손실·지불 비용·잔여 물량의 예상 종료 손실·미체결 위험을 합쳐 예산을 검사하고, 이익이나 펀딩 수취로 예산을 다시 채우지 않는다. 현금은 `시작 현금 + 실현 가격 손익 - 순비용`으로 매 체결·펀딩마다 검산한다.

잔여 포지션 본절은 잔여분에 배분된 진입비·펀딩을 사용한다. 전체 회복 가격은 누적 실현 순손익을 포함한다. 두 가격은 예상 슬리피지와 종료 수수료를 고려한 실행 전 호가 기준 추정값이다. 실제 틱 반올림·체결 결과는 원장의 체결 가격으로 처리하며 본절 추정값을 실제 체결 보장 가격으로 쓰지 않는다. 포지션이 없으면 가격은 null이다.

같은 구간의 연속 추가 거래 손실은 실제 종료 체결 후 판정한다. 체결되지 않은 손절 의도만으로 손실 횟수를 올리지 않는다. 두 번의 손실 뒤에는 해당 구간 및 이름만 바꾼 겹치는 구간을 잠근다. 같은 구간의 새로운 버전과 잠금 이후 완료 15분봉의 구조 증거가 있어야 해제한다.

재시작, 지연·누락, 취소 중 체결, 포지션 불일치에는 증가 주문을 잠근다. 재개에는 실제 수량, 주문 상태, 잔고, 보호 주문, 근거의 일치가 필요하다. 자료 장애가 있었다면 연속 3개 정상 1분봉과 누락 복구도 요구한다. 계좌 중단은 일반 대사로 해제하지 않는다.

체크포인트는 설정에 묶인 JSON 이벤트와 상태 체크섬이다. 복원 시 이벤트를 다시 계산해 상태 일치를 검사한 뒤 재시작 잠금을 건다. 실제 주문을 재전송하지 않는다. 거래소 수량이 내부 장부와 다르면 실제 수량에 따른 정리 필요량을 출력하며 원가를 만들어 넣지 않는다. 원인 체결을 복구하거나 외부 조치를 거쳐 다시 대사해야 한다.

## 실행

저장소 루트에서 새 출력 경로를 지정한다. 기존 결과를 덮어쓰지 않는다.

```bash
.venv/bin/python scripts/run_recovery_replay.py --output /tmp/recovery-v01-scenarios
```

생성된 각 시나리오 폴더에는 입력 이벤트, 판단 이유, 체결·펀딩 원장, 최종 상태와 체크포인트가 있다. 같은 입력을 재생하려면:

```bash
.venv/bin/python scripts/run_recovery_replay.py \
  --events /tmp/recovery-v01-scenarios/adverse_add_recovery_reduce/events.jsonl \
  --output /tmp/recovery-v01-replayed
```

오프라인 체크포인트 이후 이벤트만 별도 JSONL로 제공하면 `--resume <checkpoint.json> --restart-ms <수신시각>`으로 복구 경로를 실행할 수 있다. 후속 이벤트는 재시작 시각 이후여야 한다.

## 입력 형식

모든 이벤트는 수신·판단 시각 순서로 공급한다. 숫자 가격·수량·비용은 문자열로 보내면 소수점 정밀도를 보존한다. 상태 플래그에는 JSON true/false만 허용한다.

| type | 주요 필드 |
|---|---|
| `start` | `plan`과 `quote`; 계획은 ID·방향·생성시각·지지/저항·보호 종료가·초기 수량·독립 근거, 분할이 있으면 만료 포함 |
| `bar` | `end_ms`, `received_ms`, `open/high/low/close`; 완료 1분봉 |
| `quote` | `time_ms`, `bid/ask`, 총수량·남은 증거금·호가 유동성의 수량 한도, 실행 가능·펀딩 확인 플래그 |
| `context` | `time_ms`, `thesis_valid`, `context_known`; 선택적으로 구간 새 버전·시장 판단 |
| `fill` | 체결 ID·주문 ID·수량·실행가·실제 수수료·수신시각 |
| `cancel_ack` | 주문 ID·최종 취소 확인 시각 |
| `funding` | 이벤트 ID·실제 비용·시각; 양수는 지불, 음수는 수취 |
| `fault` | 시각·이유·접속/보호 상태·계좌 중단 여부 |
| `reconcile` | 실제 부호 있는 수량, 주문·잔고·보호·근거·누락 복구 확인 |
| `heartbeat` | 새 봉이 오지 않는 동안의 시간 진행·지연 감지 |

`simulate_fills: true`는 연구용 합성 체결기를 호출한다. 유동성은 주문 간 공유하며, 취소 확인은 이 체결기에서 즉시 처리한다. 지연·부분 체결·취소 경합은 자동 체결을 끄고 명시적 `fill`·`cancel_ack`로 재생한다. OHLC 저가·고가에 닿았다는 이유로 지정가 체결을 만들지 않는다. 봉에서 손절 침범을 알게 된 경우 후속 실행 가능한 호가를 사용하므로 정확한 장중 스톱 체결 모형과 구별된다.

## 검증 범위와 남은 시장 입력

합성 시나리오는 주문 순서·회계·근거 보존의 검증이며, 실제 거래 성과가 아니다. 지정된 문맥·구간·초기 진입 계획으로 엔진을 재생할 수 있다. 이번 작업에서 새로운 상위 흐름 분류기나 매물대 탐색 규칙을 임의로 추가하지 않았다.

실제 시장 비교에는 인과적으로 기록된 구간/문맥/초기 계획, 실제 상품의 비용·주문 단위·계좌 한도·호가 유동성, 정확한 펀딩 이벤트가 필요하다. 거래소 송신·강제청산·증거금 모델과 자동 라이브 복구는 연결하지 않았다. 본 구현 완료를 실운용 가능 또는 비용 후 수익성 확보로 해석하지 않는다.
