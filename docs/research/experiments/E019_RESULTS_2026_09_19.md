# E019 — 공개 수신과 T0 진입 의도 연결 결과

**공개 분봉·호가의 실제 수신 시각을 기록하고, 새 신호 이후에 요청한 호가로만 진입 수량·예상 비용을 계산하는 경로를 구현했다.** 짧은 공개 확인은 완료했지만 해당 시간에 새4시간 신호가 없어 실제 신호→후속 호가 진입 추정은0건이다. 이 분기는 합성 검사에서 검증했다. 완성된 모의 계좌나 수익성 검증은 아니다.

## 구현한 동작

- E018의 마지막 검증 지표 상태에서 시작해 현재까지 연속 분봉으로 준비한다. 과거 계좌/포지션은 가져오지 않는다. 준비 중 발생한 신호로 주문 의도를 만들지 않는다.
- 준비 완료 후 ARM 시각보다 뒤에 끝난 신호만 관측 대상으로 삼는다. 예정 시각은 봉 종료+1분이며 예정+60초 이후에 받은 신호는 만료한다.
- 주문 의도가 생긴 뒤 새로 시작한 호가 요청만 사용할 수 있다. 그 호가의 거래소 시각도 신호 관측 가능 시각 이후여야 한다. 예정 전·오래된 호가·늦은 응답을 과거 가격 체결로 바꾸지 않는다.
- 매수는 ask, 매도는 bid를 기준으로 기존 비용/위험 가정을 적용한다. 최우선 호가에 표시된 수량이 부족하면 더 깊은 가격의 체결을 추측하지 않는다.
- 원문·시각·체크섬을 파일로 보존하고, 적격 입력과 그에 따른 상태/출력을 SQLite 한 트랜잭션에 저장한다. 저장 중 예외의 롤백·DB 재개·동일 요청 중복 처리·구현 바인딩 변경 거부를 검사했다.

공개 GET은 서버 시각,1분봉,최우선 호가만 사용했다. API 키·계정·주문 경로는 없다. [Binance 공식 REST 명세](https://developers.binance.com/en/docs/catalog/core-trading-derivatives-trading-usd-s-m-futures/api/rest-api/market-data)를 확인했으며, 호가의 가격·수량·거래소 시각과 로컬 수신 시각을 구분했다.

지표 준비용25,414분을 새 전진 거래 표본으로 세지 않는다. 새4시간 신호가 없었던 결과를 채우기 위해 합성 신호를 공개 원장에 넣지 않았다. 실제 신호→진입 추정의 종단간 공개 확인은 아직 미완료다.

호가 나이는 교환소/로컬 시계 차이를 포함한 관측치다. 네트워크 지연만 분리한 수치가 아니다. 시작/종료 서버 시각이 로컬 요청~수신 범위±1초 안에 들어왔는지 확인했고, 이것이 정밀한 시각 동기화 인증이라는 뜻은 아니다.

## 합성 검사와 원문 대조

관련 **31개 검사(신규14·E018 경계12·기존 회계5)** 통과. 실패·오류·건너뜀0이다.

새 검사는 준비 중 의도 억제, 충분한 준비 후 ARM, 매수ask/매도bid, 예정 전 호가, 오래되거나 의도 이전인 호가, 늦은 신호/의도 만료, 표시 수량 부족, 공백/중복/미완료 봉, 시계 변경, 다른 종목/역전 호가, 저장 예외·재개·동일 요청 재시도를 다룬다.

SQLite의 원문 체크섬과44개 네트워크 응답 파일·수신 시각을 직접 대조했다. 저장된 상태/출력을 같은 전이 코드로 재생해 동일함을 확인했다. 이 재생은 독립 전략 구현 검증이 아니다. 금융 계산과 시간 경계는 별도 손계산 가능한 합성 사례로 검사했다. 기존 **405개 증거 파일·46개 등록 소스**는 실행 전후 동일했다.

저장 중 예외는 INSERT 후 COMMIT 전에 주입했고 입력/상태/출력이 함께 롤백됨을 확인했다. OS 전원 장애나 디스크 고장 전체를 검증한 것은 아니다. 잘못된 입력의 네트워크 원문은 외부 파일에 남고 적격 상태에는 적용되지 않는다.

## 이번 구현의 정확한 범위

진입 추정은 매번 **포지션이 없는1,000 USDC 계좌의 독립 진입 탐침**이다. 실제 계좌 잔고·기존 포지션·반복 진입 정책을 연결한 연속 모의 계좌가 아니다. 코드 출력에도 `ISOLATED_FLAT_1000_ENTRY_PROBE_NOT_ACCOUNT_FILL`을 명시했다. 가격·수량 추정을 실제 체결로 보장하지 않으며, 기본5bp수수료/2bp슬리피지는 연구 가정이다. 실제 계정 요율을 확인한 값이나 maker0 성과가 아니다.

이번 공개 창에서는 신호0건이므로 신호·의도별 실제 지연, 만료 빈도, 추정 체결률을 계산할 표본이 없다. `summary.json`의 `eligible_signal_count` 필드는 내부적으로 준비 후 생성된 신호 수를 담는 명칭이며, 미래에는 만료/중립/억제 신호와 실제 의도를 출력 종류로 구분해야 한다. 이번에는 모든 해당 수량이0이다.

남은 핵심은 **연속 모의 계좌의 진입·유지·청산과 늦게 확정된 실제 펀딩의 정산**이다. 과거 시점의 펀딩 정보를 나중에 받아 이전 의사결정을 다시 계산하지 않도록 해야 한다. 또한 현재 프로세스의 단조 시각은 재부팅 후 이어 쓸 수 없으므로, 장기 재개는 새로운 수신 세션/시계 기준과 대조가 필요하다. DB 재열기 검사를 그 운영 문제의 완료로 부르지 않는다.

다음은 새 전략 튜닝 대신 이 의도 경로와 계좌 상태를 연결하고, 고정 합성 사건에서 진입→보유→청산·늦은 펀딩·프로세스 재개를 검증하는 단계다. 이후 실제 새 신호가 발생하는 공개 관측을 별도로 등록한다. 이번 기술 확인만으로 장기 관측이나 수익성 확증을 시작한 상태는 아니다.
