# E021 — 공개 수신과 연속 모의 계좌 연결

2026-09-19. E020 계좌·T0·위험/비용을 그대로 사용하고 공개 분봉/호가/펀딩 일정/확정 내역 수신을 연결한다. 전략 파라미터 탐색, 실주문, 장기 L2 수집은 없다. 과거 소스·증거는 보존한다.

## 고정 범위

- 공식 공개 GET `time`, `klines`, `ticker/bookTicker`, `premiumIndex`, `fundingRate`만 허용. API 키/계정/주문 접근 없음. 새 출력 디렉터리만 사용한다.
- `premiumIndex.nextFundingTime`은 예정 사건으로만 저장하고 `lastFundingRate`로 돈을 정산하지 않는다. `fundingRate`의 확정 사건만 E020 현재 수신 회계에 반영한다. 미래 일정을8시간 고정으로 만들지 않는다.
- 신규 빈 계좌의 조회 시작은 생성 시각−24시간으로 고정한다. 모든 펀딩 요청은 그 시작부터 요청 직전−1초까지의 전체 구간을 반복 조회한다. 한 페이지100건 상한에 닿으면 잘림 가능성 때문에 거부한다. 이번 유한 실행에서만 쓰는 정책이며 장기 페이징 완료 주장이 아니다.
- 관측된 예정 시각을 지난 미정산 사건, 일정/내역 조회30초 초과, 서버 시각 확인120초 초과, 완료 분봉120초 초과, 응답 오류가 있으면 새 진입을 막는다. 펀딩 시각±1초는 진입을 막는다. 청산·보유 위험 평가는 계속한다.
- 새로운 일정이 나타나도 기존 미정산 예정 사건을 지우지 않는다. 아직 미래인 예정 시각 변경은 수동 대조가 필요한 품질 문제로 남긴다. 실제 확정 시각과 예정 시각의 허용 차이는1초이며, 근접한 복수 사건은 거부한다.
- 반환 순서/종목/정산 유형/조회 범위/중복/수정/이전에 있던 사건 누락을 검사한다. 모호한 펀딩이나 오류 응답은 계좌 원장에 부분 반영하지 않고 거부 사유를 함께 저장한다. 유효한 후속 응답으로 일시 오류는 회복되지만 일정 충돌·보유 중30초 일정 관측 공백은 자동 해제하지 않는다.
- 원문 응답과 요청 매개변수·수신 시계·파생 상태/원장을 함께 기록한다. 새 세션은 조회 신선도를 초기화하고 E020 공백 청산 정책을 유지한다. 종료 시 대기 진입을 취소하고 모의 잔여 포지션 유무를 그대로 보고한다.

## 검증/실행

고정 합성 사건으로 미정산·지연·누락·충돌·중복·응답 실패·반전·위험 청산·저장 원자성·재개를 검사한다. 그 뒤 총180초/공개100요청/준비40페이지/응답512KiB/원문16MiB, 관측45초/폴링5초의 짧은 공개 연결 확인을 별도 결과로 구분한다. 관측 창에 새4시간 신호가 없으면0건으로 남기며 성공 기준을 바꾸지 않는다. 실제 새 신호 구간의 전진 거래 검증은 별도 등록이 필요하다.

`SCOPED_READY`는 관측한 예정 사건과 반환 내역의 대조/신선도 통과다. 거래소가 아직 공개하지 않은 사건·관측 사이 일정 변경·장기 내역 전체의 무누락 인증은 아니다. 품질이 나쁜 동안의 수익을 정상 표본으로 집계하지 않는다. 이번 결과는 기술 확인이며 전략 수익성/실운용 승인이 아니다.

공식 근거: [Binance USDⓈ-M 시장 데이터 명세](https://developers.binance.com/en/docs/catalog/core-trading-derivatives-trading-usd-s-m-futures/api/rest-api/market-data). 펀딩 이력의 구간 양끝 포함·오름차순·limit 및 `nextFundingTime`/확정 정산 `markPrice`를 확인했다. 위 신선도·진입 제한 수치는 거래소 보장값이 아닌 이 실험의 보수적 정책이다.
