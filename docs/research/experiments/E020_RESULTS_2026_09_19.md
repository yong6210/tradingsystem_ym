# E020 — 연속 모의 계좌 검증 결과

**진입 추정을 잔고·포지션·청산·위험 상태가 이어지는 모의 계좌로 연결했다.** 고정 합성 사건의 구현·회계 검증은 통과했다. 공개 전진 거래나 전략 수익성 검증을 완료한 것은 아니다. T0는 연구 대조 모델로 유지하며 최종 모델 채택·실주문은 없다.

## 달라진 동작

- 매번 포지션 없는1,000 USDC로 계산하던 E019 탐침과 달리, 현재 잔고로 수량을 계산하고 보유 중 손익·비용·위험 상태를 유지한다. 관측 신호 수와 적격 의도 수를 별도로 센다.
- 동일 방향 신호는 유지, 중립은 청산, 반대 방향은 청산 후 다음 적격 호가에서 재진입한다. 같은 호가에서 청산과 반대 진입을 동시에 만들지 않는다.
- 관측된 bid/ask로 손절·일손실·누적 낙폭·7일 보유 상한을 검사한다. 표시 수량이 부족하면 미청산 상태를 유지하며 가격이 회복해도 이미 발생한 청산 필요 상태를 없애지 않는다.
- 늦게 받은 확정 펀딩은 정산 당시의 모의 수량으로 계산해 **수신 시점** 잔고에 반영한다. 이미 청산했어도 반영하며 같은 사건은 한 번만 적용한다. 과거 신호·수량 결정·잔고 기록을 소급 수정하지 않는다.
- 새 수신 세션은 기존 잔고·포지션·위험 상태를 보존하고 대기 진입을 취소한다. 관측 공백을 기록하고 남은 포지션은 다음 적격 호가로 정리한다. 지표 준비/ARM 전 신규 진입은 막는다.
- 입력 원문·시계·세션·출력·계좌 상태를 SQLite 한 트랜잭션에 저장한다. 저장 직전 예외의 롤백과 동일 요청 재시도의 중복 방지를 확인했다.

| 기존 수신·증분·회계 검사 | 31 |

새 검사는 실제 T0 계산으로 생성한 진입, 동일 방향 유지·중립·반전, 오래된/예정 전 호가·만료, 손절 갭·표시 수량 부족·회복 후 청산, 숏 ask 손절, 일손실·DD·시간 상한, 늦은/중복/충돌/정산 경계 펀딩, 새 날 평가 전 받은 펀딩 손실, 새 세션·시계 역행·이전 세션 거부, 저장 실패·재개·재시도를 다룬다.

등록 전 개발 검사에서 ARM 시각을 준비된 마지막 완료 봉보다 앞에 둔 테스트 fixture 오류를 발견했다. 신선도 검사 기준은 유지하고 fixture 시각을 올바른 순서로 수정했다. 위50개는 이후 소스·검사 목록을 고정한 실행 결과이며 등록 실행의 자동 재시도는0이다.

## 통합 시나리오

| 합성 사건 | 확인한 결과 |
|---|---|
| 롱 진입 → 손절 호가의 표시 수량 부족 → 가격 회복 → 청산 → 늦은 펀딩·중복 | 청산 필요 상태 유지, 과거 보유량으로 현재 잔고 정산, 중복 차감 없음 |
| 숏 진입 → 새 세션/단조 시계 초기화 → 공백 청산 → 늦은 펀딩 | 계좌 보존·진입 차단, 새 호가로 숏 청산, 양의 펀딩률에 따른 숏 수취 반영 |
| T0 롱 신호 → 다음4시간 봉의 숏 신호 → 청산 → 다음 호가 숏 진입 → 손절 | 실제 증분 신호와 계좌 연결, 반전의 두 호가 분리, 잔고에 따른 다음 수량 사용 |

별도 Decimal 원장 재생은 부호 있는 보유량, 평균 진입가, 진입·청산 수수료, 실현손익, 정산 시점 보유량, 현재 시점 펀딩 반영을 계산했다. 각 입력 이후 저장 잔고와 `초기잔고 + 실현손익 − 수수료 − 펀딩`이 일치했다. 이는 독립 회계 검산이며 독립 전략 구현 비교는 아니다. 합성 사건의 최종 잔고는 [원자료](../../../reports/validation/e020_continuous_paper_20260919/scenarios.json)에 남기되 전략 수익률로 해석하지 않는다.

## 아직 증명하지 않은 부분

1. **공개 전진 연결:** 새 계좌는 이번에 네트워크를 사용하지 않았다. E019의 짧은 공개 수신 확인과 E020의 합성 계좌 확인을 합쳐 공개 거래 완료로 부르지 않는다.
2. **펀딩 완전성:** 받은 사건의 중복·회계만 처리한다. 빠진 정산을 발견하고 조회를 재개하는 공개 어댑터는 아직 없다. 펀딩 시각±1초의 체결은 보유량이 모호해 거부한다. 실제 계정 펀딩의 복제·거래소 시계 동기화 보장이 아니다.
3. **체결·위험의 관측 한계:** 기본5bp 수수료·2bp 슬리피지는 고정 연구 가정이다. 실제 maker0 체결, 큐 순서·부분체결·호가 깊이·보호주문은 구현하지 않았다. 폴링 사이 손절·최대 낙폭은 알 수 없고 손절 가격을 넘어선 손실이 가능하다. 일손실 기준은 그날 첫 관측 평가액이며 UTC 자정 미관측 평가액을 복원하지 않는다.
4. **복구 범위:** DB 재열기와 예외 롤백, 새 세션의 고정 사건을 검사했다. OS 전원 장애 전체·운영 자동 재시작·장기 저장량 적격성은 검증하지 않았다. 보유량/정산 이력은 이 유한 시험에서 상태에 남는다.
5. **수익성:** 기존 T0의 이익 집중·긴 회복·비용 문제는 이번 기술 구현으로 해결되지 않았다. 전략 튜닝이나 새 백테스트는 수행하지 않았다.

## 다음 순서

먼저 **공개 수신기와 새 계좌를 연결하고 펀딩 조회 누락·지연을 상태로 드러내는 제한된 실행 경로**를 만든다. 미확인 펀딩/자료 공백 상태를 정상 성과로 집계하거나 신규 진입을 허용하지 않는 기준을 고정한다. 그다음 실제 새4시간 신호가 생기는 공개 관측 구간을 별도로 등록해 진입→보유→청산의 발생 여부를 확인한다. 미발생 분기는 그대로 미검증으로 남긴다.

기술 검증과 수익성 확증 기준을 분리하고 기존 자료의 추가 최적화·위험 배수 확대는 하지 않는다. 장기 L2 수집을 다시 선행 조건으로 삼지 않는다.
