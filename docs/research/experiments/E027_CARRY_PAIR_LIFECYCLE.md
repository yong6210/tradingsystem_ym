# E027 S10 두 시장 모의 주문·계좌 계약

2026-09-19. E026의 수익을 전략 성과로 승격하기 전에 두 시장 체결 순서와 실제 확보 수량을 검증한다. 이번 범위는 단일 BTCUSDC 현물롱/선물숏 주기의 오프라인 상태·회계·장애 훈련이다. 외부 거래소 어댑터·실주문·새 공개 수집·과거 수익 재최적화는 없다. 기존 선물 전용 복구기와 예약된 E022는 수정하지 않는다.

초기 자금은 현물 지갑500/선물 지갑500 USDC, 현물 진입 지출 상한400, 목표0.006 BTC다. 순서: 현물 지정가→3초 뒤 취소 확인→필요하면 시장가 잔량1회→확인된 순 BTC와 동일수량 선물 지정가→같은 취소/시장가1회. 선물 최소단위0.001 BTC와 현물0.00001 BTC, 명목50/5 USDC는 테스트용 고정 계약이며 역사/실계정 필터 인증이 아니다. 현물 BTC 수수료를 반영한 순수량이 선물 단위에 맞지 않으면 큰 숏을 내지 않고 진입을 중단·현물 잔량 정리한다. 매도 불가능한 dust는0으로 만들지 않는다.

두 주문의 정상 완료 뒤에만 OPEN이다. 선물 헤지 실패·모의 주기 손실5 USDC·일손실2%·DD8%·가상 유지증거금1%+청산비 준비 부족은 종료를 요구한다. 이미 미확인인 주문은 먼저 조회/취소 대조한다. 종료는 선물 환매→실제 선물0 확인→현물 매도 순서이며 위험 종료는 시장가, 정상 종료는 지정가/3초 fallback이다. 시장가마저 부분 종료되면 잔량을 보존하고 추가 자동 시장가 반복 없이 RESIDUAL_REVIEW로 남긴다.

신규 주기 진입의1% 불리한 비헤지 가격 이동+두 시장 왕복 예상 수수료 준비액이5 USDC 예산 이하여야 한다. 이는 합성 위험 준비 가정이며 실제 손실 상한이 아니다. 수수료 추정은 현물10bp/선물2.5bp로 유지하되 회계는 응답의 실제 수수료와 지급 자산(USDC/BTC)을 쓴다. 선물 BTC 수수료는 미지원으로 명시한다. 가격 갭·부분체결로 계획 예산을 넘을 수 있고 발생 금액을 그대로 기록한다.

주문/취소 송신 의도는 SQLite BEGIN IMMEDIATE로 먼저 점유한다. 송신 뒤 응답 불명과 점유 직후 종료는 같은 ID 조회만 허용하며 not-found만으로 재송신하지 않는다. 주문 응답에는 전체 체결 ID·체결시각·수량·명목·USDC/BTC 수수료와 일관된 누적 수량이 있어야 한다. 중복은 무효과, 내용 충돌·역순 상태·누락 체결·과도 수량은 원문과 함께 격리하고 신규 동작을 중단한다. 선물 청산 주문은 reduce-only, 현물 청산은 실제 재고 이내다.

선물 손익과 현물 현금을 분리하고 현물 평가이익을 선물 증거금으로 이전하지 않는다. 선물 진입에는 기존/추가 명목의1배 초기 담보와 수수료를 준비하도록 가정하고 주문 생성과 송신 직전 모두 재검사한다. 이는 실계정 레버리지 인증이 아니다. 펀딩은 정산 이전 체결시각의 실제 선물 보유량으로 계산해 늦은 수신도 현재 선물 지갑에1회 반영한다. 같은시각 체결은 정산 뒤로 규정한다. 응답 관측 시각보다 미래의 체결은 격리한다. 운영비도 ID별1회 현물 현금 차감한다. 운영비 입력 기능을 실제 운영비 확정/성과 반영 완료로 부르지 않는다.

신선한 양시장 bid/ask·마크·펀딩 확인 상태가 필요하다. 오래된 호가로 새 주문을 만들지 않으며, 취소와 응답 조회는 허용한다. 완전한 조회 어댑터·계정/다중주기 통합·프로세스 리더·실제 유지증거금·호가 체결확률은 미완료다. 로컬 두 지갑은 한 연구 소유자만 관리한다. 모의 거래소 접수/체결 DB와 로컬 원장을 독립 검산하고 장애 결과를 수익성 근거로 사용하지 않는다.
