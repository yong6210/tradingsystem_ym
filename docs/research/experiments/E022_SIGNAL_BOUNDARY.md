# E022 — 새4시간 신호의 시각 지정 공개 검증

고정 대상: **2026-09-18 20:00 UTC = 한국9월19일05:00 완료 봉**. 진입 예정은05:01이다. E021의 신호 없는 짧은 확인을 반복하지 않고, 해당 봉을 완료 전에 ARM한 계좌에서 관측한다. 이번은 한 번의 기술 검증이며 모델 채택·수익성 시험이 아니다.

## 실행 계약

- 준비/등록은 먼저 오프라인에서 한다. E021 검증 지표 상태를 seed로 재사용하고, 실행 직전에 새 빈1,000 USDC 모의 계좌를 만든다. 비용·위험·T0·공개 입력/펀딩 정책은 E020/E021 그대로다.
- 목표−60초에 네트워크 시작, 늦어도 목표−30초 안에 시작해야 한다. ARM은 목표−1초 이전이어야 한다. 너무 이르거나 늦으면 네트워크 없이 거절/미실행으로 기록한다. 목표 시각을 다음 봉으로 자동 변경하지 않는다.
- 시작180초 전부터의 짧은 대기는1초 이하 간격으로만 하고 네트워크 요청은 없다. 대기 중 벽시계/단조 시계 차이1초 초과는 거절한다. 장시간 수집/별도 상주 프로세스는 만들지 않는다.
- 목표+110초를 관측 종료 상한으로 정한다. 조회 주기10초, 서버 시각은60초마다 갱신한다. 각 주기의 최악 요청 시간25초와 종료 요청10초 여유가 없으면 새 주기를 시작하지 않는다. 실제 기록이 더 짧을 수 있으며 실측 길이를 보고한다.
- E021 전송의 총180초/100요청/응답512KiB/원문16MiB 한도를 그대로 쓴다. 기존45초 연결 확인 대신 새 시간 창을 등록한 것이며 시간/요청 한도를 무제한 늘리지 않는다. 준비 최대40페이지는 같지만 시작 시각 조건도 함께 적용한다.
- END에서 대기 의도를 취소한다. 모의 포지션이 있으면 이후 새 호가로 종료 청산을 한 번 시도한다. 표시 수량 부족/오류라면 잔여 포지션을 그대로 보고한다. 이 청산은 **관측 종료 청산**이며 자연스러운 전략 청산이나 전략 수익률로 집계하지 않는다.
- 입력 원장 재생과 별도로 Decimal 회계, 원문 bid/ask+가정 슬리피지/틱 가격·수수료, 확정 펀딩 당시 수량을 검산한다. 진입은 직전 의도의 목표 봉 시각·생성 후 요청·이후 거래소 호가·예정+1분/만료를 직접 대조한다.
- 신호 없음·가드/수량/지연 등으로 진입 없음·진입 관측을 구분한다. 실패·늦은 기동·미발생을 성공으로 바꾸거나 결과를 위해 재시도하지 않는다. 동일 실행 디렉터리의 중복 생성도 거부한다.

## 검증과 예약

합성 시계로 시작/ARM 경계·봉 완료→예정+1분→진입→종료 청산을 검사한다. 변조된 원장·선행 호가·다른 목표 신호를 독립 감사가 거부하는지 확인한다. 기존73검사도 함께 실행하고 소스/테스트/seed/기존 증거를 고정한다.

현재 작업에 연결한 예약은 한국04:58에 한 번 재개해 등록 실행기를 호출하도록 준비한다. 정확한 타이머 실행을 보장하지 않으므로 실제 기동이 늦으면 미실행으로 남긴다. 시도 완료/실패/시각 놓침 후 예약을 중지한다. 예약 등록 여부는 별도 도구 결과로 확인하며 이 문서만으로 예약 완료를 주장하지 않는다. 로컬 실행에는 컴퓨터와 앱이 켜져 있어야 한다.

보유 중 실제 펀딩·자연스러운 전략 청산·장기 전략 성과는 이번 짧은 창에서 보장할 수 없다. 확인된 분기만 보고하고 다음 실험은 그 결과 이후에 정한다.
