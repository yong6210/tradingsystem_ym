# E019 — 공개 수신 이후의 T0 진입 의도 연결

2026-09-19. 신호·수신 시각→후속 호가→고정 위험 진입 추정과 원본/상태/출력 저장 경계를 구현한다. **진입 탐침이며 완성된 모의 계좌·체결·수익률 평가가 아니다.** 거래소 주문/계정 API는 호출하지 않는다.

## 고정 범위

- E018 마지막 검증 지표 상태를 준비 시작점으로 사용한다. 계좌는 가져오지 않는다. 공개1분봉으로 현재까지 연속 준비한다. 준비 중 신호는 모두 억제하고 준비 완료 뒤 ARM 시각 이후에 끝난 신호만 관측 대상으로 둔다.
- 완료 봉 종료+1분의 기존 예정 시각을 보존한다. 예정+60초를 넘겨 받은 신호는 만료한다. 예정 전에 받은 신호는 예정 시각까지 기다린다. 다음 호가 요청은 의도가 만들어진 뒤 시작해야 한다. 당시 거래소 호가 시각도 관측 가능 시각 이후여야 한다.
- 매수 ask/매도 bid 기준으로 기존 기본 비용5bp/슬리피지2bp·1,000 USDC·0.5% 위험·0.001 수량 단위를 사용한다. 표시된 최우선 호가 수량보다 크면 더 깊은 체결을 추측하지 않는다. 고정 초기자본의 **독립 진입 추정**이며 실제 가용잔고/포지션/진입 횟수 정책과 다르다.
- 종가 확정은 로컬 수신 시각에서1초를 뺀 시각으로 보수적으로 판단한다. 서버시각은 요청 시작~수신 범위±1초 안에 있어야 한다. 응답5초, 호가 나이5초/미래1초, UTC와 단조 시간 변화 차이1초를 기술 상한으로 둔다. 최적 체결 조건이나 정밀한 NTP 검증은 아니다.
- raw 응답·수신 시각·체크섬은 파일에 먼저 보존한다. 적격 입력과 결과 지표 상태·의도/추정 출력은 SQLite 단일 트랜잭션으로 저장한다. 동일 요청 재시도는 정확한 원문/시각이 같아야 한다. 재시작 시 구현/설정 바인딩을 확인한다. OS 전원 장애 전체 검증은 아니다.

## 짧은 공개 확인

공식 공개 GET `/fapi/v1/time`, `/fapi/v1/klines`, `/fapi/v1/ticker/bookTicker`만 사용한다. 요청별5초, 최대70요청, 응답당512KiB, 전체원문16MiB, 전체실행180초. 준비 최대40페이지×1,000분. 준비 뒤 관측45초,5초 간격.429/418/다른HTTP 오류 및 자료 공백에 자동 재시도하지 않는다. 수익이 나올 때까지 연장하지 않는다.

공식 명세: [USDⓈ-M 시장 자료 REST](https://developers.binance.com/en/docs/catalog/core-trading-derivatives-trading-usd-s-m-futures/api/rest-api/market-data). 2026-09-19 확인. 기존 L2 장기 수집 계약은 보존하되 이 제한된 봉/최우선호가 진입 탐침의 선행 조건으로 삼지 않는다.

45초에4시간 신호가 없으면 신호0/진입추정0을 그대로 보고한다. 실제 신호가 없는데 합성 신호를 공개 관측 결과에 섞지 않는다. 모든 실제 신호·원문은 동결 후 생성/수신 시각을 보존한다. 성과 평가 또는 완전한 전진 전략으로 선언하지 않는다.

미완료: 포지션 유지/청산·실제 확정 펀딩의 늦은 수신 처리·지속 계좌·실주문/보호주문·수익성 확증. 그 기능을 구현하기 전에는 이 진입 추정에서 수익률을 만들지 않는다. 다음 연결에서 확정 펀딩을 이전 의사결정에 소급 삽입하지 않는 회계가 필요하다.
