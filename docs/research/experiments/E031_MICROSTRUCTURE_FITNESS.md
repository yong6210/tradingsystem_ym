# E031 — 기존 주문 흐름·시장조성 자료의 사용 범위 점검

2026-09-19. E030 이후 다음 후보 실행 여부를 결정하는 **읽기 전용 자료 진단**이다. 새 신호/수익/체결률을 계산하지 않으며 장기 수집이나 실제 주문을 시작하지 않는다.

## 질문과 범위

기존에 등록한 실제 공개 원문으로 S06 본래 호가·체결 가설 또는 S11 시장조성의 비용 후 경제성을 평가할 수 있는가? 과거의 연결 검사 수·합성 장애 검사를 시장 관측 표본으로 합산하지 않는다.

대상은 최초 `execution_data_fitness_20260917`, 공개 재연결 두 시도, 네 스트림 영속 수집 두 시도, E021 REST 관측, E022 결과 존재 여부다. 파생 재생 파일은 새로운 시장 표본이 아니다. 저장소 전체의 비등록 자료를 전수 조사한 결론은 아니다.

## 결과 확인 전에 정한 계산

- 원문 해시를 기존 검증 기록과 대조한다. 영속 로그는 순번·앞 해시·각 행 해시·체크포인트와 배치의 원문 끝 순번/해시를 별도로 대조한다.
- 스트림별 원문 건수, 서로 다른 공개 집계 체결 ID, 중복/충돌/역순·ID 건너뜀을 기록한다. ID 건너뜀0은 공식 전달 완전성 보장이 아니다. 거래 없는 시간 자체는 결측으로 세지 않는다.
- 거래소 시각과 로컬 수신/저장 후 공개 시각을 분리한다. 각 체결 시각 T 이전의 마지막 호가 갱신을 전체 파일에서 사후 선택했을 때, 그 호가가 실제로는 체결의 로컬 사용 가능 시각보다 늦게 공개된 경우를 세어 시간 조인 위험을 확인한다. 기존 엔진이 이 잘못된 조인을 사용한다는 주장이 아니다.
- 최초 자료는 기존 재생의 보수적인 snapshot 공개 경계를 재사용한다. 정확한 REST 단조 수신 시각이나 fsync 공개 시각이 없으므로 지연 검증용으로 승격하지 않는다. 두 영속 자료는 기록된 배치 공개 시각과 적격 여부를 사용한다. 종료 수신은 표본에서 제외하되 개수는 보존한다.
- 한 구간에서 첫/마지막 사용 가능 호가와 체결의 공통 시각 범위를 구한다. 이는 관측 범위이며 연속 품질 인증이 아니다. 3/60/300초 길이별 `floor(범위/길이)`는 겹치지 않는 창의 **낙관적 개수 상한**이다. 실제 적격 사건·독립 표본 수·통계적 검정력으로 해석하지 않는다. 서로 떨어진 수집 구간을 이어 붙이지 않는다.
- S06/S11 모두 비용 후 성과 추정을 보류한다. 최소한 원본 호가·공개 체결·사용 가능 시각의 연속된 자료와 고정된 신호/관찰·위험/청산 창이 필요하다. S11은 추가로 대기열/부분 체결/취소 경쟁의 불확실성을 체결 시나리오에 남겨야 하며 공개 L2만으로 자기 주문 체결을 확정하지 않는다.

3초는 기존 시장가 전환 대기 정책에서,60/300초는 짧은 후속 가격 관찰의 자료 길이 점검용에서 온다. 선택할 신호의 최적 보유기간이 아니다. 수익성에 충분한 전체 기간은 여기서 임의로 정하지 않는다. 하루/일주일 또는100건만으로 충분하다고 주장하지 않는다.

## 종료 기준

실제/합성·재생/신규 원문 구분, 호가와 체결의 공통 범위, 시각 조인의 위험, 후보별 부족 자료와 다음 최소 행동을 남기면 이 진단은 종료한다. 불충분하면 짧은 연결 검사를 반복하거나 체결률을 가정해 후보를 합격시키지 않는다. 실제 자료 확보는 별도 접근/기간/용량 계약이 구체화된 뒤 판단한다. E022는 원래 예약·목표 시각을 유지한다.
