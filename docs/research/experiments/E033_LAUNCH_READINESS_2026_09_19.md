2026-09-19 KST05:22. **E022는 현재 예약 파일 부재와 시작 기한 경과로 실행 준비 불가다. 과거 예약 생성은 확인했지만, 예약 파일이 없어지거나 이동한 원인·시점과 스케줄러 동작은 아직 미확인이다.** 이 문서는 스케줄러 복구 완료나 공개 관측 결과가 아니다.

## 확인한 근거

원래 대상 작업 `프로젝트 전반 점검 및 개선`의 과거 도구 결과를 다시 읽었다. UTC2026-09-18 16:15:04.467에 도구가 `btc-4` 생성·ACTIVE를 반환했고,16:15:11.739의 실제 파일 읽기 결과에도 heartbeat·ACTIVE·대상 작업 ID·일회 일정·프롬프트가 있었다. 따라서 “처음부터 예약되지 않았다”는 설명은 현재 증거와 맞지 않는다. 해당 파일 읽기 원문과 기록 해시는 [별도 역사 자료](../../../reports/validation/e033_launch_readiness_20260919/historical_provenance.json)로 보존했다. 과거 프롬프트는 증거이며 재실행 지시로 사용하지 않는다.

현재 점검에서는 `/Users/yumin/.codex/automations/btc-4/automation.toml`이 없다. 현재 다른 예약 파일이 있다는 이유로 이를 대체 실행하지 않는다. 과거 파일 존재와 현재 파일 부재만으로 삭제 주체·삭제 시점·저장소 이전·스케줄러 오류를 결정할 수 없다. 예약 디렉터리 수정 시각도 이 예약의 변경 시각을 증명하지 않는다.

대상 작업은 조회 시 notLoaded, 최근 두 차례 진행은 interrupted였고 E022 공개 결과 폴더는 없었다. 이는 기동 원인을 확정하는 실행 영수증이 아니다. 예약 조회 도구는 화면 카드만 표시하고 상세 필드를 반환하지 않았다. Codex 화면 읽기는 CUA 도구가 안전 제한으로 거절해 중단했다. 다른 방식으로 화면 접근 제한을 우회하지 않았다. 사용자에게 현재 예약 목록의 해당 항목 존재/상태 확인을 요청했다.

[OpenAI 공식 안내](https://developers.openai.com/ko-KR/docs/automations)는 예약 목록의 상태·최근 실행 기록 확인과 로컬 실행 시 컴퓨터/앱 실행 유지를 안내한다. 문서는 이번 사건의 원인을 증명하지 않는다. 잠자기·앱 종료·사용자 삭제·정상 완료 자동 정리 등은 확인되지 않은 가설이다.

## 이번에 보완한 점

현재 상태를 읽는 독립 점검기 [check_signal_launch_readiness.py](../../../scripts/check_signal_launch_readiness.py)를 추가했다. 원래 동결 실행기와 예약 소스는 수정하지 않았다. 점검기는 시장 요청·실주문·작업 실행·예약 생성/변경 기능이 없다.

현재 예약 파일이 없거나 읽을 수 없거나 중지 상태이면 준비 완료로 표시하지 않는다. ID·종류·대상 작업·일정·프롬프트가 과거 고정값과 다를 때도 차이를 남긴다. 준비 자료/소스 해시 변경, 기동 기한 경과, 공개 실행 디렉터리의 기존 점유 여부를 함께 보고한다. 빈 공개 디렉터리도 이미 시도한 것으로 취급해 재시도 가능이라고 표시하지 않는다.

점검 통과 시 표현도 `FRESH_CONFIGURATION_CHECK_ONLY`다. 현재 설정의 일시적 일치일 뿐 예약 재개·실행기 시작·ARM·시장 관측이나 미래에도 설정이 유지될 것을 증명하지 않는다. 이 점검을 과거 영수증 하나로 대체할 수 없다. 현재 구현은 독립 진단 도구이며 예약 실행 경로에 배포/연결한 상태는 아니다.
