# Q004 — 미래 가격 전에 고정하는 PRICE 예측

2026-09-19. 기존 자료 재분할 대신 실제 미래 결과가 발생하기 전에 예측을 기록한다. **예측/동일 명목 사건 진단이며 1,000 USDC 모의 계좌·체결 검증·손실 5% 검증이 아니다.** 경제성 근거가 부족한 상태에서 주문·위험 구현을 확대하지 않는다.

## 질문과 선택 이력

Q003에서 E040의 PRICE/FLOW 모두 전체 MSE가 단순 기준보다 컸지만, abs(prediction)>2H 구간의 비용 후 사건 평균은 양수였다. 이는 이미 본 표본에서 발견한 사후 선택이다. 그 구간을 과거에서 재실행해 성공 전략으로 만들지 않는다.

질문은 **고정한 PRICE 예측의 크기와 선택 사건 수익이 새 시장 자료에서도 재현되는가**다. PRICE를 사용한 이유는 FLOW의 추가 정보 가치가 확인되지 않아 특징 수가 적은 원래 대조를 유지하기 때문이다. 단순 과거 평균/0 예측 대조, 원래 H와 사후 선택한 2H를 모두 보존한다. 원래 모델의 성공 가능성이 높다고 전제하지 않으며 새 최적화·보정은 없다. 이 후보는 Q002 캐리와 별개이고 예측 연구 1개 안의 선택 규칙 2개다.

## 고정 모델과 시각

[정책 JSON](../../../configs/research/q004_prospective_price_forecast_v1.json)을 따른다. E040 PRICE의 완료 1일/7일 수익률·1일 실현 변동성, 과거 180일·하루 학습 간격, 학습 구간 표준화, n 크기 ridge, 학습 목표 평균 절편을 유지한다. 코드의 동일 계산식과 독립 least-squares 대조를 재사용한다.

매일 UTC 00:00=b. b 이전 완료 분봉만 현재 특징으로 사용한다. 학습 날짜는 [b−181일,b−1일), 가장 최근 목표 종료는 b−1일이다. 예측 목표는 b+1분 시가→b+1일 시가의 가격 수익(bp). 현재/미래 목표가 NaN이어도 학습에 넣지 않는다. 과거 180일 목표 평균과 0 예측도 같은 예측 기록에 저장한다.

첫 경계는 **2026-09-19 00:00 UTC=한국 09:00**. 경계+5초부터 자료 확인·계산을 시작하고 **+50초까지 영속 기록이 완료돼야** 한다. 실제 목표 가격 시작 +60초보다 앞선다. 거래소 시각과 로컬 시각 차이 1초 이내·조회 왕복 3초 이내를 요구하고 벽시계/단조 시계 차이도 확인한다. 늦은 실행은 `MISSED`이며 이후 결과를 보고 예측을 복원하지 않는다. 파일 작성 완료 시각까지 검사한다. 로컬 영수증이며 외부 공증은 아니다.

등록은 코드·정책·명세·테스트·기존 입력 해시와 함께 첫 경계 전에 끝내야 한다. 이번 준비 시각 이전 가격은 모두 학습/준비 자료로 분류한다. 기존 E040 기록과 2026-08월 공식 검증 분봉을 재사용하고 이후 완료 봉만 공개 API로 보완한다. 날짜 간격·중복·양수 가격·OHLC·단위·봉 종료를 검사한다. 과거 입력과 겹치는 부분은 값을 대조한다. 새 API 응답·요청/수신 시각·해시를 저장한다.

## 사건 진입·보유·종료와 비용

- H=18bp+직전 확정 펀딩 3개의 합 절댓값(bp)+왕복 가격 단위 여유(0.2/직전종가×10,000). 정산 시각 b 미만만 사용한다.
- original_H: abs(p)>H, exploratory_2H: abs(p)>2H이면 예측 방향. 나머지는 무거래. 두 선택 모두 같은 예측에서 고정하며 하나만 골라 보고하지 않는다.
- 사건은 b+60초부터 b+86,400초까지 고정 보유하고 끝낸다. 사건 단위 조기 손절 없음, 중복/추가 진입/롤 없음. 이는 예측 목표와 정책의 대응을 보는 단위 명목 진단이며 실제 계좌에서 무손절 운용하라는 뜻이 아니다.
- 비용은 사용자 BTCUSDC taker 2.5bp/편도, 기존 슬리피지 2/5bp, 실제 역사적 정산 펀딩과 정산당 추가 0/1bp 스트레스를 유지한다. 가격 기준은 각 미래 분봉 open에 불리한 슬리피지·틱을 적용한다. 실제 호가/주문 체결을 관측한 것이 아니다. 현금 이자/운영비/증거금/최소 수량은 계좌 단계에서 별도 필요하며 이번 사건 수익을 1,000 USDC 계좌에 곱하지 않는다.
- 펀딩은 원래 E040의 분 단위 처리와 맞춰 정산 시각을 다음 분 경계로 올림한 뒤 entry<정산처리≤exit인 정산만 반영한다. 명목분모는 진입 기준 시가다. 실제 체결 전 보유를 소급하지 않는다.
- 결과는 목표 종료 분봉이 완료된 뒤 조회한다. 예측 파일·공표 영수증·등록 해시가 유효해야 점수화한다. 늦게 생성된 예측은 결과가 좋아도 채점하지 않는다. 원문 결과 누락은 0 수익으로 바꾸지 않는다. 펀딩은 진입 하루 전부터 종료 분봉 끝까지 조회하여 구간 양끝을 감싸는 정산 기록과 인접 간격 8시간+1초 이하를 요구한다. 빈 응답·중간 누락·종료 정산 미게시·더 긴 정산 주기이면 비용 0으로 처리하지 않고 미확인으로 남긴다. 이는 수집 완전성의 보수적 조건이며 향후 정산 주기 불변을 보장하지 않는다.

## 평가 기간과 종료

2026-09-19부터 90개 UTC 경계, 마지막 경계 2026-12-17, 마지막 목표 종료 2026-12-18 00:00 UTC. 90일은 이번 자료 수집/진단의 고정 길이이고 수익성 확증에 충분한 표본 크기라는 뜻이 아니다. 강한 사건은 드물 수 있으므로 사건 수와 불확실성을 반드시 함께 보고하며 표본 부족 시 미판정으로 끝낸다. 좋은 성과를 얻기 위해 관찰 종료를 연장하지 않는다.

주 지표: PRICE 대 MEAN180/ZERO의 같은 날짜 MSE/MAE, 원래/강한 선택의 실제 사건당·달력당 비용 후 bp와 예측−실현 격차. 무신호는 0 사건 수익, 미공표/미확인 결과는 결측으로 구분한다. 전체 90개 예정 날짜 대비 유효/누락 수를 공개한다. 원래 문턱 대비 개선과 양 비용 순익도 보지만 자동 채택 관문은 없다. 실제 계좌의 수익·5% 손실·회복·집중·운영비와 실체결은 별도 검증이 필요하다.

결과 확인 전에 규칙을 고정했더라도 실제 공표가 없는 날은 전진 검증이 아니다. 입력 오류로 버전을 바꾸면 원기록을 보존하고 새 버전은 별도 미래 구간으로 등록한다. 원래/강한 선택 중 좋은 것만 최종 모델로 선택하면 그 선택 이후 독립 계좌 평가가 다시 필요하다.

## 이번 실행과 운영 범위

이번 작업에서는 코드·테스트·규칙 고정, 첫 날짜의 준비, 기한 내 첫 예측 공표까지만 실행한다. 내일의 실제 목표 결과는 아직 존재하지 않으므로 수익 결과를 만들지 않는다. 90일 자동 실행이나 새 예약은 만들지 않는다. 스크립트가 준비돼 있다는 것과 매일 기동하는 것은 다르다. 이후 기동되지 않은 날짜는 미공표로 남는다. E022의 기동 누락을 정상 무신호로 숨기지 않았던 원칙을 유지한다.
