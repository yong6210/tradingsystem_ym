# E022 — 시각 지정 관측 준비 및 예약

**새4시간 봉 완료를 포함하는 공개 실행기를 준비하고 한국9월19일04:58에 이 작업을 재개하도록 예약했다. 관련85검사는 통과했으며 실제 공개 실행은 아직 시작하지 않았다.** 준비 완료를 실제 진입이나 수익성 확인으로 해석하지 않는다.

## 정한 시각과 동작

| 한국 시각 (2026-09-19) | 동작 |
|---|---|
| 04:58 | 현재 작업의 예약 재개. 등록된 실행기 호출 |
| 04:59 | 공개 데이터 조회 시작. 이보다 일찍 재개하면 짧게 대기 |
| 04:59:30 | 시작 허용의 마지막 시각. 이후 기동은 미실행으로 기록 |
| 04:59:59 이전 | 지표/펀딩 준비 후 ARM 완료 필요 |
| 05:00 | 대상4시간 봉 완료 (UTC2026-09-18 20:00) |
| 05:01 이후 | 실제 새 신호와 후속 호가가 적격이면 모의 진입 |
| 05:01:50까지 | 관측 종료 상한. 이후 새 호가의 종료 청산/마지막 시각 확인은 남은 전송 예산 내 수행 |

예약 실행 시각은 정밀 타이머 보장이 아니다. 기동 지연·준비 지연·시계 변경으로 대상 봉을 놓치면 미실행/실패로 남기며 다음 봉으로 자동 이동하거나 재시도하지 않는다. 신호 없음, 신호는 있으나 진입 차단, 실제 목표 신호의 모의 진입을 구분한다.

이번은 짧은 기술 관측이다. 종료를 위해 청산하면 `observation_end_exit`로 따로 집계한다. 그 청산 손익을 전략의 자연스러운 청산 성과로 부르지 않는다. 표시 수량 부족 등으로 청산되지 않으면 잔여 모의 포지션을 그대로 보고한다. 실제 주문은 없다.

## 이번에 완료한 검증

- **85개 등록/실행/통과**, 실패·오류·건너뜀0. 신규12개와 기존73개다.
- 신규 검사는 UTC4시간 경계·너무 이른/정상/늦은 시작·봉 완료 전 ARM·실제 T0 합성 신호→예정 이후 진입→종료 청산을 다룬다.
- 독립 Decimal 감사는 원문 bid/ask의 가정 슬리피지/틱 가격·수수료·잔고·과거 보유량 펀딩을 검산한다. 진입 직전 의도의 대상 봉, 의도 생성 이후 요청, 예정 이후 호가를 확인한다. 가격·현금·신호 계보·호가 시각을 바꾼 사례를 거부했다.
- 짧은 대기에서 네트워크가 호출되지 않고1초 이하 간격을 쓰며, 벽시계/단조 시계 차이를 거부하는지 확인했다.
- 소스62개·이전 증거728개를 실행 전후 대조했다. 전략/위험/비용 설정 변경과 신규 튜닝은 없다.
- 실제 실행 명령을 현재 시각에 호출했을 때 `TOO_EARLY`, 네트워크 요청0으로 종료했다. 공개 결과 디렉터리가 만들어지지 않아 예정 실행을 소모하지 않았다.

전송의 최대180초/100요청/원문16MiB 한도는 E021을 그대로 사용한다. 새 창에서는 폴링10초·서버 시각 확인60초로 고정했고, 요청·종료 여유가 없으면 새 주기를 시작하지 않는다. 실제 기록 길이와 분기 발생 여부는 실행 후 보고한다.

## 예약 상태

이 작업에 연결된 `BTC 새 4시간 신호 검증` 예약을 도구로 생성하고 ACTIVE/heartbeat/현재 작업 대상임을 읽어서 확인했다. 식별자는 `btc-4`다. 대상 일회 실행 후 완료·실패·시각 놓침 결과를 검토하고 예약을 중지하도록 설정했다. 과거의 별도 중지된 자동화는 변경하지 않았다.

예약 생성 첫 호출은 현재 작업 목적지 인자가 빠져 도구 검증에서 거절됐고 아무 예약도 생성하지 않았다. 목적지를 명시한 호출로 하나를 생성했다. 이는 공개 실험 실패나 시장 관측 재시도가 아니다.

로컬 파일을 쓰므로 해당 시각에는 컴퓨터와 Codex 앱이 켜져 있어야 한다. [OpenAI 공식 예약 작업 안내](https://developers.openai.com/ko-KR/docs/automations). 정확한 재개 시각·네트워크 정상·실제 진입을 예약만으로 보장하지 않는다.
