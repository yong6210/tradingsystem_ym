# 수집 작업 인계·완료 영수증·중단 복구 v1

2026-09-18. 최종 자동매매 모델을 위한 자료 신뢰성 작업이다. 전략 추가나 수익성 검증 결과가 아니다. 기존 공개 연결 검증을 마친 v6 수집기에 새 조정기를 주입하여 **오프라인** 중단·복구를 확인했다. 기존 수집기 기본값과 과거 확정 소스·자료는 변경하지 않았다.

## 해결한 문제와 순서

기존 조정기는 실행 중 작업과 완료 결과를 메모리에 보관했다. 부모 프로세스가 사라지면 ‘파일이 남아 있다’는 사실만으로 인계된 작업인지, 감사가 완료됐는지 판단할 수 없었다. 새 조정기는 다음 순서를 강제한다.

1. START에 저장 계약·작업 한도·구현 해시를 기록한다. EPOCH는 초기 입력 위치와 체크포인트 영수증을 묶는다.
2. 확정 원본과 감사 구간의 ticket을 UNIT로 영속 저장한 뒤에만 작업자가 실행될 수 있다.
3. 압축 등록과 감사 체크포인트가 완료되면 AUDIT 영수증을 기록한다. 다음 감사 작업이 실행되기 전에 앞 영수증을 저장한다.
4. CLOSED는 인계된 마지막 입력 위치를 고정한다. 모든 단위 감사와 종료 감사가 끝난 뒤 FINAL, 모든 epoch 종료 뒤 COMPLETE를 기록한다.

이벤트는 순번과 이전 이벤트 해시를 가진 개별 파일이다. 임시 파일 fsync → 원자적 이름 교체 → 디렉터리 fsync 순서를 사용한다. 256개 이벤트·개별512KiB·원장 전체16MiB·복구16회 상한과 기존 공용 저장 예산을 적용한다. 기록/검증은 동기이며 매 append마다 유한 이력을 다시 검사한다. 장기 운용에 무제한 확장 가능한 구조로 인증하지 않는다.

## 복구가 의미하는 것

호출자가 보관한 외부 영수증과 실행 디렉터리의 단독 소유권이 필요하다. 연속 이벤트·구현 해시·계약·입력 위치를 검증하고, 이름 교체는 됐지만 응답을 잃은 이벤트는 다시 fsync한 뒤 사용한다. 임시 이벤트만 존재하면 인계를 인정하지 않는다.

체크포인트는 마지막 완료 영수증과 같거나 정확히 한 단계 뒤여야 한다. 한 단계 뒤라면 인계된 다음 작업의 입력 끝 위치와 종료 여부가 일치할 때만 유실된 영수증을 복원한다. 이미 완료한 작업을 다시 감사하지 않고, 남은 인계 작업은 이어서 처리한다. 모든 인계 원본/등록 gzip은 오프라인에서 다시 검증한다. 손상된 gzip을 발견했을 때 원본으로 조용히 대체하지 않는다.

인계되지 않은 원본·seal·임시 파일·압축 orphan은 보존한다. 열린 epoch는 닫혔다고 추정하지 않는다. `ADMITTED_CLOSED_EPOCHS_RECOVERED`도 **기록된 닫힌 epoch의 작업 복구**라는 뜻이다. 전체 원래 실행의 완전성·연속 정상 운용·자료 품질 적격성·실시간 호가 상태 복원을 인증하지 않는다. 모든 복구 결과에 `full_original_run_certified=false`, `live_market_state_restored=false`를 남긴다.

최신 외부 영수증 이전으로의 원장 후퇴를 검출한다. 외부 영수증도 함께 잃었거나 보관한 영수증 이후 자료 전부가 악의적으로 되돌려진 상황까지 해시로 보장하지 않는다. 외부 영수증 전달/보관 서비스와 새 실시간 세션 시작 감독기는 아직 없다.

## 부모 종료 후 작업자

고정된 압축/감사 모듈만 실행하는 wrapper가 부모 PID와 독립15초 이하 수명을50ms 간격으로 확인한다. 부모가 없어지면 읽기 전용 작업자는 종료한다. 부모가 살아 있을 때의 공용 예약·시간/RSS 제한·회수는 기존 감독기를 따른다. 프로세스 정지나 실행 불가능 상태까지 선점하는 OS 하드 타이머는 아니다. 부모 사망 후 고아 프로세스의 OS 회수를 이 하네스가 수행했다는 주장도 하지 않는다.
