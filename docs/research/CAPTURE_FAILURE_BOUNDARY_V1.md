# 수집 실패 경계와 고정 전제 검사 v1

2026-09-18. 이전 전체 회귀의 실패10·오류5를 그대로 보존하며, 실패 후 저장과 초기화/정리 경계를 별도 구현으로 보완한다. 전체 회귀 승인·실제 수집 적격성·전략 수익성의 인증이 아니다.

## 구현

- `app/research/data/capture_failure_boundary.py`: 실패한 공용 저장 예산에 결과/END를 다시 쓰지 않는다. 원래 수집 원인과 저장 예외를 메모리 진단에 남기고, 같은 감독기에서 재호출해도 저장·연결을 재시도하지 않는다. 정상 저장 상태의 일반 예외와 취소는 호출자에게 전파한다.
- `app/research/data/guarded_generation_capture.py`: 기존 증분 감사 실행기를 이용하는 별도 합성 경로다. 준비 중 원래 종료 시각이 지났으면 연결 전에 중단하며, 초기화 중 예외를 실패로 기록한다. 정리 중 예외가 발생해도 저장 예산의 루트 잠금을 해제한다. 기존 실행기와 기본 경로는 보존한다.
- 결과 저장이나 END의 rename 이후 확인 응답이 유실되면 파일은 물리적으로 존재할 수 있다. `durable_result_acknowledged`와 `completion_receipt_acknowledged`는 false이며 메모리 보고서로 성공을 승인하지 않는다. `result_persisted=false`는 **반환된 실패 진단 자체가 저장되지 않았다**는 뜻이다. 이전 결과 파일의 부재를 뜻하지 않으며 `physical_result_files_may_exist=true`를 함께 반환한다. 재시작 판단은 기존 영수증 검증을 거쳐야 한다.
- `tests/fixed_capture_fixture.py`: 보관 전환 검사 준비를 0.45초 동안 우연히 생성된 자료량에서 고정152원본/81감사 묶음으로 바꾼다. 실제 journal·압축 작업자·재생·보관 원장을 사용하지만 시각은 모델링했으며 transport 요청은0이다. 60초 namespace는 실제60초 관측이 아니다.

## 검증 범위

[검증 기록](../../reports/validation/capture_failure_boundary_20260918/verification.json), [검사 로그](../../reports/validation/capture_failure_boundary_20260918/qualified_tests.log), [이전15개 실패 대조](../../reports/validation/capture_failure_boundary_20260918/FAILURE_DISPOSITION.md).

`.venv/bin/python -m unittest tests.test_capture_failure_boundary -v`의58개가 통과했다.35개는 기존 증분 감사 검사를 새 합성 실행기에 적용한 통합 검사다. 저장 실패 원인 보존, 결과/영수증 확인 유실, 재호출, 복구, 늦은 초기화, 정리 오류, 고정 전제 보관 전환, 정확한 여유 공간 경계, 감사/압축 동시 진행, 미확정 꼬리 보존, 작업자 종료·부모 저장 지연을 포함한다. 새 SIGKILL 실험이나 장기 부하 인증은 수행하지 않았다.

감독기/보관 전환 단위 검사는 여유 공간64GiB를 명시적으로 모의한다. 실제 호스트의 공간 부족이 해당 동작 분기를 막지 않게 하기 위한 격리이며, 실제16GiB 운영 기준을 통과한 증거가 아니다. 별도 경계 검사는 예약 공간·추가 쓰기·65536바이트 여유를 유지하며, 공간 부족 시 생성/연결 전 거부와 잠금 해제를 검사한다. 합성 세대 실행기는 기존과 같이 `min_free_bytes=0`이며 실제 운용 준비로 해석하지 않는다.

전체 회귀는 승인하지 않는다. 기존15개 중7개는 같은 핵심 검사를 새 경로/고정 전제에서 통과했고4개는 부분 검증,4개는 미해결이다. 과거 통과/실패 기록을 대체하지 않는다. 개발 중 공간 부족으로 실패한 실행과 영수증 주입 hook 오류로 실패한 실행도 보존했다.

## 남은 순서

1. 미확정 꼬리의 collector 통합, 작은 세대의 비경제성 분기, 실제 scheduler 통합을 고정 사건으로 검증한다. 이전 재연결 rolling 경로3개 실패는 별도 비교 경로의 미해결 항목으로 유지하고 기본안으로 다시 채택하지 않는다.
2. 실제 저장 여유를16GiB 예약 이상으로 확보한 뒤 필요한 전체 회귀/고정 부하 검사를 수행한다. 과거 증거·사용자 자료는 자동 삭제하지 않는다. 긴 이력의 전체 파일·seed·metadata·예약·부모 목록·원점 복구 비용 상한은 별도 필수 과제다.
3. 이 종료 조건 후 짧은 공개 확인과 장기 등록 판단, 실제 체결/시장가 전환 비용 및 고정 후보 전진 모의 검증으로 돌아간다. 새 전략·실주문·24시간 수집 승인은 없다.
